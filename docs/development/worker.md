## Dedicated executor command surface

The CLI dispatches `worker serve` and the executor inspection/credential commands to the actual dedicated service. Select its state with `--state-dir` before the subcommand, or an explicitly configured `EVERYTHING_STATE_DIR`; worker commands do not silently use the ordinary Host default. Existing ordinary Host data is rejected by the executor preflight. `worker coordinator ...` instead uses the selected running authoritative Host's owner IPC and its explicitly configured optional coordinator; see [coordinator CLI](worker-coordinator-cli.md).

| Command | Behavior |
| --- | --- |
| `worker identity` | Inspect the actual running executor identity, or create/read its separate purpose identity under the offline state lease |
| `worker serve --config PATH` | Validate the owner-controlled bounded configuration, retain purpose pins and run one native WorkerRuntime, owner endpoint and explicit encrypted relay session |
| `worker status` | Inspect bounded actual executor phase, public pins, model reference and relay state |
| `worker inspect --task UUID`, `--delegation UUID` or `--cleanup` | Inspect one proven worker-owned native task, one compact delegation or actual Broker cleanup state |
| `worker revoke --peer UUID --request-id UUID` | Explicit permanent purpose-peer revocation using the original supplied operation identity |
| `worker acknowledge-cleanup` | Submit the exact operation/digest/operator/note/request identity; this does not certify remote effects or grant another attempt |
| `worker credential store` or `delete` | Offline-only exact worker-purpose native credential operation using the validated configuration; store reads only the explicitly named environment variable |

The [executor contract](../contracts/worker-executor.md) specifies the actual configuration and credential arguments. Configuration contains no raw secret, requires a regular single-link owner-controlled file within64KiB, and confirms full coordinator key fingerprints. Retained active peers cannot disappear silently from configuration; revoked peers remain revoked. The native profile/reference is immutable for that dedicated state. No ambient provider credentials or ordinary Host credentials are forwarded.

The public service waiter requests cancellation on drop without aborting its owned recovery loop. Actual native supervisor, relay and local server joins govern successful exit; NeedsOwner retains inspection and exact cleanup access. Native credential operations similarly retain the leased endpoint through their actual platform operation even if their caller disappears. The exact `f045f8a` combined CLI/relay walkthrough passed malformed/unsafe input rejection, purpose identity, CredentialUnavailable with zero native tasks/tool calls/admissions, exact revocation replay, revoked-key restart and actual joined exit.
