# Continuous backlog synchronization

GitHub Issues, including current bodies and comments, are the authoritative implementation backlog. Issue #30 supplies the evolving roadmap. Local plans and previous assignments are snapshots.

Run `python3 scripts/sync_issues.py` from any checkout at startup, at least every five minutes during active work, immediately after every PR merge, issue completion or milestone, and before a repository completion claim. Python 3 and an authenticated GitHub CLI are required. The script uses read-only GitHub API requests, fetches all open and closed issues and comments with pagination, excludes pull requests, and compares requirement hashes, state and comments. A failed refresh does not advance the last successful synchronization time; report that blocker and retry while continuing independent work.

The script atomically persists `<git-common-dir>/everything-orchestration/checkpoint.json`, shared across worktrees. Find the common directory with `git rev-parse --path-format=absolute --git-common-dir`. The checkpoint contains the last successful sync time, next due time, full issue snapshots, detected changes and coordinator-maintained assignments, dependency graph and blockers. It contains no credentials or application user data and is local orchestration state, not a product backup subsystem. Read it after compaction or restart before resuming work.

Supply `--coordination /absolute/path/to/coordination.json` to replace the checkpoint's coordination object. Record active issue owners, branches/worktrees, frozen interfaces, prerequisites and unresolved integration or validation blockers. Without that option a refresh retains the existing coordination object. Only the primary coordinator updates this object. Keep the shared implementation status document synchronized at integration milestones.

After each refresh, the coordinator must read every changed requirement and relevant comment. Compare active issues with the exact requirements assigned to their owners. Send changes immediately, redirect incompatible work safely, preserve useful completed work and update priorities. Newly opened and reopened issues enter the graph automatically; closed issues require reconciliation with their actual integrated implementation. Dispatch newly unblocked independent work without waiting for another user instruction.

Before merging, refresh and confirm that the final PR satisfies the latest issue body and comments. Before declaring completion, refresh again, inspect every outstanding implementation issue and reconcile issues created or edited during final validation. Deferred automated verification stays explicitly tracked in #32 and must never be counted as verified.
