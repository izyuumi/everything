# Tools

The `tools` module defines the native asynchronous tool boundary. `ToolRegistry` owns tool implementations, immutable descriptor snapshots, and compiled JSON Schema validators. Registration rejects duplicate names, malformed descriptors, invalid schemas, schemas requiring external resources, and oversized schemas. Discovery returns descriptors in ascending tool-name order.

For execution, the registry resolves the tool, checks cancellation, validates arguments on a Tokio blocking worker, checks cancellation again, and invokes the tool. Invalid arguments never reach the implementation. Validation accepts at most 1 MiB of serialized arguments and reports at most 32 violations. Schemas are limited to 256 KiB; regular-expression compilation and backtracking also have limits.

The host constructs `ToolExecutionContext` with trusted request and task identifiers, an absolute workspace root, and a cancellation token. The context is separate from model-controlled JSON arguments and cannot be deserialized. The broker can attach crate-private task vault data to it: the task's resolved vault values for redaction and, for a shell, the environment pairs to inject ([vault](vault.md)). Its Debug output shows only binding names and a value count. Its workspace root describes the execution scope; it provides no filesystem confinement or shell sandbox. Tool implementations must cooperate with cancellation and clean up resources before returning.

Descriptors declare required capabilities, read-only behavior, and concurrency safety. These declarations describe implementations; the registry does not grant permissions or enforce concurrency policy. The [Tool Broker](broker.md) composes this registry with [permission policy](permissions.md), durable journal claims, shared exclusion, supervised cancellation, and persistent cleanup quarantine. Production privileged execution enters through that broker; registry execution alone is an internal primitive. No shell, filesystem, MCP, or other privileged tool is supplied by this foundation.

See [tools contracts](../contracts/tools.md) for the public API and [implementation status](../status/implementation.md) for integration gates.
