# Optional System One classification

`selector::system_one` wraps the existing offline `ToolSelector`. Local mode is the default. It creates no HTTP client, initializes no native credential backend, and performs no classification requests. `SearchTools` always uses offline selection. Both paths return the same `ToolSelection` consumed by context construction; native definitions still enter the Tool Broker for exact-operation authorization. Classification never executes tools or grants permissions.

One adapter serves every remote provider. `SystemOneSettings` carries a `SystemOneProvider` choice, an endpoint, an arbitrary model ID and an optional native-store credential reference. The provider selects one of two wires over the same HTTP client, bounds and approval path. `typesafe` (the default when the field is absent, so existing settings keep their behavior) POSTs the TypeSafe choice body to the configured full endpoint; the TypeSafe preset `https://api.typesafe.ai/v1/systemone` with `jev-latest` is a client-side default, not a Host constant. `openrouter` (endpoint exactly the `OPENROUTER_ENDPOINT` constant `https://openrouter.ai/api/v1`), `openai_compatible` (any HTTPS or literal-loopback HTTP base URL) and `local_model` (a literal-loopback base URL, for Ollama, llama.cpp or LM Studio style servers, no key required) POST an OpenAI chat-completions body to `<base>/chat/completions`. Their endpoint is the base URL, not the completions URL: a path already ending in `/chat/completions` is rejected. Offline local selection is not a provider: it remains the separate default and the fallback. There is no automatic model discovery, external gateway, background classification, or automatic retry.

The host calls synchronous `prepare` on a blocking worker with its current `ExecutionAuthority`. Local configuration returns local results. Remote configuration retrieves permitted candidates, ranks them locally, retains up to 254, and prepares the exact task summary and candidate names/descriptions. It returns a disclosure object without network or credential-store activity. Input schemas, workspace files, permission records and credentials do not enter the HTTP body.

A trusted owner surface displays `provider`, `destination` (the exact POST URL), `model`, `payload` (the exact body, chat-completions for OpenAI-style providers), `authority`, and `fingerprint`, then consumes that disclosure with `approve`. Configuration alone is never approval, including for TypeSafe or loopback. Approval is memory-only, non-deserializable and expires within five minutes. It binds the originating selector instance and immutable catalog, provider, canonical endpoint including query, derived request URL, model, exact body, credential reference, result limit, and full authority including the exact optional inherited allowlist. Unrestricted and explicitly empty allowlists remain distinct. A restarted or independently constructed selector cannot reuse an approval.

`select_approved` receives the host's current authority separately. It checks full authority equality and current tool visibility before a credential lookup, then repeats those checks after the potentially blocking lookup immediately before POST. It checks expiry and cancellation immediately before sending. Returned decisions receive another visibility check. An already-started request cannot retract bytes if authority changes concurrently; the host must serialize owner trust changes against dispatch when that stronger boundary is required. The broker still rechecks execution permissions immediately before every tool invocation.

Each selector permits four concurrent classification attempts. Every admitted blocking phase retains the slot until actual worker completion, including when its caller future is dropped. Busy admission returns only the bounded `search_tools` fallback without starting another worker; other failures perform fresh local retrieval. Requests are at most 512 KiB, responses at most 64 KiB, connection setup at most three seconds, and the full request/response operation at most ten seconds. Redirects, proxy discovery and transport retries are disabled. Request failures, missing configured credentials, malformed or out-of-set responses, stale approvals and invalid configuration produce fresh local retrieval with sanitized diagnostics and the `search_tools` fallback. Cancellation returns an explicit cancellation error. Permission/storage failures propagate because discovery cannot safely infer visibility.

The neutral `credentials` module uses explicit native keyring backends: macOS Keychain and Linux Secret Service. System One derives its native-store account from the full canonical endpoint and opaque reference, so changing the destination or query does not forward an old endpoint's key. A native update keeps the configured reference only when both endpoint and provider are unchanged; switching provider at the same endpoint clears it and requires fresh secure key entry. The native credential worker retains its admission permit until the actual OS call finishes even when classification stops waiting. Credential values and native errors never enter diagnostics. See [setup](../development/system-one.md), the [wire contract](../contracts/system-one.md), and [credential boundary](../contracts/credentials.md).
