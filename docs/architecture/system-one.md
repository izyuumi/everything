# Optional System One classification

`selector::system_one` wraps the existing offline `ToolSelector`. Local mode is the default. It creates no HTTP client, initializes no native credential backend, and performs no classification requests. `SearchTools` always uses offline selection. Both paths return the same `ToolSelection` consumed by context construction; native definitions still enter the Tool Broker for exact-operation authorization. Classification never executes tools or grants permissions.

One generic adapter accepts a full compatible HTTPS endpoint, arbitrary model ID, and optional native-store credential reference. `SelectionConfig::typesafe` supplies the TypeSafe endpoint and `jev-latest` model through that same adapter. Literal-loopback HTTP is also supported. There is no automatic model discovery, external gateway, background classification, or automatic retry.

The host calls synchronous `prepare` on a blocking worker with its current `ExecutionAuthority`. Local configuration returns local results. Remote configuration retrieves permitted candidates, ranks them locally, retains up to 254, and prepares the exact task summary and candidate names/descriptions. It returns a disclosure object without network or credential-store activity. Input schemas, workspace files, permission records and credentials do not enter the HTTP body.

A trusted owner surface displays `destination`, `model`, `payload`, `authority`, and `fingerprint`, then consumes that disclosure with `approve`. Configuration alone is never approval, including for TypeSafe or loopback. Approval is memory-only, non-deserializable and expires within five minutes. It binds the originating selector instance and immutable catalog, canonical endpoint including query, model, exact body, credential reference, result limit, and full authority including the exact optional inherited allowlist. Unrestricted and explicitly empty allowlists remain distinct. A restarted or independently constructed selector cannot reuse an approval.

`select_approved` receives the host's current authority separately. It checks full authority equality and current tool visibility before a credential lookup, then repeats those checks after the potentially blocking lookup immediately before POST. It checks expiry and cancellation immediately before sending. Returned decisions receive another visibility check. An already-started request cannot retract bytes if authority changes concurrently; the host must serialize owner trust changes against dispatch when that stronger boundary is required. The broker still rechecks execution permissions immediately before every tool invocation.

Each selector permits four concurrent classification attempts. Every admitted blocking phase retains the slot until actual worker completion, including when its caller future is dropped. Busy admission returns only the bounded `search_tools` fallback without starting another worker; other failures perform fresh local retrieval. Requests are at most 512 KiB, responses at most 64 KiB, connection setup at most three seconds, and the full request/response operation at most ten seconds. Redirects, proxy discovery and transport retries are disabled. Request failures, missing configured credentials, malformed responses, stale approvals and invalid configuration produce fresh local retrieval with sanitized diagnostics and the `search_tools` fallback. Cancellation returns an explicit cancellation error. Permission/storage failures propagate because discovery cannot safely infer visibility.

The neutral `credentials` module uses explicit native keyring backends: macOS Keychain and Linux Secret Service. System One derives its native-store account from the full canonical endpoint and opaque reference, so changing the destination or query does not forward an old endpoint's key. The native credential worker retains its admission permit until the actual OS call finishes even when classification stops waiting. Credential values and native errors never enter diagnostics. See [setup](../development/system-one.md), the [wire contract](../contracts/system-one.md), and [credential boundary](../contracts/credentials.md).

Local compilation and disposable checks are tracked with the integration report. Successful TypeSafe/custom-service classification, successful native-store persistence, Apple behavior, adversarial protocol coverage and a security audit require their respective environments. Automated coverage remains deferred in [#32](https://github.com/izyuumi/everything/issues/32).
