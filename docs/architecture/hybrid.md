# Optional hybrid wiki retrieval

Issue [#21](https://github.com/izyuumi/everything/issues/21) implements `memory::search` and the feature-gated `memory::vector`. Existing `Wiki::search` remains lexical FTS5. Markdown is authoritative; semantic storage is a separate disposable SQLite file. The service ships only the real local EmbeddingGemma 2 backend, injected through the generic `Embedder` contract. No model gateway, inference daemon, model download, alternative embedder, or additional memory writer is introduced.

## Ownership and configuration

`HybridSearch` owns one `VectorIndex` and an `Arc<dyn Embedder>` with a stable validated profile. Creating a model, opening a vector file, and attaching the service are explicit host operations under the default-off `local-embeddings` feature. A disabled configuration never constructs these objects. Public search/build calls are synchronous and must run on bounded blocking admission in an async host. Native inference retains the existing backend's bounded nonpreemptible sections.

Consolidation accepts `set_hybrid_search(Some(service))` without changing `ConsolidationConfig`. The same `MaintenanceState` continues owning its single `Wiki`; no second connection writes canonical memory. `rebuild_semantic` runs under the existing blocking admission, and `semantic_status` returns durable vector progress. Passing `None` releases semantic resources and restores explicitly disabled lexical queries. `set_hybrid_search_result` accepts an actual initialization result and keeps FTS available with sanitized unavailable provenance when native/cache setup fails; cancellation propagates. It does not abort the rest of the local host or copy model paths/native error bodies into query summaries. Optional query-result retrieval metadata uses a serde default, preserving existing saved maintenance outcomes. Ingest candidate selection and deterministic lint remain lexical/non-inference operations. Cancelling a query signals its active token before waiting for filesystem admission, allowing the local inference backend to observe cancellation.

Runtime tasks can call `Consolidator::retrieve` for bounded actual evidence without creating maintenance jobs or invoking an answer-model provider. This direct path shares the same source synchronization, retrieval provenance, cancellation and single-owner admission as maintenance queries. Its blocking worker retains admission until completion even when the awaiting task is dropped.

## Source boundary

`WikiIndex` exposes bounded read APIs rather than its SQLite connection. `source_fingerprint` streams the persisted parser/chunking profile, sorted canonical page paths/content hashes, and actual chunk IDs/byte lengths/line ranges/counts through domain-separated SHA-256. Lexical schema 2 adds one settings table; a changed or absent `WikiLimits` profile invalidates derived rows before canonical rescan so an unchanged page hash cannot silently preserve older segmentation. `chunks_after` pages stable chunk IDs with an exclusive cursor, row limit and aggregate byte bound. `chunks_by_ids` deduplicates bounded IDs and hydrates current title, full source chunk, provenance and page hash. Row lengths are checked before strings are copied. No semantic fields or virtual-table triggers are added to the lexical database, so its normal writes do not depend on extension initialization.

A source fingerprint describes the last synchronized wiki index. Search and rebuild synchronize canonical files before relying on it; they synchronize again after native work before semantic results or a generation are accepted. The single owner excludes internal writes during those operations. External editors remain uncooperative filesystem writers and may race a completed scan; this module does not promise a cross-database transaction or file-content compare-and-swap.

## Generations and incremental work

Every generation persists its full `EmbeddingIndexSpec`, exact index fingerprint, source fingerprint, fixed dimension, ready flag, cursor, and embedded/reused/blank counts. A table named from the internal positive generation integer contains one `vec0` cosine vector per nonblank wiki chunk. No caller-supplied SQL identifier is interpolated. All vectors are validated for dimensions, finite values, unit L2 norm and exact profile compatibility before insertion. Reused vector blobs are decoded and revalidated. Initial dimensions are 128, 256, 512 and 768, and the profile must declare unit-L2 cosine semantics.

Document preparation uses the page title and full original chunk Markdown. Its schema identifier records heading chunks, preserved Unicode, rejected overflow, skipped blank chunks and the profiled source-manifest revision. The index fingerprint includes that schema. An input hash additionally binds the exact title/text bytes and index fingerprint. Changing a document or title therefore prevents incompatible vector reuse; provenance and presentation are always hydrated from the current source index. Backend token or byte limits fail explicitly, leaving FTS usable instead of silently indexing a prefix.

A build starts or resumes one shadow generation for the current source and specification. Each chunk commits its vector/input hash and new cursor in one transaction. A call may stop at its chunk or monotonic elapsed budget and return resumable progress; cancellation returns an error while retaining already committed progress. The next call resumes only if source and specification still match. A new source or profile retires incompatible incomplete work and creates a fresh generation. Unchanged inputs can copy validated vectors from the compatible prior active generation without inference. Deleted chunks are omitted from the new scan.

The final canonical synchronization must still match the generation's source fingerprint. Only then does one transaction mark it ready and change the active pointer. A crash before that commit retains the prior active generation and the build cursor. A crash afterward observes the new pointer. At most the active and one shadow/retired generation are retained; old nonactive tables are removed transactionally when starting another build. These operations rebuild derived state and never restore or overwrite Markdown.

## Ranking and fallback

FTS5 retrieval is available first. Semantic inference runs only when an active ready generation matches the exact configured index profile and current source fingerprint. Native `vec0` retrieves a bounded cosine-distance rank list. Returned IDs/input hashes are checked against current chunks, and canonical files are synchronized again before accepting that list. Query cancellation propagates and never becomes a successful lexical result.

The rank lists combine by reciprocal-rank fusion with constant 60: each source contributes `1 / (60 + one-based rank)`. BM25 and cosine distances retain their own optional fields; neither is treated as a comparable numeric score. Fusion scores sort descending, with chunk IDs breaking ties deterministically. Results include current source provenance and bounded excerpts.

Missing, stale or incompatible generations and semantic failures produce lexical results with explicit fallback reason and bounded diagnostic. A partial build never becomes a partial active index. Source I/O and lexical errors remain errors. The summary distinguishes lexical and hybrid operation; an unavailable model does not fabricate vectors or semantic scores.

## Limits and verification

The private database uses WAL, synchronous FULL, exclusive writer ownership and an application/schema identity. Default limits are 50,000 vectors per generation and a 512 MiB main-database page ceiling; configurable maxima are 100,000 and 2 GiB. WAL/checkpoint files can temporarily add to the main-file bound. Chunk pages hydrate at most 256 rows and 16 MiB, searches use at most 100 candidates per rank list, and final results are at most 100. Lexical pages also enforce a 16 MiB aggregate field/provenance bound before copying strings, without truncating titles or altering BM25 ranking. An oversized page returns a limit error; a caller can request fewer rows. Build calls process at most 1,024 chunks and use a positive elapsed budget up to 300 seconds. Native inference can finish its bounded call after that elapsed threshold; this is cooperative budgeting rather than hard preemption.

The [native initialization decision](../decisions/ADR-0004-scoped-sqlite-vector-index.md) records the essential unsafe ABI boundary. Disposable Linux runs used the actual pinned local EmbeddingGemma 2 ONNX bundle and native ONNX Runtime at all four dimensions. They observed hybrid retrieval, persisted partial-build close/reopen/resume, exact-profile rejection, changed-input inference with unchanged-input reuse, deleted-chunk removal, and rejected oversized input with FTS fallback. A canonical edit during real query inference produced a stale-source fallback whose refreshed lexical results reflected the edit. Changing the chunk-size profile reparsed unchanged files, changed the actual chunk count and invalidated the source fingerprint; a version-one lexical index migrated to schema two.

Focused runs also observed cancellation during native build and consolidation query work, subsequent resume/query success, bounded rejection of malformed metadata and oversized existing vector databases, real canonical citations through the single consolidation owner, and decoding of older query outcomes. Actual cache-initialization failure retained lexical results with sanitized semantic-failure provenance; explicit disabling reported disabled provenance before any model initialization. Direct retrieval returned actual lexical and hybrid evidence, cancelled waiting admission and native inference, and allowed another successful query after the caller was dropped; its journal contained zero job rows. Rebuild cancellation was observed before admission, while waiting behind an actual hybrid query, and during inference; resumed builds completed after explicit cancellation and caller drop. A disposable lexical-cache corruption exercise observed the aggregate limit, a successful smaller request preserving full title/heading fields, and rejection of a non-text field. These observations used authored disposable data. No live answer-model request, Apple hybrid runtime, forced process/power-loss scenario or broad retrieval-quality evaluation was performed. Automated migration, crash, cancellation, corruption and ranking coverage is deferred to [#32](https://github.com/izyuumi/everything/issues/32).
