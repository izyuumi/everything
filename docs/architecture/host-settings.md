# Host settings and model credentials

`host::settings::SettingsRepository` maintains non-secret owner settings in `<state>/host-settings-v1.json`. It reuses the validated state lease and performs descriptor-relative owner-only, no-follow, single-link file checks. Updates compare the expected in-memory revision and exact current disk contents, validate the replacement, then write a private temporary file, synchronize it, rename it, and synchronize the directory. Blocking filesystem calls belong on a blocking worker.

Schema 1 contains an optional default conversation configuration, a physical existing workspace, execution mode, tool enablement, context and native-loop limits, at most sixteen model credential references, an optional ordinary device relay origin, and optional worker coordination. The default creates a separate private `<state>/workspace` and selects read-only operation with tools disabled. It selects no model or relay, performs no credential lookup, and makes no network request. Defaulted memory, configured MCP and optional selection fields compose those services in the same host. They contain non-secret settings and purpose-bound references; embeddings, external selection and MCP startup remain off unless explicitly configured and authorized. Defaulted `preference_overrides` separately retain optional embedding enablement/dimensions and System One enablement without erasing configured paths, endpoints or references. The shared service applies semantic/classifier changes through actual generation controls; other Memory policy, MCP, worker and relay changes require restart. Composition status and the revisioned Settings snapshot distinguish active, pending and unavailable state. A saved file does not by itself prove successful application.

`worker: None` disables coordination. `Some(WorkerCoordinatorSettings { relay_origin })` explicitly selects its separate worker-purpose encrypted relay. Host startup creates that purpose endpoint only when configured and reuses the existing Agent/Scheduler/Broker/Store. Enabling or changing the origin requires restart; a live settings change closes fresh preparation/admission and its old relay/reconciler. It never silently revokes existing remote authority or proves remote execution stopped. When no service was constructed at startup, status creates no worker identity and reports uninspected retained-history counts as `None`, with known zero in-process preparation/operation counts. A service disabled through live settings remains retained for inspection and reports its actual bounded `Some` history counts with `enabled: false`. No selected files, worker credential values, live tickets or reusable approval belong in settings.

`ModelCredentialReference` identifies the provider, exact official or canonical explicit loopback endpoint, non-nil UUID reference, and `session` or `native` storage. Its native store account is a SHA-256 scoped identifier over provider, endpoint, and reference. The settings file never contains credential values. A native reference uses the implemented platform Keychain or Secret Service backend, with no plaintext fallback.

`CredentialVault` stores session secrets in a bounded in-memory map and uses the native credential store for native references. It captures the two provider environment variables once at host construction. Those environment credentials are fallback only for their respective official endpoints. A loopback endpoint requires its own explicit matching credential reference. A configured but missing binding reports absence instead of falling back to another credential source. Malformed credentials for an unused provider do not prevent host construction.

`SecretTransfer` is a bounded, validated UTF-8 secret used only for ephemeral owner IPC. Its debug representation is redacted and underlying storage zeroizes on release. IPC encoding and input frame buffers also zeroize. It must never be placed in the command inbox, domain envelope, event log, task checkpoint, settings file, or general logs. Native store operation failures are reported with sanitized typed errors. Platform credential calls are cooperative operating-system operations; in-flight store/remove completion cannot be inferred from a disconnected client.

`HostProviderFactory::create` validates the exact saved `ConversationConfig`, resolves only that configuration's scoped credential, observes cancellation, and constructs the native Anthropic or OpenAI adapter. Construction performs no inference. It preserves the selected endpoint and provider-specific adapter validation. Missing credentials leave durable tasks available for an explicit owner action. Provider request and response behavior remains defined by the [provider contract](../contracts/providers.md).

A disposable observation verified default private workspace/read-only/tool settings, compare-and-swap revision advancement, stale revision rejection, and settings persistence after repository reopen. Static compilation validates native store API composition; Keychain and Secret Service runtime behavior has not been exercised by this host integration. The [composition contract](../contracts/host-composition.md) defines actual memory, MCP, selector and scheduler integration. Fresh focused owner-route, restart, bootstrap and local embedding observations are qualified in that contract; native credential-store and Apple behavior remain unverified.

The [shared settings operation service](../contracts/settings-service.md) is registered over the same leased Agent, Store, SettingsRepository, DeviceEndpoint and Host mutation guard. [Startup recovery](../contracts/host-settings-startup.md) reads actual disk/cache plus bounded typed history before optional model/runtime/vector or remote-selector admission. Unresolved file intent or an exact-current unobserved application keeps those features off while preserving configuration. The existing Host JoinSet worker advances original known-applied work; it does not create another runtime. Known no-file-effect recovery restores only an available original live admission ticket. After restart, no missing ticket or backend is recreated merely to declare recovery complete.

[Owner replacement](../contracts/settings-owner-routes.md) now uses this service and returns its original receipt, with full settings only if the current validated file still matches that known-applied post-file. Explicit original-ID reconciliation observes the file without writing it or directly starting a helper. [Native Settings routes](../contracts/native-settings-routes.md) use Host-minted session proofs over private pipe/FIFO ingress, not the request-file bridge. Existing model/device metadata and closed actions cannot mint owner authority or paired grants. First-time credential enrollment, complete native screens and the immutable restricted runtime remain separate implementation work.

During drain, Host mutation admission closes intake and Composition, then releases that guard. SettingsService close settles file/claim cleanup; Composition then starts actual Memory/selector shutdown, waking admitted application waits before the final JoinSet driver join. Owner inspection and explicit reconciliation remain cleanup-only, while fresh writes reject closed intake. The complete current source still requires final combined Rust, disposable runtime and applicable Apple validation; the historical observations above do not validate these newer routes or live controls.
