# Headless memory composition leaf

The implemented `host::memory` leaf owns the memory components needed by issue [#68](https://github.com/izyuumi/everything/issues/68). It receives the real leased Agent and optional existing native TaskProviderFactory. It derives fixed private memory paths from that Agent, moves one Wiki into one Consolidator, optionally attaches the implemented local EmbeddingGemma 2 hybrid service, and supervises one existing Consolidator worker. It adds no inference loop, scheduler, broker, source downloader or remote service.

The default opens local Markdown/FTS and maintenance journals, creates no model provider and performs no embedding construction. An explicit maintenance binding can use the same endpoint-bound native provider factory as tasks. Unavailable construction leaves offline retrieval/lint and waiting-for-model ingest with an accurate diagnostic. Canonical consolidation instructions remain inside the existing memory module. Explicit embedding construction verifies the selected runtime digest before initialization, uses pinned bundle validation and the requested dimension, then transfers the real HybridSearch into the same Wiki owner. Failure is visible while genuine FTS remains available; cancellation stays cancellation.

Retrieval returns actual provenance and fits a small serialized capture budget before handing excerpts to a future scheduler integration. The service never generates a separate model answer for task context. Existing Consolidator query jobs are a distinct owner operation and may generate an answer only when an actual maintenance provider is configured. Native resumes must use their saved captured memory; this leaf does not silently retrieve again inside an active native turn.

State ownership spans asynchronous cancellation and native blocking cleanup. Initialization and the maintenance worker have retained supervisors holding the Agent. Last-owner drop signals shutdown; the worker is awaited, then the real Consolidator admission permit supplies a blocking-work barrier. Host shutdown must first stop new owner/scheduler preparation and drain handlers, because raw Consolidator handles remain a trusted host interface. The barrier cannot stop an independent future caller. Runtime/model and MCP/tool cleanup responsibilities remain separate, and all must settle before final host state ownership ends.

Settings are fixed for an owner lifetime and changes require a host restart. This keeps the process-global ONNX runtime and immutable generation profile explicit. Expected hashes do not make path-based dynamic loading safe against hostile same-user replacement; operator-selected native libraries and their paths remain trusted. Filesystem/SQLite atomicity and external-edit limitations remain the existing Wiki and [consolidation](consolidation.md) contracts.

Opt-in embeddings additionally require a process-start `ORT_DISABLE_TELEMETRY=1` preflight before artifact access. Missing suppression produces a distinct effective unavailable status and genuine FTS, while preserving desired settings. The application keeps the existing API telemetry-disable call and never changes its process environment. This addresses supported-runtime initialization telemetry; native code still has ordinary host authority and requires an operator-verified build.

The host runtime, revisioned settings schema, owner IPC/CLI controls and scheduler preparation must explicitly call this leaf before application integration is complete. See [the host memory contract](../contracts/host-memory.md) for current APIs and bounds.

Disposable optimized validation exercised real Markdown retrieval, citations, lint, offline query, waiting-for-model ingest, cancellation, restart, bounded captures and state-lease retention through detached blocking work. The default performed no Internet calls or runtime/model/vector access. Initial native inference at all four dimensions produced real hybrid results, but two traced processes attempted outbound telemetry despite the API telemetry setting. Issue [#72](https://github.com/izyuumi/everything/issues/72) added the process-start guard. Subsequent isolated verification with the exact supported Linux runtime and flag produced genuine native retrieval/cancellation results at all four dimensions with zero Internet-family attempts. Missing or other flag values retained real FTS with the specific unavailable diagnostic. This observation does not verify arbitrary native builds, macOS telemetry behavior or production OS confinement.
