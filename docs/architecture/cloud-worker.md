# Optional native worker

The worker library composes the existing native Agent, Scheduler, model adapters, Tool Broker, filesystem tools, offline discovery and encrypted relay connection. It does not introduce another agent loop or a cloud infrastructure service. The dedicated executor CLI, native root reservation/result admission and ordered schema10/schema11/schema12 migration registration are implemented. The optional Host coordinator is composed and has qualified native-admission, encrypted-relay and credential-rejection observations. See [Host admission](../contracts/host-worker-admission.md), [the service](../contracts/host-worker-service.md) and [owner CLI](../development/worker-coordinator-cli.md).

Worker endpoints are explicit. Opening an endpoint is local and binds one leased Agent to its purpose identity, coordinator/executor role and exact relay origin. No endpoint opens a socket until its caller explicitly runs the relay future. Empty host configuration must never construct or run that future. Worker identities and peer pins are separate from ordinary Host/Replica identities and permissions. Known ordinary device identities cannot be reused in the same Store.

The owner reviews an exact bounded manifest containing selected task data and copied files. The Host retains its preparation for at most sixty seconds, then explicit Delegate consumes the exact ticket and mints a thirty-second approval bounded by the manifest deadline and a monotonic cap. The generic library permits at most five minutes; the Host uses the shorter interval. The mandatory `WorkerOutboundGate` acquires actual native scheduler authority and reservation before both durable enqueue and each socket send. Its owned permit remains alive through the relevant operation. A private endpoint authority mutex serializes local cancellation, revocation and received control packets with enqueue/transmission. Without an actual gate, coordinator Offers cannot be enqueued or transmitted; a worker database row does not reserve native scheduler capacity or parent budget. The initial Host control surface permits fresh root delegation only, with no model-origin or nested cloud-delegation tool.

The executor composes one filesystem-only registry, one global broker and one Scheduler with one primary and one pending slot. No scheduler-management tools, shell, MCP, general network tools or semantic selector are registered. Native model traffic uses a separately approved immutable worker-owned provider configuration and credential reference. Lookup uses only the worker-purpose native credential key, without host/environment/cloud SDK fallback. The worker starts a fresh native conversation from the selected manifest instruction and selected file workspace. Local host history, wiki and opaque checkpoints are not transferred.

The immutable worker model profile and delegation/native identities survive restart. State containing unrelated native tasks fails startup. Native task, conversation and create/input command identities cannot be reused by another delegation. Workspace publication and native enqueue recheck current peer/cancellation/deadline under the same endpoint authority mutex. Existing native attempt journals and their original deadlines remain authoritative; interrupted or uncertain inference and tool effects are never automatically resumed or refunded.

Incoming authenticated application packets are validated and committed atomically with their state changes and replay identity before relay acknowledgment. Original encrypted outbox envelopes survive reconnect, so transport uncertainty does not generate a new job identity. Relay acceptance and application result acknowledgment are distinct. Cancellation-before-Offer records a tombstone; later arrival of that Offer cannot start native execution. CancellationAccepted records durable intent and never proves remote effects stopped. Revocation is permanent and suppresses queued ordinary traffic. Exact already-durable messages can still authenticate for acknowledgment after revocation without acquiring new rights.

Worker results include a bounded summary, approved artifacts and actual native counters. Uncertain native state is explicitly Unknown. Tool cleanup uncertainty keeps the broker quarantined and prevents admission of new jobs. Generated files are private quarantined data, never automatically applied to a user's workspace. The authoritative host must integrate/accept the exact result before the explicit application acknowledgment; result telemetry cannot widen permissions or refund a reservation.

The native reservation is a durable external lane of the same Scheduler. Its immutable definition is never dispatched to a local model worker. The original terminal encrypted packet, pinned by migration11, and actual private quarantine can mint the bridge's result capability. The Agent then appends one attributed `RemoteTaskFinished` event and settles the original task/private checkpoint atomically. Only the resulting opaque receipt can authorize an ACK. Unknown keeps its slot and complete charge; disconnects, cancellation and acknowledgments do not prove remote stop. Migration12 indexes binding lookup while preserving full validation and ambiguity rejection.

The runtime supervisor retains its leased Agent through scheduler shutdown and actual broker cleanup. Dropping a runtime requests cancellation. Public shutdown waits at most twenty-five seconds and returns pending while ownership remains. Actual task snapshots, broker cleanup requirements and exact operator cleanup attestation remain available through the runtime handle. Unknown cleanup is never automatically acknowledged.

The first capability profile does not execute arbitrary code and makes no hard CPU/RAM/PID/disk guarantee. The strict namespace observation in the implementation handoff established a useful future launcher prerequisite, not a production arbitrary-code backend: seccomp and aggregate resource enforcement remain unavailable. The executing worker's OS operator can inspect the scoped plaintext it executes. Encrypted relay transport protects content from the relay, not from that operator.

Worker retention is bounded and fails closed on exhaustion. There is no automatic job deletion, backup/restore mechanism or infrastructure provisioning. See [the contract](../contracts/worker.md), [worker files](../development/worker-files.md) and [validation](../development/worker.md) for current boundaries.
