# Native macOS menu bar client

The optional `EverythingMac` application uses SwiftUI `MenuBarExtra` and the native Settings scene on macOS 14 or newer. The macOS target uses the shared Apple project. It contains no agent loop or provider adapter. Only the local device-preference actor opens its own SQLite database; the app never opens the Host database. The Rust host remains authoritative and owns task execution independently of this application.

## Responsibilities

The [This Mac consumer](../contracts/this-mac-settings.md) adds conventional notification preferences, saved app appearance and separate observed OS status without Host or model availability. `SettingsWindowObserver` binds real window/app events to the one app-owned store. Draft revisions, original write receipts and owned callbacks remain distinct from Host settings and notification delivery.

- `EverythingMacApp` owns the observable application model and menu bar scene. Its termination delegate invalidates intake and joins original assistant callbacks, local preference/notification work and native Store/presenters before shared-client shutdown and normal app termination.
- `HostModel` maintains presentation state, coalesced read refreshes, exact mutation identities and revision-checked settings snapshots. Connection edits remain drafts until Connect is selected. Tasks and approvals retain the connection that returned them, preventing stale callbacks from targeting another host.
- `TasksView` inspects actual task metadata and offers cancellation and ordinary wake. A wake does not grant uncertain provider retry or tool cleanup authority. Legacy foreground ownership remains explicit.
- `PermissionsView` reads bounded pending summaries for a selected conversation, loads exact scope and arguments separately, and rechecks that immutable request before submitting an operation decision. It uses the exact operation UUID and conversation, including spawned tasks; it does not derive task identity from a command UUID.
- `SchedulesView` presents read-only engine status, bounded job pages and selected-job run history through the existing owner queries. It preserves actual cursors and keeps Unknown outcomes separate from usage-accounting certainty; it adds no scheduling or host-lifetime authority.
- `SettingsView` edits workspace, execution mode, tool enablement and context budget. The complete original settings object is retained, and the existing revision is required when saving. Other fields and credential references remain intact. Models and Tool Selection retain their separate secure native credential controls; Devices retains its own native ceremony.
- `Shared/OwnerIPC` contains bounded JSON values, local owner request records and a CLI-backed IPC client. It does not implement encrypted replica transport.

The optional [Ask Settings inspector](../contracts/apple-settings-assistant-composition.md) shares the same app-owned native Store. Its explicit child Open reads the configured recipient without inference; each question requires fresh disclosure review and its own original Send admission. Private text is bounded in RAM and cleared on genuine retirement or covering presentation. Authenticated typed cards reuse existing native confirmations, Device sheets and acknowledged known-section navigation. Text cannot create actions, credentials or provider fallback. Conventional controls remain available independently.

## Owner IPC bridge

The application runs an explicitly selected, trusted absolute Everything CLI executable without a shell. `owner --request-file` always uses the implemented Rust owner client; it never opens a competing Agent. Rust retains descriptor-relative state/socket checks, same-UID peer authentication, frame bounds and authoritative command admission. The application verifies the executable through a no-follow descriptor walk with trusted ancestor ownership and write permissions. This does not isolate code selected by the same user; the selected binary runs with that user's normal privileges.

Each request uses a new private temporary directory and a 0600 regular request file. The file remains owned until its CLI child has exited, then normal completion removes it. At most four requests are admitted. Requests and output are bounded to 1 MiB and 2 MiB respectively; stderr is bounded to 64 KiB and its content is not surfaced or logged. JSON nesting is limited to 64. The environment forwards only the user's home directory, system executable search paths and a fixed UTF-8 locale; provider credentials are not forwarded.

I/O and child waiting run on a bounded Dispatch queue. A 45-second monotonic deadline or task cancellation starts cancellation of the owned CLI. The supervisor attempts SIGINT immediately, SIGTERM after two seconds and SIGKILL after four seconds, each once for its captured positive CLI PID. Ownership and the admission slot remain until actual child exit. Filesystem calls and termination remain cooperative; this is not a claim that arbitrary blocked operating-system operations can be forcibly bounded. Signal attempts use only the captured CLI PID; the client performs no Host-PID lookup or process-group signaling. Forced application termination cannot guarantee private temporary-file cleanup.

The menu refreshes read-only metadata every 15 seconds while its label task is alive. This does not schedule or execute agent work. Task lists request up to ten records to accommodate large valid task instructions within the real frame limit. Conversation discovery returns up to 100 records. Pending approval pages contain 20 summaries with a retained exclusive cursor and a 1000-summary presentation cap. These are bounded views, not complete history exports.

## Mutation and lifetime semantics

Domain actions retain the complete current command envelope, including its original command ID, nullable issuing device and issue time. The owner CLI rejects unknown or omitted fields instead of silently discarding metadata. A transport failure preserves the exact in-memory request for an explicit retry; it never substitutes a new command identity. No mutation is automatically replayed on application restart. Inspect authoritative task, approval or settings state after an ambiguous result.

Permission decisions pass through the durable host inbox and native authorizer. Settings preserve the complete snapshot and compare revisions. A pending action prevents connection changes and other mutations until it is reconciled. Its original command ID remains visible. Inspect result reads the actual host command receipt and clears the reminder only for a durable completed or rejected command. An owner can also confirm that they inspected current state and clear the application reminder; admitted host work and command history remain intact. The reminder is presentation state, not a second durable runtime queue.

Service installation, start, stop and login enablement invoke the actual Rust `service` commands for `com.everything.host`. Installation and stopping require explicit user confirmation. Each action validates its typed report and then reads `service status`; Settings and the menu show installed, login enablement, launchd PID or loaded/not-loaded state and last exit status. The result is cleared when the connection changes and is not polled. They affect the launchd user agent, not a separately launched foreground host. Opening or closing the menu bar app neither starts nor stops the runtime. Normal Quit only drains the application's CLI children.

## Validation limits

Historical foundation parsing and Foundation-only checks covered the original small client extraction. Later exact-head GitHub Actions, including PR #162 runs `38940702838` and `38940702892`, passed Ubuntu formatting/strict Clippy and actual Xcode 26.6 macOS/iOS build and analysis for their respective source trees. Those logs retain nonfatal AppIntents metadata warnings. They precede the final assistant composition. Corrected #163 head `81810ec3` additionally passed actual Ubuntu run `38943440168` and both Apple SDK builds/analyses in `38943440172`, with retained checkout trees equal to that published head. The earlier failed private Observable-macro build is retained separately; [the architecture checkpoint](settings.md) distinguishes these source/CI facts from manual acceptance.

Builds do not verify inspector/navigation/accessibility behavior, launchd actions, native permission/credential/pairing sheets, provider inference, connection/occlusion races or the quit-app/Host-PID lifetime observation. Those require actual supported runtime observations and remain unverified. Deferred automated coverage remains [#32](https://github.com/izyuumi/everything/issues/32).
