# Native MCP tool adapter

Issue [#19](https://github.com/izyuumi/everything/issues/19) adds `tools::mcp`, using the official Rust MCP SDK. MCP is an optional tool protocol; model inference and the Vorra agent runtime remain native. This implementation supports configured Unix stdio processes. HTTP transport, OAuth discovery, dynamic server installation, and server-selected executable launch are outside this adapter.

The host constructs a non-deserializable `McpStdioConfig` with an explicit server ID, absolute executable, physical working directory, arguments, environment, and deadlines. Calling `McpHost::connect` authorizes starting that exact local executable. It must originate from trusted owner configuration or an explicit owner action, never model output or an untrusted document. Launch can itself run arbitrary code before any MCP tool permission. Application path checks do not sandbox the server, and a server may contact external services using credentials explicitly supplied to it. Select and review the entire server executable, arguments, dependencies, allowed directories, and credential scopes accordingly.

The child inherits no environment variables: `env_clear` precedes the explicit map, including any deliberately selected `PATH` or credentials. Arguments and environment values are retained in zeroizing strings; configuration debug output shows counts and environment key names only. Operating-system process arguments and child memory are not confidential to the same OS user. Child stderr is intentionally discarded rather than surfaced as trusted host diagnostics. Server error bodies, input arguments, and credentials do not enter adapter error messages. The underlying SDK logs server metadata and instructions even at info level, and detailed tracing can contain tool traffic. Host logging must treat these SDK targets as private and filter `rmcp` targets from shared logs.

## Ownership and discovery

Each `McpHost` owns a bounded admission semaphore for one to sixteen processes. Preparation and filesystem metadata run on a blocking worker while retaining admission. Each process runs in its own Unix process group. SIGCHLD-driven observation uses `waitid` with `NOWAIT` to retain the leader PID while signalling the group and leader, then disarms signalling before reaping. A captured RAII guard performs the same anchored fallback on supervisor drop; stale direct-PID `kill_on_drop` is disabled. An owned supervisor releases admission only after confirmed termination/reaping. Unconfirmed cleanup permanently consumes that admission slot until the owner replaces the host after reconciliation. Explicit shutdown cancels the SDK service and awaits process cleanup. Dropping a session requests shutdown when its last registered-tool/session reference disappears. A registered registry therefore retains its server; hosts must explicitly shut down sessions before releasing the runtime.

Initialization advertises Vorra identity with no sampling, roots, elicitation, resource, task, or experimental capabilities. Incoming server requests other than ping disconnect the transport. Server instructions and annotations never become host policy or privileged model instructions. Tool-list notifications invalidate the frozen catalog. Calls with a stale catalog fail before dispatch; replacing a session requires explicit owner orchestration and rebuilding the registry. There is no silent reconnect, automatic rediscovery, or call replay.

Discovery uses bounded individual SDK requests and validates complete pages, cursor progress, duplicate names, native aliases, schemas and descriptor sizes. It bypasses the SDK's optional list cache and unbounded `list_all_tools` helper. The adapter snapshots names and object input schemas, then atomically validates registration into a cloned `ToolRegistry`. Registration failure leaves the original registry intact. Registry schema compilation remains offline, so server schemas cannot cause network reference fetches.

Native aliases contain at most 62 ASCII letters, digits, underscores or hyphens. They include the explicit server ID, a readable original-name prefix, and a domain-separated SHA-256 suffix. Exact original MCP names are retained and sent unchanged in `tools/call`. Hash collisions and duplicate original names fail discovery rather than silently selecting a tool. Host scope identity binds the explicit launch configuration, including environment values, through a SHA-256 configuration fingerprint. That identity is private configuration metadata and does not authenticate executable contents or an external service.

## Broker and result semantics

Every imported descriptor declares capability `mcp`, `read_only = false`, and `exclusive` concurrency. Server safety hints are untrusted and cannot lower those requirements. `register` returns corresponding `ToolScopeRule::Host` entries. The host merges those entries into the final broker authorizer, with the same registry and store, before exposing definitions to a model. FullHost authority and exact-operation approval remain necessary. Calling the registry directly bypasses those boundaries and is not a production execution path.

There is one active request per session. A completed MCP result produces `ToolOutput` with the remote `isError` flag preserved in `is_error`, native content blocks, optional structured content, explicit server identity, and original tool name. The broker retains semantic errors as terminal failures with output and exact replay; completion does not imply an absence of partial effects. Content blocks and resource links remain untrusted data. The adapter does not fetch returned links, execute returned instructions, fulfil additional client input requests, or poll asynchronous server tasks.

Cancellation, timeout, disconnect, protocol failure, or an unpersistable result after dispatch shuts down the session and reports uncertain effects. Even killing and reaping a local server cannot prove that external activity it initiated stopped. These failures retain `cleanup_completed = false`, causing broker quarantine and owner reconciliation. Predispatch invalidation, busy admission, or an already disconnected session is a definitive no-effect failure for that invocation. No uncertain invocation is automatically retried.

## Validation boundaries

The [MCP contract](../contracts/mcp.md) lists APIs and resource limits. On Linux on 2026-10-15, a disposable owner driver launched the actual published `@modelcontextprotocol/server-filesystem@1.0.0` package, using its MCP SDK 1.31.0 dependency, an explicitly selected Node executable, an empty environment and a temporary allowed directory. No mock server, live model credentials or real user files were used. The driver and generated data were outside the repository and are not an automated suite.

Observed behavior included fourteen discovered tools, native alias and conservative descriptor bounds, a capacity rejection before process launch, and a ReadOnly broker denying a write. Explicit disposable-owner approvals permitted a real write, move and read. Replaying the move's durable operation returned the recorded result without moving again. A missing-file result preserved MCP `isError` as a terminal broker failure with content. A dropped pending shutdown caller followed by two concurrent callers joined the same cleanup outcome; the process exited, a subsequent invocation failed before dispatch, and another process could acquire the released slot. A precancelled connection returned the typed cancellation error.

A real two-MiB file read exceeded the frame bound and disconnected. A separate real named-pipe read was cancelled while blocked. Both broker operations reported unknown effects with unconfirmed cleanup and quarantined their separate disposable host stores; local shutdown nevertheless killed and reaped each server. Uncertain operations were not replayed. Linux process existence was checked through `/proc`; these observations do not establish macOS process behavior or arbitrary descendant containment.

The adapter and locked dependencies compiled with actual Rust 1.88.0, and the release observation driver ran successfully. Formatter and workspace release checks passed. Strict Clippy at the raised minimum compiler exposed existing `collapsible_if` warnings in other modules; checking with only that lint excepted passed, so the shared integration must resolve those warnings before its unqualified required check can pass. Automated discovery, malformed-wire, cancellation and disconnected-server coverage remains deferred in [#32](https://github.com/izyuumi/everything/issues/32). Apple compilation/runtime validation, hostile-server coverage and a security review remain separate requirements. This adapter is not an operating-system sandbox or a security audit.
