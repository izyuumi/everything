# Context

Issue [#16](https://github.com/izyuumi/everything/issues/16) implements the pure synchronous `context` module. It accepts explicit immutable instructions, task state and constraints, durable source references with provider messages, ranked wiki excerpts, selected tools, and an explicit model budget. It returns a validated native `ModelRequest`, usage estimates, memory citations and omissions, loss-aware compaction metadata, and continuation disposition. It has no storage mutation, runtime, retrieval, or provider-inference dependency.

The builder first budgets exact instructions, the full task object, and every selected tool. It then retains the longest fitting recent history suffix and adds memory in caller priority order. Fixed task constraints cannot be removed to make a request fit. History trimming preserves complete tool-call/result groups; invalid or unfinished tool sequences are rejected. The latest complete group is always retained or construction fails. Every request reserves output tokens and a configurable safety margin and has a hard serialized byte ceiling.

Token estimation charges one serialized JSON byte as one input token and adds structural overhead. This favors conservative input selection for typical text without adding a tokenizer dependency. It cannot certify every provider's native tokenization. The runtime must supply actual model context/output limits and handle a provider's stricter validation. The [context contract](../contracts/context.md) specifies the estimate, byte limits, ordering, and failure behavior.

Compaction leaves authoritative raw events untouched. A deterministic extractive digest records covered event IDs/sequences, source hash, counts, bounded old-message snippets, and explicit information loss. The builder also accepts a summary generated separately by a real model, validates its exact source prefix, and preserves its provider/model attribution. It does not implement an LLM inference job or claim semantic summarization. Returned records are suitable for separate durable persistence; task state, event reconstruction, and saving records belong to host integration.

Retrieved memory carries wiki page and line provenance and remains quoted user-context data. Summaries also remain quoted user-context data. System messages in supplied history are rejected so immutable instructions cannot disappear during compaction. All active task constraints must be supplied in the explicit task object; the builder does not infer constraints from arbitrary older prose.

Opaque provider continuation is bound to the fixed context, a complete raw-history prefix, and the current compaction record. Append-only history with unchanged context and summary can preserve it. At completed turn boundaries, history rewrites, changed fixed context, a changed summary/cutoff, or budget pressure clear it with a reported reason. A tool round remains unconsumed while the newest assistant message contains calls and no later assistant has resumed after the results, including when user steering follows them. During that round, attempted clearing or compaction of the round returns a structured error because native reasoning or thinking state may be required to consume those results. The host must retain the stable prior context and cursor through that round, including across restart, and defer context-changing steering or compaction until it completes. Adapters remain responsible for continuation semantics and avoiding history replay.

Automated acceptance checks are deferred to [#32](https://github.com/izyuumi/everything/issues/32). No live provider request, semantic-summary evaluation, or runtime persistence integration is claimed by this foundation.
