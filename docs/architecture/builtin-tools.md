# Native filesystem and shell tools

`src/tools/builtin/` implements `read_file`, `write_file`, `search_files`, and `shell` using the native tool interface. `BuiltinTools` supplies their trusted permission registrations. Production calls go through the [Tool Broker](broker.md), which provides exact operation identity, mode enforcement, explicit approvals, durability, shared concurrency, and cancellation supervision. Direct registry execution is not a privileged production entry point.

Filesystem tools accept workspace-relative paths and operate through pinned directory handles. Every root and parent component is opened with established `cap-std` and `rustix` APIs, rejecting symlinks at the operating-system boundary. Reads reject nonregular and multiply linked files. Writes create a private same-directory temporary file, sync its contents, atomically replace the destination, and sync its parent directory. Replacement does not modify the destination's old inode. Existing parent directories are required; the tools do not create directory trees or provide backup/restore. Read-only tools may run concurrently; writes and shell execution use the broker's global exclusive gate.

Literal file search walks bounded directory entries, scans bounded UTF-8 file prefixes, and returns line numbers, excerpts, and explicit partial-result metadata. It skips symlinks, hard links, special files, non-UTF-8 content, and unsupported paths with bounded warnings. Markdown wiki indexing and semantic retrieval remain separate memory components.

The shell is explicitly trusted FullHost execution requiring exact-operation approval. It uses `/bin/sh -c` with the workspace as its initial working directory, null stdin, a fixed minimal environment, bounded captured output, and a separate process group. The leader remains unreaped while its group receives its termination signal, preventing a later group kill from targeting a reused PID. Readers drain stdout and stderr concurrently, and cleanup waits are bounded. The shell does not implement a sandbox: commands can access the host, read credentials directly from files, contact remote services, and deliberately escape a process group. Timeout or cancellation therefore reports uncertain effects and incomplete cleanup confidence even after ordinary descendants stop. The broker quarantines that uncertainty for owner review.

A host-provided literal redactor applies to returned text and diagnostics. Each call extends it with the task's resolved [vault](vault.md) values from the execution context, and the shell adds the task's bound `NAME=<value>` vault pairs to its otherwise cleared environment. It does not inspect credentials, infer every secret, alter file contents, or conceal exact arguments from the owner approval record. All outputs have a 64 KiB serialized ceiling. See the [builtin contract](../contracts/builtin-tools.md) for bounds, output semantics, environment, and verification limits.
