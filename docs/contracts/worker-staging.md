# Local approved worker manifest staging

`WorkerEndpoint::stage_approved(ApprovedDelegation, UnixMillis)` retains the consumed approval's complete immutable manifest locally and returns an opaque `StagedDelegation`. It requires a leased Coordinator endpoint, matching local identity and relay origin, a current worker-purpose pin, an unexpired real approval and an unstarted matching job. It creates no encrypted packet, outbox message, native task, provider, relay connection or Scheduler reservation.

The returned object has no Clone or serialization implementation. Its read-only `manifest()`, `binding()`, `fingerprint()`, `approved_at()` and typed `expires_at()` accessors expose the exact original approval metadata for subsequent trusted owner admission. `validate_for_admission(now)` checks the original monotonic and wall-clock expiry. This object and the stored manifest grant no dispatch authority.

Staging uses the existing coordinator `worker_delegations` row with `Offered` state and no message. A staged orphan can therefore be Offered without any Offer ever being sent. The existing schema-ten immutable manifest/binding triggers, 256-job limit, serialized 64 MiB ledger bound, ordinary job reserve and permanent revocation reserve remain effective. Exact canonical manifest bytes and SHA must match replay; the original attempt, peer and worker-native IDs cannot be adopted by another manifest. Cancellation, acceptance, result, rejection or revocation prevents fresh staging of that job.

The endpoint's owned authority mutex moves into the actual blocking transaction, which also retains the Agent lease. Real approval freshness is checked after the SQLite transaction acquires its lock and again before commit; expired work rolls back. Dropping the async caller cannot release ownership before its transaction finishes or suppress its committed-change watch notification. A cancelled caller must inspect the immutable snapshot to learn whether staging committed.

After restart, `snapshot` and `jobs` recover the original full manifest and deadline. Reopening does not reconstruct an approval object, renew its lifetime or create an Offer. An orphan without the real Scheduler reservation cannot dispatch. The real native reservation and Gate, exact first-offer enqueue/replay and Host integration remain sequential work; this staging prerequisite does not implement them. An authorized later dispatch must validate the current purpose pin and exact original manifest against the actual Scheduler permit. No new attempt or owner approval is inferred from the durable row.

The disposable public-data walkthrough retained and reopened the exact 329184-byte manifest, observed zero Offer messages/native tasks/connect syscalls, rejected changed replay and reused worker-native identities, rejected expiry while waiting on an actual SQLite writer, retained a committed stage and wake after its caller was dropped, enforced cancellation/revocation and rejected the 257th job. Both private databases had integrity `ok`, no foreign-key violations and mode0600. Exact source/driver/binary hashes and raw observations are retained in `/tmp/vorra-worker-staging-inspection/verification.json` with `main.rs`, `observations.json`, `connect.strace` and the static/release logs.
