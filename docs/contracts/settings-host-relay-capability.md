# Host-owned Settings relay capability

The Unix Host composition retains one opaque `SettingsRelayCapability` in its original `HostSettingsTransportOwner`. It owns the actual unscoped `SettingsService` clone, the existing `SettingsAgentRuntime` Arc and the same lean `HostSettingsTransport`. Its private fields have no `HostInner` back-reference, second Supervisor, task, channel, mutation guard or general authority factory. It is neither cloneable nor serializable.

Only Host code can call its consuming constructor. The existing startup block first creates the real transport and full owner, then successfully binds that transport to its actual Settings service. It constructs the capability from those same Host objects and installs the whole value before registering the original transport in the existing OnceLock and spawning the unchanged relay owner. No receipt authority is produced and discarded to simulate a consumer.

Installation compares the exact Host identity Arc, requires that actual owner to remain live and refuses an occupied field. Failure closes only the original receiving owner identity and returns the actual fixed `DeviceError::Invalid` with the same whole uninstalled capability in a boxed aggregate. It never replaces an installed value or closes a mismatched input's transport. The owner remains intact through failure mapping. Bind failure creates no capability; OnceLock failure drops the full owner through its existing identity-closing Drop.

The new optional capability is the full owner's last field, after the existing receive Work. Existing custom Drop first closes the actual Host identity; declaration-order destruction then allows original Work retention and fencing before releasing the supplier's handles. No existing field order or Work Drop changes. Releasing the supplier is neither a Supervisor join nor proof of clean protocol drain.

Owner and connected-owner accessors borrow that installed whole value. Absence is a fixed typed error, never a reconstructed/default supplier. `matches_host` establishes structural pointer identity only. `receipt_authority` forwards the existing same-service `paired_receipt_authority` producer and its real typed error; it does not bypass current Authority checks. `paired_runtime` borrows the original runtime without exposing its fields or creating another Supervisor.

These authority/runtime forwarders and the connected-owner accessor remain uninvoked by the current relay pump. Public Delivery retains ordinary `receive_envelope`, and both selectors remain OrdinaryOnly. The later dispatcher must coordinate a real disjoint borrow for mutable Work adoption and the borrowed runtime; this source does not invent that consumer. Final send, accepted dispatch, exact parent/creator/Supervisor retirement and complete Host drain remain separate prerequisites. An ACK, expiry, row deletion or released handle supplies none of those proofs.

This unit is validated by direct Rust formatting and static source review only until supported integrated CI runs. It establishes no compiler, transport, database, provider, runtime or security acceptance.
