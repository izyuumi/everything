# Native Host Settings controls

The macOS Models, Memory and Tool Selection panes use the existing app-owned `NativeSettingsStore`, `NativeSettingsLifecycle`, `NativeSettingsSession` and `OwnerIPCClient`. General, the read-only Host settings pane and the independent This Mac notification preferences remain separate sections. There is no model dependency, another client, another process supervisor or another Host configuration store. The [private Session contract](apple-native-settings-session.md) remains the authority and transport boundary.

## Draft and observation

`NativeSettingsDraft` captures one validated Host snapshot and registry. Models, Memory and Tool Selection edit a shared draft and submit one ordered batch. A model ID and the System One selection model ID remain opaque bounded strings. Endpoint policy remains authoritative in Rust. System One is opt-in; the TypeSafe preset is the existing `https://api.typesafe.ai/v1/systemone` endpoint and `jev-latest` model. Selecting Local disables the override without deleting a retained System One configuration or its reference. While Local is saved, enabling System One requires public metadata at the draft's revision whose retained endpoint/model match the draft seed; otherwise the toggle is disabled until reload, so an unread custom endpoint is never silently replaced by the preset.

Embedding enablement defaults to off according to the actual descriptor. Dimension choices come from the actual Host registry, including an explicit model-default option. Missing profile metadata disables dimension editing; the UI does not invent a supported list or infer helper health from a model name. Snapshot entries show saved, effective, pending, restart-required and unavailable values separately. Effective model configuration does not establish provider connectivity or successful inference. Lexical retrieval remains the fallback when the optional semantic boundary is unavailable. The Memory pane labels the dimension descriptor's actual apply behavior, such as Index rebuild required, and its static text makes no helper-readiness claim; readiness comes only from snapshot and application states. Error and warning notices use an icon plus an `Error:`/`Warning:` accessibility label rather than color alone. The General defaults section labels cached values when the Host is offline; Save remains disabled and nothing is queued.

The Store reads public credential-reference metadata with the same client's existing owner Settings query and constructs `OwnerSettingsDocument` using the acknowledged native Host ID. Only a document at the snapshot's actual revision is exposed; failure or a revision mismatch is visibly unavailable. A configured reference is not a secret-presence check. This read uses the existing nonsecret file-backed query route; native proofs, credentials, invitations and private native frames never pass through it. The [owner metadata contract](apple-owner-settings-metadata.md) defines the strict helper and separate initial-enrollment CAS flow.

Read refreshes never submit an effect. A foreground observer owns one task, sleeps two seconds between bounded Changes reads and advances the original cursor even when filtered rows expose no hints. Visible hints trigger an authoritative Get; known original operation hints also trigger read-only Inspect. A single Boolean coalesces reads already in progress. Foreground recovery and an observed Host reconnect request another read through the existing original session, without another Open or extended lifetime. Failed reads stop polling until an explicit refresh or a genuine activity/reconnect transition. A reconnect or activity request that arrives while a read is in flight is honored once after that read finishes, even when the in-flight read failed, so a Host that returns mid-read is re-read without another gesture. Cached observations are labeled stale, and fresh effect admission is disabled while stale or reading.

Dirty drafts retain their original revision, scope and descriptor set. A changed revision, Host identity or registry blocks Save and requires explicit reload and review. No automatic retry or rebase changes the patch. Reload discards drafts only after its actual read succeeds; a failed reload clears its discard intent. Fields cannot change during that read. After a known file save, the Store adopts a new baseline only when an actual snapshot is exactly the original next revision, contains the original changed values, and the draft still equals its captured submission. A later revision or intervening edit remains a conflict. Closing and explicitly reopening the same applied connection preserves dirty drafts for review; applying a different connection clears its presentation. Offline edits are drafts only and never queue an effect.

## Synchronous gesture and owned operation

`prepareAction(_:)` runs synchronously on MainActor. It captures the exact current snapshot, descriptor registry, owner identity and original `NativeSettingsAdmission` before a Button can create a Task. Its closed input accepts the existing initial Update, RequestAction, PairDevice and RevokeDevice intents only. These controls are now extended by the separately owned [secure-entry](apple-native-credential-entry.md) and [Devices](apple-native-devices.md) consumers. The opaque returned `Action` cannot be constructed by another file and exposes only its original operation ID and public context. Public IDs are not authority: execution also matches the exact retained admission object and actual owner; the Session checks its private gate/proof and the Host performs real admission.

`perform(_:)` starts at most one owned worker for that original Action. Dropping the view/caller does not cancel or replace that worker. The Store retains at most 64 original records, including unused, cancelled and terminal records; it does not evict an unresolved identity. An unused prepared ticket can be cancelled locally and is labeled as never submitted, without creating a Host receipt. All worker admission is bounded to four concurrent original operations and the same client/Session retain their existing four-RPC limits. There is no work queue.

Save constructs a new exact patch from the captured draft. Protected model/recipient changes return the original RequiresConfirmation reference. The pane displays the original batch and revision, and the separate Confirm button synchronously prepares exactly one original `ConfirmPatch` invocation before its owned task. Confirmation requires the same current owner, a fresh snapshot at the original revision, no prior attempted confirmation, and the original reference expiry. Lifecycle generation, actual active NSApplication/window state and wall/monotonic deadlines are rechecked by the existing admission. Draft edits cannot replace the reviewed patch, and a failed or uncertain confirmation exposes Inspect instead of minting another native attempt.

`NativeSettingsOperation` retains the original target, snapshot and registry, prepared receipt and validated inspection. Later inspections must preserve binding/origin, the terminal phase, any resolved file intent and any terminal application observation. The sole terminal-phase exception is actual file reconciliation: an original Finished Unknown with a retained unresolved write can become a validated Finished result with the same write identity and an actual Applied/NotApplied resolution. It cannot return to Awaiting, InFlight or Applying; a non-file terminal Unknown cannot gain a write or become known. Pending application remains an immutable saved-file receipt with a separate eventual application observation. Wall timestamps are data, not causal ordering: a legitimate later journal update can have an earlier timestamp after clock regression. The consumer therefore checks original identities and immutable facts instead of discarding observations by timestamp. Metadata validation does not establish journal authenticity or recompute an admission; the Host remains authoritative.

Unknown, Applying, in-flight, awaiting and transport-uncertain originals block new mutations. Inspect reads the same original operation. Reconcile explicitly observes only that original unresolved file intent; it does not rewrite settings or reapply a backend. Cancel targets the same original action and cannot claim a file rollback. No effect is replayed automatically after reconnect, close, a response loss or an error. Operation failures use closed sanitized errors, not request or response buffers.

## Lifecycle ownership and remaining boundaries

The app-owned window observer and connection composition bind the same Store; the assistant additionally receives a synchronous before-retire hook. Closing the window or replacing the connection synchronously invalidates the old lifecycle before another owner is published. Retirement captures and joins that owner's read, change observer and every effect worker, then joins its same original Session drain. An old callback cannot publish into a new owner. Unresolved cleanup keeps its original owner and report within the existing eight-owner bound. App quit awaits all retained owners before the same Root-owned client shutdown; none of these paths stops the independent Host.

The owned-action seam deliberately exposes no raw Session, proof, generic closure executor, secret payload or generic cache. Secure entry/initial metadata linking and private Devices presentation use their actual separately owned typed adapters; the optional [assistant composition](apple-settings-assistant-composition.md) shares this Store. Those integrated consumers do not establish remote Settings, actual credential storage/OS dialogs or successful inference.

Local validation covers complete Swift grammar and a genuine Foundation-only strict Swift 6 typecheck of the complete draft and its actual metadata dependencies. Actual AppKit/SwiftUI/CryptoKit registration and supported SDK compilation are present in the later integrated checkpoint below; UI/lifecycle observations remain unverified. No new automated tests are introduced; deferred coverage remains [#32](https://github.com/izyuumi/everything/issues/32). Implementation tracking remains [#114](https://github.com/izyuumi/everything/issues/114), [#110](https://github.com/izyuumi/everything/issues/110) and [#112](https://github.com/izyuumi/everything/issues/112).

The three new controls/draft/operation leaves are registered only in the macOS Sources phase using six new project objects and two append-only membership changes. The iOS phase and all other existing project objects remain unchanged. Later integrated #163 passed actual supported Mac/iOS build/analyze for the composed source. Historical grammar/Foundation subset checks remain limited, and SDK compilation does not establish UI runtime success.
