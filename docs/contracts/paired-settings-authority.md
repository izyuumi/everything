# Committed-Bind paired Authority

This held, uncompiled source adds a paired parent to the existing SettingsService/Authority. Host registration and calls are not wired by this increment. It enables no accepted public Delivery, paired SettingsCaller, command, child, tool, effect or reply publication. The [Settings contract](settings.md), [historical paired operation metadata](paired-settings-operations.md) and [owned Bind receive contract](settings-bind-receive.md) remain separate boundaries.

The native-v1 caller enum, NativeUi parent/child factories, operation identity and serialized reservation/fence/cleanup are preserved. A paired parent is a separate private type and map in the original Authority Sessions mutex. It never places a paired UUID into native session fields.

## Installation

The existing same ServiceCore must first attach the actual HostSettingsTransport handle. Attachment records its genuine Host identity Arc once, refuses another Arc even with equal public IDs, and rejects service stop/closed intake. It does not create a caller or grant authority. The later committed Bind must match both this exact Arc and the Core's original Agent state lease, Main connection, endpoint incarnation and mutation Arc through its opaque verified source.

Installation consumes the real OwnedCommittedSettingsBind returned only after its original receive worker joined. It does not invoke the source's precommit guard check: that original guard is intentionally inactive after the join. Instead it takes the actual Core Host mutation guard, moves it and the owned Bind into the existing blocking helper, and reads the current grant and complete verified device pin in one read transaction. No SQLite work runs on a Tokio worker. The original Bind private witness and full context remain owned through the blocking closure and its returned outcome; dropping the awaiting future is not a join. Ordinary admission failures return the original Bind alongside the typed parent failure. A blocking panic/join failure remains the existing Worker error and can leave the original history Unknown; it is never reported as a successful parent admission.

Checks include current non-revoked Host/peer, exact full pin, exact original grant ID/revision and full committed head, Active grant state, grant time, original fixed parent deadline, immutable intent/history state/lifetime/creator identity, and the sealed required reply reservation metadata. The actual wall cannot precede its commit reservation.created_at or the previous accepted parent observation. Under the same Authority mutex, installation rejects stopped/closed intake and retired connection/Host before creating the record. The grant read occurs under the canonical Host mutation guard, without a second Store connection inside its transaction. Direct out-of-band SQLite writes are not an instantaneous trust-monitoring guarantee.

Fresh installation additionally requires the original Bind issued/expires interval and monotonic deadline. The existing fixed parent lifetime anchors the Bind deadline: when parent expiry exceeds Bind expiry, subtract that exact millisecond difference from the committed parent Instant; otherwise the parent deadline is already stricter. This preserves the original clock base and never computes a new now-plus lifetime. Parent expiry remains the original min(requested expiry, issued_at+300000, grant expiry). Time and connection/stop state are checked again after actual entropy acquisition, before insertion.

A repeated lookup with the same retained committed owner may return the already installed exact record after the inner Bind interval expires, only while its original parent wall/monotonic bounds and current checks remain valid. It must match the original creator Arc, immutable intent, full pin, connection Arc and both fixed lifetime fields. It neither mints another parent nor extends deadlines. This is not a receiver for a fresh outer envelope carrying a known Bind, and CE Preparing/Unknown/history metadata alone cannot use this exception. That receive path and its actual precommit parent qualification remain absent.

Bind establishes a management parent, not provider consent or Settings chat admission. A grant with no configured-provider session consent can still bind for its allowed ordinary subset; no model request is made here. Chat later requires its own actual configured-provider/recipient/source checks and existing shared capacity admission.

## Ownership and limits

The parent map retains only fixed nonsecret intent/full pin, original creator Arc, lean connection identity, server-generated parent ID, cancellation and fixed wall/monotonic metadata. It contains no Agent, Store, endpoint, mutation Arc, ServiceCore, receive owner, body, callback or queue. The outward opaque parent holds the same Authority and exact map record; the map does not hold that outward handle, avoiding Authority -> handle -> Authority cycles. There is no serialized or public parent constructor. Parent and admission Debug are fixed redacted strings.

The map retains at most 32 original records for that Authority lifetime, including closed/expired/retired records, and at most four for one actual peer/connection. It does not evict or reuse an unresolved original. This conservative lifetime cap may require a Host restart after exhaustion; a connection replacement does not refund map capacity. The CE per-connection Bind history remains separate and unchanged. A reused public Bind ID on a different connection is a different map key, but cannot substitute for the original connection Arc. Parent IDs use established-library fallible OS randomness; collision is a conflict without automatic retry.

The owned admission returns the original committed Bind and either the exact opaque parent or a structured SettingsServiceError. Its metadata getters expose ID/expiry and a child cancellation token, not standalone current authority. Dropping an ordinary handle does not close a parent. Explicit close authenticates both the same Authority and exact map record and cancels only that parent. Authority intake stop cancels all its paired parents alongside the existing native close. Connection/Host retirement propagates cancellation through the lean connection token. Deadline expiry is checked at the service boundary; no background timer or claimed OS/provider join is introduced.

A caller must retain the original committed owner and inspect the real owned outcome. This increment does not change the CE BindingHistory state to Ready/Closed, free reply reservations, project private data, or claim receipt delivery/effect disposition. Parent close alone is not cleanup of future admitted child/service work. Later command/caller/child integration must add the actual same-transaction precommit parent gate, current policy intersections, owned publication permit and true drain witnesses before activation.
