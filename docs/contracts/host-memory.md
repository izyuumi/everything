# Host memory owner

`host::memory::MemoryService` composes one canonical Wiki, one Consolidator and optional local EmbeddingGemma 2 retrieval under the actual Agent state lease. This leaf API does not register host settings, IPC commands, CLI commands or scheduler context hooks; those remain issue [#68](https://github.com/izyuumi/everything/issues/68) composition work.

`MemoryService::open(agent, settings, optional_provider_factory, cancellation)` validates settings and opens fixed private paths under the retained `Agent::state_directory()`: `memory/wiki/`, `memory/lexical.sqlite3`, and `memory/maintenance.sqlite3`. An unleased Agent is rejected. Directories must satisfy the host's private directory policy; database files must be owner-only, single-link regular files opened without following the final symlink. The same owner is used for retrieval, maintenance, lint and semantic rebuild. Canonical files and derived indexes remain subject to the existing trusted same-user filesystem boundary.

## Settings and effective status

`MemorySettings` uses serde defaults and rejects unknown fields. Defaults enable local evidence retrieval with eight results, at most 4096 UTF-8 bytes per excerpt and a 32-KiB aggregate serialized captured-memory budget. Limits permit 1–16 results, 64–16384 excerpt bytes, and 1–256 KiB aggregate bytes. Actual paths, line ranges and whole chunk identities are preserved; over-budget hits are explicitly counted as omitted. Excerpt truncation preserves UTF-8 boundaries. Retrieval does not issue an answer-model request. Disabled retrieval returns no captured excerpts.

`maintenance: null` calls `Consolidator::open_offline` without a model or provider. An explicit `MaintenanceModelSettings` contains only provider, exact official/loopback endpoint, model ID and maximum output tokens. It reuses the actual TaskProviderFactory and its endpoint-bound credential resolution. User instructions or temperature are not accepted as maintenance settings; native consolidation owns its instructions and source-validation protocol. Construction is bounded to thirty seconds and cancellation/timeout cancels the factory child token. Missing factory, unavailable credentials/provider or incompatible reported context/output capabilities leaves an offline owner with an explicit unavailable status. The default constructs no provider. Context tokens default to 32000 and the model timeout to 120000 ms; validation uses the actual configured output budget.

`EmbeddingSettings` defaults to `disabled`. Opt-in mode `embedding_gemma2` requires a runtime-library path, expected SHA-256 digest, pinned model-bundle path and one of 128/256/512/768 dimensions. Optional execution settings retain the existing backend defaults and bounds: 1–16 threads, 8–8192 input tokens, positive inference/load deadlines through 300 seconds. No model download, alternative model, remote embedding provider or automatic rebuild occurs.

Disabled embeddings perform no vector database open, runtime/model file reads, dynamic runtime initialization or inference. Feature-disabled builds report configured embedding availability honestly and retain FTS. Enabled construction opens the runtime input without following its final symlink and with nonblocking mode, verifies that it is a regular file no larger than 256 MiB, and checks the expected hash before calling the existing runtime initializer. The runtime's own reported digest is also checked. Operators must choose a trusted runtime and protect its path and ancestors: hashing is not a race-free attestation of a later path-based dynamic-library load against malicious same-user replacement. The existing backend verifies the pinned bundle. One model load serves the selected profile using `with_dimensions`; initialization and inference remain off Tokio workers. Process-global ONNX runtime initialization and immutable service configuration make configuration replacement a host-restart operation.

`status()` separates desired settings available through `settings()` from actual maintenance/embedding/worker status. Initialization failures retain bounded typed diagnostic codes, attach the Consolidator's genuine FTS failure provenance and do not fabricate semantic results. Query fallback mode and omission counts remain part of `RetrievedMemory`. Cancellation is an error. Wiki/lexical failures are not converted into an empty successful retrieval.

Feature-enabled construction first calls the backend's telemetry-suppression preflight before opening or hashing the runtime. The process must have been launched with `ORT_DISABLE_TELEMETRY=1`. Otherwise desired opt-in settings remain visible, effective embeddings become `unavailable` with `embedding_telemetry_suppression_required`, and real FTS remains available with semantic-failure provenance. No runtime, model or vector database is read in that case. The backend repeats the preflight before initialization and keeps API telemetry suppression. This is a supported trusted-runtime control, not an OS sandbox or an attestation about earlier foreign ORT initialization.

## Calls and lifecycle

`retrieve(question, cancellation)` accepts the existing nonempty, single-line retrieval question of at most 4096 UTF-8 bytes and 64 whitespace-separated terms. It returns real bounded `MemoryExcerpt` values, retrieval summary and omitted-hit count for native context capture. A scheduler deriving a query from a multiline task must bound and normalize that derived query separately while preserving the original objective. The caller must persist the captured result for the exact command before inference and reuse the saved result on active resumes. This service does not itself mutate scheduler task definitions.

`consolidator()` exposes the actual owner to trusted host code for existing ingest/query/lint/job/cancel/retry/host-plan operations. The host must enforce owner authorization and stop new raw Consolidator work during drain. It must not retain raw owner clones as independent services after shutting down the memory owner. Feature-enabled `semantic_status()` and `rebuild_semantic(budget, fresh, cancellation)` expose real generation state and resumable bounded rebuilding. Their budgets, cancellation, stale/incompatible-generation fallback and inference rules are the existing [hybrid contract](hybrid.md).

One supervised Consolidator worker starts on successful open. Its supervisor retains the Agent through worker shutdown and actual blocking-admission quiescence. Dropping the last MemoryService owner cancels that worker; it does not abandon the retained supervisor. Initialization is also owned: dropping the caller signals cancellation while its retained Agent remains alive until blocking constructors settle. `shutdown()` rejects later service retrieval/rebuild work, cancels and awaits the worker, and waits for actual Consolidator admission to become idle. A dropped shutdown caller does not abort the supervisor. Unexpected worker/quiescence failures are reported rather than swallowed.

The retained Agent is the last service-core field destroyed, preserving its state lease through final owned Consolidator, SQLite and native resource destruction. Stopped worker status proves work quiescence; it does not claim all trusted owner clones or their resources have already been dropped. Final resource destruction remains part of dropping the last owner after the host has drained callers.

`Consolidator::wait_idle()` acquires its real single admission permit, so detached blocking reads/rebuilds must finish before the barrier returns. This is a point-in-time blocking-work barrier, not a worker-stop command or a ban on future raw calls. Before relying on it for final host lease release, the host must stop new handler/scheduler/raw-owner admissions, cancel and await their owned work, and stop the Consolidator worker. A model request runs outside blocking admission; waiting for that worker separately is required. Owner cancellation/status handling and the host's broker cleanup rules remain authoritative.
