# Builtin tool contract

## Registration and authority

`BuiltinTools::new(BuiltinConfig { redact_literals }) -> Result<BuiltinTools, ToolError>` constructs four native tools. `register_into(&self, &mut ToolRegistry) -> Result<BTreeMap<String, ToolScopeRule>, ToolError>` registers them and returns their trusted scope rules. Add the returned rules to the same registry's `Authorizer`. Duplicate names fail before registration begins. Fixed schemas are compiled through the registry; initialize on a blocking boundary. The implementation uses existing `cap-std`, `rustix`, Tokio, Serde, and UUID dependencies.

`register_workspace_into(&self, &mut ToolRegistry)` registers only entries whose trusted scope is exactly `ToolScopeRule::Filesystem`. The returned registry and scope additions contain `read_file`, `write_file` and `search_files`; neither `shell` nor any Host-scoped tool is installed. Filtering happens before duplicate preflight as well as actual registration, so an unrelated existing shell registration does not block a filesystem-only registration. Both methods share the same registration path and preserve live broker permission enforcement. Rust 1.88 default/all-feature all-target checking and strict Clippy passed for this registration path. Disposable actual Broker inspection confirmed exactly three filesystem tools, no shell descriptor, duplicate preflight, unchanged all-builtin registration, ReadOnly write denial, TrustedWorkspace write/read and denied traversal/absolute/symlink/hard-link effects with unchanged outside content.

`read_file` and `search_files` declare filesystem-read capability, read-only behavior, concurrent execution, and `Filesystem { path_pointers: ["/path"] }`. `write_file` declares filesystem-write capability, exclusive execution, and that same scope pointer. `shell` declares shell capability, exclusive execution, and `Host { service: "native_shell" }`. ReadOnly cannot write; TrustedWorkspace cannot execute shell; FullHost still requires exact shell approval. Builtin file tools remain confined to workspace-relative operations even under FullHost. They do not provide an unrestricted filesystem mode.

All privileged calls must use the broker. Host-issued context supplies request/task identity, workspace, and cancellation; arguments cannot replace those values. Use one global broker and its task-scoped clones. Configure broker cancellation grace for at least two seconds so normal shell cleanup can complete; a shorter grace remains fail-closed through broker quarantine.

## Paths and file effects

Paths contain 1–1024 UTF-8 bytes with normal relative components and no controls or backslashes. Absolute paths, parent components, and current-directory components are rejected. `search_files` alone accepts `.` for the workspace root. Components are opened relative to pinned directory descriptors with `NOFOLLOW`; regular reads additionally use nonblocking open to avoid waiting on special files. Every regular-file read checks for exactly one hard link. Symlinks, special files, directories used as files, and multiply linked files are rejected or explicitly skipped during search. No directory traversal follows a symlink. The workspace's canonical root path is reopened component by component without symlinks before the operation.

These boundaries confine the operations performed by the native tools; they do not isolate the host from another process with the same filesystem privileges. A concurrent external process can rename directories, modify file content, or change hard-link counts. Reads are not snapshots, and the link-count check describes the opened inode when inspected. The broker coordinates its own tools, not arbitrary external processes.

`write_file { path, text }` accepts at most 262144 UTF-8 bytes and requires an existing parent directory. It creates a unique `0600` temporary file, writes in cancellable 8192-byte chunks, syncs it, checks cancellation, renames within the same pinned parent, and syncs that directory. Existing destinations must be regular, singly linked files when inspected. Replacement installs a new private inode and does not follow a final destination symlink that races the rename. Existing destination permissions are replaced by `0600`. Success returns `{ bytes_written, atomic: true, mode: "0600" }`. Filesystem support for atomic rename and sync determines the underlying durability guarantee; only the immediate parent directory is synced.

A failure before creating a temporary file reports `FailedWithoutSideEffects`. A failure or cancellation after creation attempts removal and directory sync and reports `EffectsUnknown`; completed cleanup is asserted only when the owned synchronous work ended and temporary cleanup succeeded. Failure after rename may mean the new contents are already visible. No interrupted write is silently retried. Cancellation racing the final commit can produce a successful write with broker interruption metadata; the native loop must honor `requires_stop()`.

Filesystem operations run on Tokio blocking workers with broker admission limits. Reads and search are finite and observe cancellation at bounded iteration boundaries; writes observe it between chunks and before commit. An operating-system call on an unhealthy filesystem can block beyond those checks. Rust cannot forcibly interrupt that call. If broker cleanup expires, its quarantine remains necessary while the owned blocking operation may finish; host owner review must establish completion before acknowledging cleanup. There is no deliberately detached filesystem worker or background retry.

## Read and search output

`read_file { path, offset? }` defaults offset to zero and returns at most 8192 raw bytes from that offset. `text` uses explicitly flagged lossy UTF-8 decoding. Results contain `offset`, `bytes_read`, observed `total_bytes`, `truncated`, `utf8_lossy`, and `redacted`. Truncation also covers redaction expansion beyond the returned text budget. Subsequent ranges use raw byte offsets; a range can start or end within a UTF-8 character. No binary-content decoding guarantee is implied.

`search_files { path, query }` performs case-sensitive literal substring matching in regular UTF-8 file prefixes. Query is nonempty, has no line breaks, and is at most 256 Unicode characters and 1024 UTF-8 bytes. Search limits are five seconds between filesystem calls, depth 16, 4096 visited entries, 1024 scanned files, 262144 scanned bytes per file, 4194304 bytes total, 100 matched lines, and 45000 serialized bytes for the match array. Directory entries are sorted within each bounded directory batch. A matched line returns `path`, one-based `line`, `text` from the matched line around its first match, and `truncated`/`redacted` flags. A line that fits the excerpt is returned whole; a longer line starts at most 96 bytes before the match (earlier if the rest of the line is shorter than the excerpt), on a UTF-8 character boundary, and `truncated` reports any omitted leading or trailing text. Excerpts contain at most 256 UTF-8 bytes after redaction. There is one result per matching line, rather than one per occurrence.

Search returns `complete`, unique `limits`, up to eight bounded `warnings`, `entries_visited`, `files_scanned`, `bytes_scanned`, and `skipped_entries`. Bounds, skipped unsupported entries, unreadable entries, and non-UTF-8 content prevent a complete claim. A file prefix ending inside a UTF-8 character is skipped with an explicit warning. Partial matches are useful output and are not presented as an exhaustive search. Search cancellation reports a definitive read-only interruption through the broker error contract.

## Shell execution and cleanup

`shell { command, timeout_ms? }` accepts a nonempty command of at most 16384 Unicode characters and 65536 UTF-8 bytes, without NUL. Timeout defaults to 30000 milliseconds and accepts 1–300000. The broker execution deadline is an independent upper bound. The command runs as `/bin/sh -c` with workspace current directory, null stdin, and cleared environment containing only `PATH=/usr/bin:/bin`, `LANG=C`, and `LC_ALL=C`. It inherits no ambient HOME, API keys, SSH-agent socket, startup-file variables, or dynamic-loader variables. An explicitly approved command can still read host files or set its own environment. Unix platforms with `/bin/sh`, process groups, and `waitid` with `WNOWAIT` are required; Linux was manually exercised and macOS requires its CI build and runtime follow-up.

Stdout and stderr drain concurrently while retaining their first 4096 raw bytes each. Output contains redacted/lossy-decoded `stdout` and `stderr`, full drained byte counts, per-stream `truncated` and `utf8_lossy` flags, `redacted`, `exit_code`, `signal`, `process_group_stopped`, and `sandboxed: false`. Nonzero exit or termination by signal is a completed semantic failure (`ToolOutput.is_error = true`) with output retained in the broker's terminal failed record. The same operation ID replays that record. A returned zero exit is the shell leader's completed status, not a claim that indirect remote effects completed successfully.

The child starts a separate process group. Normal exit is observed with `waitid(EXITED|NOWAIT|NOHANG)`, retaining its PID until the owned group is sent SIGKILL. The group-kill guard is disarmed before the leader is reaped, and no later group-kill operation is issued. Reaping and remaining pipe drains each have a 500-millisecond cleanup deadline. Signal-zero checks allow 250 milliseconds for the group to disappear. On macOS `killpg` returns `EPERM` for a group whose only member is the exited, unreaped leader, so the guard accepts `EPERM` only after `waitid` has observed that exit; the following reap and `ESRCH` group-absence check remain the cleanup proof. Before this correction every successful macOS shell call reported `EffectsUnknown` and quarantined the broker. The guard verifies child ownership again immediately before every signal path and also signals the still-anchored leader directly, covering a leader that moved out of its original group. Tokio's automatic direct-child kill-on-drop is disabled so it cannot signal a reused PID after an unexpected external reap. Unexpected future drop verifies the child is still waitable, signals its anchored group and leader, and then allows Tokio's orphan-reaping fallback. An `ECHILD` observation disarms signaling and returns unknown rather than risking a signal to reused identity. The host must not install a competing global child reaper; only the tool owns this child. Errors, remaining processes, or open pipes report uncertainty.

Timeout and cancellation kill the owned group, reap the leader, and finish bounded output cleanup. They always return `EffectsUnknown { cleanup_completed: false }`: arbitrary trusted shell code can deliberately leave the process group or start remote work. The broker persistently quarantines such work. A host owner must inspect actual processes and effects before cleanup attestation. This policy intentionally avoids claiming that process groups constrain arbitrary shell or establish universal descendant cleanup. No elevated helper, container, OS sandbox, network restriction, or credential isolation service is installed by these tools.

## Redaction, output budget, and validation

Host configuration accepts at most 64 nonempty literal redaction values, each at most 1024 bytes and at most 16384 bytes total. Overlapping literal spans are masked as one region. Replacement scans original bytes once from bounded look-behind so replacement markers are never recursively redacted. Masking uses original byte spans before lossy UTF-8 conversion. Read ranges include bounded look-behind and look-ahead, and search excerpts retain full scanned-file context, so offset ranges and query positions inside a configured literal remain masked. Literals spanning line boundaries are also masked. A truncated stream's trailing prefix of a configured literal is redacted. Text budgets are enforced after replacement, with explicit truncation flags. Returned read/search text, stdout/stderr, paths, and diagnostics receive configured literal redaction. Each call also adds the task's resolved vault values carried by the execution context (at most 16, each at most 8192 bytes) to that call's literal set; when one of them is masked, the output gains `vault_redacted: true`. The Host passes no static literals; the foreground CLI still passes `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`. `shell` sets `PATH`, `LANG` and `LC_ALL` as before and then the task's bound vault `NAME=<value>` pairs from the context; names that would override those or change loader or shell startup behavior are refused by `vault_use`. See the [vault contract](vault.md#per-task-redactor). Written content and durable exact invocation arguments do not. This is configured literal filtering, not automatic secret classification; unconfigured secrets and deliberately transformed values may remain visible.

`MAX_BUILTIN_OUTPUT_BYTES` is 65536 bytes including the serialized `ToolOutput` envelope. Stream and excerpt limits leave room for escaping and metadata; an unexpected overflow fails explicitly rather than returning an oversized public event. The downstream 256 KiB event budget must still include its provider/event envelope. The host must not log raw tool inputs or pre-redaction output.

Native filesystem operations reserve caller-relative `.everything-agents` and `.everything-workspace.json` path components for scheduler control state. Direct reads/writes/search roots reject them, and recursive search skips them. This check applies to the supplied path within the current authorized workspace; ordinary files inside an isolated child workspace remain usable. FullHost shell is unrestricted and is not an application filesystem sandbox.

When the runtime holds a leased state directory (the Host, and offline `chat --tools` with its lease), `read_file`, `write_file` and `search_files` also refuse paths inside that directory with `path is inside the protected Host state directory`, failing without side effects. The path is first validated as workspace-relative; the tool then canonicalizes the target (resolving symlinks and `..`; for a missing file, its parent, and only when the error is not-found; any other canonicalization error fails without side effects and reports that underlying error, which carries no path) and compares it with the canonical state directory, and every directory opened while walking the workspace root and the path is also compared with the state directory's device/inode. Recursive search skips the state directory with that warning. The Host-managed `<state>/workspace` subtree is exempt when it is a real directory (a symlinked `workspace` is not exempt): it is the default `workspace_root` that `host-settings-v1.json` persists, so file tools keep working there. A root inside it skips the root-walk identity check, and a target whose canonical path stays inside it passes the pre-check; a symlink from there to anything else in the state directory resolves outside the subtree and is refused. An ancestor workspace such as `$HOME` still cannot reach `<state>/workspace` through the state directory, because the walk passes the state directory itself. The error never contains the path or file contents. A workspace that contains the state directory is still accepted; only paths inside it are refused. A runtime without a leased state directory (the worker process, library callers built from a bare `Store`) has no such check.

Reserved names are checked without ASCII case sensitivity. Descriptor device/inode comparisons also reject filesystem-equivalent directory and marker aliases during traversal/read/replacement, rather than implementing a filesystem normalization algorithm. macOS alias behavior still requires platform runtime verification.
