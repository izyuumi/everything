# Settings operation core

The #109 core extends the [typed contract](settings.md) with one leased Host authority and one bounded operation journal. This first source slice implements authentication, exact retained action identity, native admission and closed native observations. Host/CLI registration, the secret pipe, device route binding, describe/get/update, cross-store file application and dynamic memory/selection changes are not integrated by this slice. It does not establish that the full settings facade works. A locked Rust1.88 all-feature workspace/all-target check passed on frozen afb4c4d with expected unconsumed private-entry warnings and one unused import. Later source corrections have formatting/static inspection only; full production integration, strict analysis and runtime validation remain separate coordinator gates.

## Trusted sources

SettingsService opens only with the same actual Agent StateLease as SettingsRepository and the actual configured Host endpoint identity. It shares the Host mutation admission supplied by composition. LocalCall is the server-created same-UID authenticated local request; a supplied principal/session UUID cannot create a caller. The local-owner caller, native UI caller and host-created restricted Settings session are distinct private source variants.

A native session receives a random 32-byte private capability through a dedicated sensitive pipe route once that route is implemented. Only a domain-separated SHA-256 fingerprint remains in its bounded in-memory record. Capability encoding uses the existing base64 library, randomness the existing OS RNG and secret ownership zeroizing storage. Public IDs, action references, operation inspections and receipts are data. There is no app attestation claim or new remote grant. Sensitive session/credential/invitation values must never reach ordinary request files, model arguments, durable rows, snapshots or logs. Secret-bearing wire types have redacted Debug and share one zeroizing allocation through Arc when the existing local transport clones a request/response. Opaque Rust callers, restricted-session leases and native admissions remain non-Clone/non-Serde. Frame, serde, Swift and OS buffers do not provide universal zero-copy or secure erasure.

There are at most sixteen native sessions and sixteen restricted Settings authority sessions. Native session lifetime is five minutes with original wall and monotonic deadlines. Closing a one-shot CLI connection is not UI-session close. Explicit close, UI-target change, expiry or Host restart rejects new admission; no replay extends a lifetime. An already-admitted exact action may finish/inspect through its original private session proof after close/expiry while that session remains retained. Such cleanup cannot read a fresh action, approve another patch, start another effect or retry a credential. A current authenticated local owner can inspect authorized historical receipts after restart.

SettingsAgentSession is an opaque authority lease minted from a live native UI caller. It is not an implemented agent runtime. Each caller minted from that lease is bound to one of the seven SettingsToolName values; action and device preparation require the matching exact tool. It cannot perform native admission/finalization or create owner/native authority. Closing/dropping its lease cancels its ceiling; native confirmation rechecks this original source. The actual immutable restricted profile and executable seven-tool namespace remain #113 work. There is no remote caller constructor; #116 must supply verified envelope/live explicit grants before such a path exists.

## Original operation and confirmation

The retained closed target is a SettingsPatch, SettingsActionRequest or SettingsDeviceRequest. Shape validation preserves the original exact typed bytes, scope and genuine optional revision. Fresh confirmation metadata is rejected. Binding also retains actual principal, native parent session, origin kind/Settings session where applicable, canonical request digest and original times. Changing any target, origin, revision or binding under the original request ID conflicts.

| Private phase | Public interpretation |
| --- | --- |
| AwaitingConfirmation | The original protected patch returns its one original reference and expiry. |
| AwaitingAction | The original native/device request returns its one original handle and expiry. |
| InFlight | One exact native request has been admitted; inspection reports this phase without inventing a settings revision. A projected operation outcome remains unknown until completion. |
| Finished | The retained authoritative result is immutable and replayable. |

Native confirmation/admission is a separate request tied to the retained original operation and exact reference. It does not add a confirmation field to an agent's original patch or mutate that patch's identity. One native claim per original effect is enforced by the database. Repeating the exact claim returns Existing inspection and never grants another dialog. Changing its native request ID, session or reference conflicts. Host grant/session/revision and the original monotonic deadline are rechecked under SQLite admission and before commit. No file mutation or protected patch application is supplied by this initial core.

NativeActionAdmission is opaque, non-Clone and non-Serde. It retains exact identity, cancellation, the actual Agent and state through real worker completion. `check_new_effect` rejects closed, cancelled or expired admission using both original wall and monotonic bounds. It is not permission to bypass actual credential/device validation. Host effect adapters must own their actual mutation admission and finish from the real vault/endpoint result. The direct pairing adapter below and the [device facade](device-settings.md#shared-settings-facade) perform real endpoint operations; vault execution and native route binding remain separate work.

## Closed native observations

The native-only finalize surface accepts only Dismissed, exact known-section navigation, or actual notification authorization observation. It validates the original private session, admitted request and action kind, then the service generates the stable receipt. A supplied SettingsOperationResult, receipt ID or generic success flag is never accepted. Native observations cannot complete a credential write or device mutation. Observed OS state is not a grant. Cancellation closes admission and requests safe cleanup; it does not assert rollback of an admitted OS/Keychain effect.

The first source slice cannot validate a device preference revision without its actual device-owned adapter. Such valid but unsupported action requests return durable native-action-unavailable, rather than borrowing HostSettings revision. #110 supplies that real local adapter and notification/credential routes. No model/provider request is made by this core.

## Durable storage and resource limits

Migration0013 adds three tables to the existing Agent Store after actual worker schema12:

- settings_operations: immutable typed original identity, original creation/expiry, at most18KiB per canonical JSON record.
- settings_native_requests: immutable exact native request binding, unique native ID and unique original operation ID, at most1KiB.
- settings_operation_updates: append-only indexed sequence/phase/result, at most2KiB per canonical record. Later key-only change hints have a separate1KiB bound.

SQL enforces JSON/identifier/time/byte shape and immutable-row triggers. Typed reads check canonical encoding, complete binding/target digest, source identities, reference expiry and actual native-claim linkage. Lengths are checked on borrowed SQLite text before copies. Private DB data alone never mints a live caller/native session.

There are at most1024 combined retained original/native request identities,64 pending operations and8192 updates. Preparation reserves future native-identity and terminal-update capacity in the same transaction; a pending operation cannot consume the last space needed for its own claim/completion. Exact retained replay precedes capacity checks. No receipt/identity is evicted or silently renewed. New admission fails visibly when retention is exhausted. The unique native claim covers a single effect: a pairing creation receipt does not represent later trust approval or pending invitation cancellation.

Startup closes old unadmitted requests as expired and old InFlight requests as Unknown because ephemeral native authority was lost. It never recreates a session, invitation, confirmation or effect. Final known native observations replay only with their original exact source and observation. Host worker/file/Keychain reconciliation will need additional exact effect evidence; this slice makes no atomic cross-store claim.

All blocking work retains the complete service core, whose actual Agent is its last field. Native claims separately retain their actual Agent last. Owned Host mutation guards move into the actual blocking worker before awaiting, so waiter cancellation cannot release them ahead of SQL work. There is no standard mutex held across an await and no detached unowned effect.

## Native-only pairing ownership

`create_pairing` consumes the opaque NativeHostEffectAdmission and uses the exact Host endpoint retained by service construction; callers cannot supply another endpoint. One owned blocking worker retains the same Host mutation guard and whole Agent while it creates, attaches and journals one real pending invitation. It caps the endpoint lifetime by both remaining original action deadlines. An exact replay cannot receive a second effect admission, create another invitation or renew its expiry. The private creation update contains only the real pairing ID and expiry; the invitation, QR material and native proof are absent from SQLite, chat and relay records. SecretTransfer shares the zeroizing private invitation allocation and its Debug is redacted.

The creation's service-generated Completed receipt means that this exact invitation was created. It is not device approval, a grant or a promise that the invitation remains pending. Later `native_pairing` re-displays only that same retained invitation to the original authenticated live native session. Its last copy check samples the retained session cancellation plus both original expiry bounds while holding the private invitation state guard, after any mutex wait. `cancel_native_pairing` and session close cancel the exact endpoint ID outside standard mutexes; they never rewrite the historical creation receipt. The slot is attached under the claim lock with a latched close check, and creation rechecks the original source after its journal write. A creation completing after close or expiry therefore attempts actual exact cancellation before returning any invitation. Cancellation failures remain visible and retryable as CancellationPending; no blanket error means success.

At most eight live invitation leases are retained. Each owns the endpoint, original admitted native-session resource and Agent last. Known cancelled/expired/no-longer-pending slots release their private material and resource ownership; their immutable creation receipt remains readable. Unavailable after private-slot release or Host restart means the invitation cannot be re-displayed, rather than claiming cancellation or manufacturing a replacement. NotPending from the actual endpoint may also mean approval already consumed it. Neither cancellation nor hiding a view erases previously displayed material or proves remote stop.

`stop_intake` synchronously closes only the authority. Async `close` then requests actual retained claim/pairing cleanup through the owned blocking worker, outside Host mutation admission. It does not certify completion or rollback of an already-admitted external OS/vault effect. These pairing/stop source additions have Rust1.88 formatting and static inspection only at this slice; fresh production compilation, real route/manual expiry/replay/caller-drop/close observations and required integration gates remain pending.

`inspect_native_operation` is a separate cleanup-only bounded read for the authenticated original NativeUi session. It validates the actual retained cleanup caller, exact original client-session identity and principal, without expiration mutation, new admission or a revived grant. Ordinary `operation` retains normal live-caller checks and does not grant cleanup authority to LocalOwner or SettingsAgent modes.

## Revisioned facade foundation

The private LocalOwner source records the authenticated LocalCall frame request ID. Its journal logical scope uses that exact command UUID and is explicitly distinct from a NativeUi session. No supplied request ID mints a caller or native authority. Ordinary historical owner inspection remains scoped by the real owner principal, while a mutation must retain its actual original frame/request binding. This identity foundation does not yet implement owner patch or full-file application.

The two public Rust attenuation methods, begin_settings_session and settings_session_caller, require the existing opaque live host-created native caller/session. They expose no owner/native source constructor, serialization or arbitrary-ID authority. This authority API is not the future #113 restricted model runtime/profile/tool-dispatch implementation.

HostSettings now represents defaulted strict preference_overrides. Missing enable values inherit the legacy operator configuration; explicit false can preserve that configuration for later application. The dimension choice distinguishes Inherit, BackendDefault and Selected rather than ambiguous nested Option parsing. Repository validation checks only closed syntax and bounded dimension shape; actual edits must separately validate the real cached profile before effects. These fields alone do not change effective feature admission or load a model. Runtime resolution/live application remains pending. SettingRegistry.from_profile uses an actual known EmbeddingProfile and shares the existing descriptor construction; an absent profile still supplies no dimension choices.

The next writer foundation adds Applying with an immutable versioned full-file pre/post fingerprint and a typed applied/not-applied resolution. Public inspection exposes only revisions, changed key names and restart status. Applying and an unresolved Unknown are already admitted: cancellation, native-session close, expiry and service drain retain the original intent and only request cancellation. Startup exposes OptionalFeaturesSuspended while one unresolved intent remains, so the Host can close optional admission before loading anything. A lost or changed intent fails journal validation; it cannot silently reopen a writer. This source increment does not yet create file intents, apply patches, reconcile disk state or control live optional features. The actual writer and finalization transaction are the next implementation boundary.

Private file-write primitives now prepare only against an actual validated disk snapshot equal to the repository cache and derive complete canonical SHA-256 fingerprints including revision. Observation accepts only the original pre/post fingerprint, and adopts the observed cache only for those exact states. A third state remains unresolved; no arbitrary external snapshot is adopted. Typed begin_write atomically inserts or transitions one original operation to Applying, rejects another unresolved writer and reserves finite completion/repair capacity. Typed finish_write can resolve only that same immutable intent and does not relax known native receipt replay. These primitives are not yet a public patch writer or live-application consumer. Their current validation is formatting and source inspection; fresh compilation and disposable file/DB failure observations remain pending.

The facade can bind exactly one actual Arc<Composition> after verifying the same Store and retained StateLease identity. Rebinding the same Arc is harmless; a different instance conflicts. This is a consistency check, not a grant, and the service retains it before its Agent-last field without a back-reference cycle. The typed patch converter preserves unrelated fields and operator configuration when disabling a feature. Model bootstrap uses the existing CLI instruction/output defaults without discovery or connectivity. Dimension edits require an actual known profile; missing metadata is distinct from an unsupported dimension. These source primitives do not themselves admit a writer or apply a backend.

A file-resolved PendingApplication receipt may acquire one separate terminal application observation: Applied, RestartRequired, a closed Unavailable reason, or a closed Failed reason. The original file phase/result and full fingerprint remain immutable. Exact application replay returns that observation; changing it conflicts. Reads anchor both the resolved file receipt and any terminal application observation to their first retained record. Admission reserves its one future terminal row, which is released after observation. No per-chunk progress is journaled. The runner must prove the original committed file/generation still matches before recording Applied; a superseded generation, later file or stopped helper cannot supply that proof. An unobserved PendingApplication remains pending after restart, and unavailable/failed application is terminal rather than a retry instruction. The actual runner/hook consumer is not yet implemented in this source increment.

The implemented changes API reads at most128 indexed journal rows after a stable sequence, validates each bounded historical update against its original identity and retained intent, and rechecks the live caller before returning. Each redacted hint is at most1KiB and a page at most32KiB. The original authenticated caller may see its operation state; other authorized Host readers receive only shared applied-key facts with no foreign operation ID. Hints contain no values, recipients, paths, credentials, references or invitation material. Filtered rows may advance the cursor; a visible row excluded by the page byte limit remains available on the next page. The watch counter publishes only after actual commit and Store mutex release, carries no authority, and is only a wake hint for scoped journal rereads. Restart may reset that ephemeral counter; durable sequence cursors remain in SQLite. These additions have source/format validation only, with route/manual verification pending.

Explicit reconcile_write is an owner/native cleanup observation of the original operation, not a settings-agent recovery capability or a new file-write attempt. It holds the same owned Host mutation guard and whole core through the actual private-file read and receipt transaction, and never reapplies a patch or invokes a backend. Only exact original pre/post proof resolves the intent. A known unchanged pre-file state records a no-file-effect failure; a known post-file state records its actual revision and leaves affected optional features PendingApplication. A third state remains Unknown; an unreadable file or uncertain journal result reports the original identity and structured repair cause. Closed native cleanup requires the retained original session, while SettingsAgent callers cannot invoke this repair surface. Known receipt cleanup does not rewrite that receipt when later bookkeeping fails. Actual startup/owner route binding and backend restore/application remain pending.

Full-owner classification is metadata-only. New model selection, configured System One endpoint/model changes (including while off), or a changed effective tool-selection preference require native protected confirmation. Credential-reference-only owner changes do not become agent-editable keys: they stay bound to the full canonical owner request and CAS, and System One reference changes require actual selector reconfiguration. The credential adapter still requires an already-configured exact binding; this classification does not implement credential enrollment or claim vault success. Full-owner restart flags cover retained non-embedding memory configuration, MCP, relay and Worker configuration; live optional embedding/selector changes retain their distinct application path.

One shared private operation-identity builder now captures the authenticated request scope and original lifetime before durable preparation. Native/agent actions retain their actual parent native session; owner patch/full-write identities use only their exact authenticated frame UUID and an original bounded local deadline. That logical scope never becomes NativeUi authority. A protected patch submitted through raw owner authority records HostActionRequired rather than minting a native confirmation session. Exact retained replay occurs before a new identity/deadline is created.

Known-resolved reconciliation also retries the same exact operation's resource release without rereading/reapplying the file or rewriting its receipt. Claim identity/native request and active-write session must still match before cleanup, and another active operation is untouched. Persistent poisoned locks can require Host restart; an exact retry is not a promise that all ownership failures can be repaired in place.

OwnerSettingsWriteResult is data, not an authorization proof. Its optional full settings snapshot is included only when the currently validated private file and repository cache match the original known-applied post fingerprint and revision. Later settings never substitute for an old result. If no current snapshot can be verified, the original receipt is retained with settings absent; an unavailable read also emits a value-free diagnostic. Its restart flag is asserted only for a known-applied original file receipt, never an unadmitted, no-effect or unresolved proposal. This helper neither reconstructs a historical private snapshot nor enrolls credentials, and the actual replace_as_owner entry point remains pending.
