# Physical relay connection identity

Each successful `RelayConnection::connect` creates one opaque `Arc<RelaySocketIdentity>` after socket authentication succeeds. It has a private constructor, a monotonic closed atomic and the actual relay cancellation token. Its current liveness requires both an unset closed flag and an uncancelled token. There is no serialized identity, caller-supplied label, reset or replacement constructor.

The crate-private `capture_socket_identity` checks the connection's actual authenticated local device, cancellation, present socket and current liveness before returning that same Arc. `HostSettingsTransportOwner::connected_relay` now captures this actual identity instead of ignoring its connection argument. The existing `SettingsConnectionIdentity` retains it, and its liveness additionally requires that physical identity alongside the unchanged Host, retirement and cancellation checks. No independent epoch label can substitute for this capture.

Actual generic send/receive failure closes the identity in the same synchronous tail that clears the socket. `close` closes it before taking the actual socket and awaiting its existing bounded close; dropping the actual connection also closes it before field destruction. Early Send validation errors retain their old behavior and leave the socket/identity unchanged. Closure is conservative: it proves no successful network close, task join, frame destruction or completed drain. Cancellation also immediately fences liveness without claiming cleanup.

The existing generic message encoding, socket send/receive, error mapping, cancellation and timeouts remain unchanged. This increment supplies no preencoded private send, queued-owner lender, final SQL job/guard handoff or first-poll gate. A later concrete private sender must compare the genuine queued connection's same physical identity with its actual live socket, perform the current lifetime check under the uninterrupted real Host guard immediately before first socket poll, then release that guard before network waiting. No private activation, new runtime/channel or permission follows from an identity Arc. Source review and formatting are separate from compilation, encrypted runtime and security verification.
