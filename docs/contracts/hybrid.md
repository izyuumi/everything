# Hybrid retrieval contract

`memory::search::lexical_search(index, query, limit, cancellation)` returns actual FTS results without opening a vector database or invoking inference. `SearchResponse` has ranked `RetrievalHit` values and `RetrievalSummary { mode, fallback, diagnostic }`. Each hit retains chunk ID, title, heading, excerpt and one-based inclusive provenance, plus separate optional BM25 score, vector distance and RRF fusion score. FTS-only scores contribute one rank term to fusion. The original `Wiki::search` API and its BM25 semantics are unchanged.

`RetrievalMode` is `lexical` or `hybrid`. Fallback reasons are `disabled`, `missing_generation`, `incompatible_profile`, `stale_source`, and `semantic_failure`. Diagnostics are bounded local descriptions, not model answers. Cancellation is an error. Lexical/source failures are not converted to an empty successful response.

Lexical result pages have a 16 MiB aggregate byte ceiling covering IDs, original titles/headings/snippets and provenance. SQLite type/byte-length checks precede string copies; malformed field types fail explicitly. Overflow returns `WikiError::Limit` without a partial successful result. A caller may request fewer rows. Existing titles and BM25 ranking are not truncated or changed by this admission bound.

## Bounded index reads

`WikiIndex::source_fingerprint()` hashes namespace `everything.wiki-source.v2` plus NUL, parser/chunker namespace `pulldown-cmark-0.13.4.heading-chunks-v1` plus NUL, and the persisted chunking-profile string (or `unprofiled`). It then streams sorted `(path, indexed SHA-256 content hash)` pairs, followed by the page count, then sorted `(chunk ID, UTF-8 body byte count, start line, end line)` records and the chunk count. Strings have unsigned 64-bit little-endian lengths; numeric fields/counts are unsigned 64-bit little-endian. One read transaction binds the full set. Page hashes bind original Markdown; actual chunk metadata binds its deterministic segmentation. This describes the indexed snapshot and does not itself read canonical files.

Lexical schema 2 adds `wiki_settings`. Version-one indexes migrate without modifying canonical files. `Wiki::synchronize` binds the parser revision and all configured `WikiLimits` in its persisted chunking profile. A changed or absent profile transactionally invalidates derived pages/FTS before a canonical rescan, so unchanged source hashes cannot retain old chunk sizes. Direct `WikiIndex::open` migrates schema without guessing a caller's chunking settings. Parser or source-transform changes must update the explicit namespace/schema revision.

`chunks_after(after_id, limit, max_bytes)` accepts an exclusive lowercase SHA-256 chunk-ID cursor, 1–256 rows, and 1 KiB–16 MiB. `ChunkPage` returns `IndexedChunk { chunk, title, page_hash }` records and `next_after_id`. A present cursor is the last returned ID and means more rows remain; an absent cursor means exhaustion. When another row would exceed the byte budget, the page stops before materializing that row and returns the last successful cursor. If even the first row cannot fit, it returns an explicit individual-row limit error; callers may increase their bound or report unsupported source size. Metadata/string size is checked before copying row fields.

`chunks_by_ids(ids, max_bytes)` accepts at most 256 valid IDs, removes repeats, preserves first-request ordering, omits missing IDs and enforces the same aggregate byte ceiling. It returns no partial result on overflow. The raw connection and statement lifetimes remain private.

## Semantic construction

With `local-embeddings`, `VectorIndex::open(path, VectorLimits)` opens a private derived database at an existing parent path, validates its identity and initializes statically linked sqlite-vec only on that connection. Default limits are 50,000 vectors and 512 MiB of main-database pages, bounded to 100,000 and 2 GiB. Initialization does not enable SQL extension loading or affect unrelated SQLite connections. Little-endian hosts are required for initial native float persistence.

`HybridSearch::new(index, Arc<dyn Embedder>)` captures a stable `EmbeddingIndexSpec`. `specification()` returns that immutable specification. The document schema is `wiki-heading-chunks-v1;title=page-title;body=full-chunk;unicode=preserve;overflow=reject;blank=skip;source=profiled-manifest-v2`. Profile dimensions must be 128/256/512/768, normalization unit L2, and metric cosine. Other model implementations are not shipped by this integration.

`search(&mut Wiki, query, limit, cancellation)` synchronizes the same owned wiki and returns at most 100 results. It uses at most 100 candidates from each rank source. A compatible complete generation is required before query inference. RRF is the sum of `1/(60+rank)` for each list in which an ID appears; ranks start at one. Ties use chunk-ID ordering. Returned links and Markdown remain untrusted source content.

## Build and restart

`rebuild(&mut Wiki, BuildBudget, fresh, cancellation)` synchronizes canonical files, prepares/resumes a generation, embeds or reuses actual full chunk inputs, commits bounded progress, resynchronizes source, and atomically activates only a complete matching generation. `fresh: true` deliberately replaces incomplete work; use `false` on subsequent calls to resume. A matching active generation returns complete without inference unless a fresh build was requested.

`BuildBudget { max_chunks, max_elapsed }` defaults to 64 chunks and 30 seconds. Chunks require 1–1024; elapsed requires positive through 300 seconds. `BuildReport { generation, stop }` reports `complete`, `chunk_budget`, or `time_budget`. Cancellation is an error preserving the durable cursor, while native inference cleanup finishes before return. Backend input limits fail the build; they do not silently truncate or activate partial coverage. Blank source chunks are explicitly skipped and counted.

`GenerationStatus` contains internal generation ID, validated specification, source fingerprint, ready state, last committed chunk ID and vector/inference/reuse/blank counts. `VectorStatus` exposes optional active/building records and last build diagnostic. An interrupted build resumes only against the identical source and specification. Incompatible dimensions/revisions/preprocessing never share a physical vector table or copied vector. Input hashes cover namespace `everything.wiki-vector-input.v1` plus NUL, then length-prefixed index fingerprint, full text and title bytes, using unsigned 64-bit little-endian lengths. The index schema distinguishes absent/blank title behavior through the existing preprocessing specification.

The private vector schema owns `vector_generations`, `vector_state` and `vector_inputs`, plus one internally named `vec0` table per retained generation. The active pointer and readiness update share a transaction; each inserted vector, input hash and cursor update also share a transaction. A complete source scan omits deleted chunks. One active and one shadow/retired table are retained; starting later work drops older nonactive generations. The vector database is derived data, not a canonical memory or backup source.

## Consolidation adapter

`Consolidator::retrieve(question, max_results, cancellation)` directly returns actual `SearchResponse` evidence using the same wiki owner and bounded blocking admission. It accepts a nonempty question up to 4,096 UTF-8 bytes and 64 whitespace-separated terms, and 1–100 results. It does not enqueue a maintenance job or call an answer-model provider. It uses attached hybrid retrieval, default FTS, or the configured initialization-failure provenance. Cancellation interrupts admission; once admitted, the worker retains its permit through native cleanup. Dropping the caller signals its child token without releasing running worker ownership.

Feature-enabled `Consolidator::set_hybrid_search(Option<HybridSearch>)` attaches or disables semantic query retrieval through the existing single-owner admission. `rebuild_semantic(budget, fresh, cancellation)` runs that service against the actual owned wiki on its blocking worker. `semantic_status()` returns optional durable status. `set_hybrid_search_result(Result<HybridSearch, VectorError>)` accepts the actual host construction outcome: successful construction attaches the service; failure retains FTS with a static, sanitized `semantic_failure` diagnostic. Cancellation propagates and preserves the existing configuration. The explicit `None` setter clears unavailable provenance and reports disabled queries. No private native-error strings, model paths or credentials are copied into initialization-failure summaries. No public `ConsolidationConfig` field changes and no automatic model construction occur.

New query outputs include optional `retrieval: RetrievalSummary`, decoded with a serde default so previously saved jobs remain readable. Cited excerpts still come from actual canonical pages and carry content hashes, line ranges and real model-answer origins independently from retrieval mode. Ingest candidate selection and lint keep their existing behavior. Hosts should serialize setup and surface construction failures rather than pretend semantic retrieval was attached.

The single owner excludes competing internal writes, but source files, lexical SQLite and vector SQLite do not share a transaction. An external writer can race a completed synchronization. Hosts must coordinate edits; no source fingerprint authenticates content or prevents hostile same-UID replacement. Static and disposable runtime verification do not replace deferred automated coverage in [#32](https://github.com/izyuumi/everything/issues/32).
