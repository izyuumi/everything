# Joined Read reply currentness

The internal Read currentness gate takes only the genuine
[true-joined Fresh owner](settings-read-receipts.md). Known and Duplicate cannot
construct that owner, allocate a new response or renew a slot. The original
receive guard is retired when execute finishes; this gate never calls the
intake guard-active check or substitutes a skip flag. It creates no Source,
caller, permission token, parent or values from labels, rows or public DTOs.

Authority observes the existing same512-global/64-full-peer closed query map
through the actual owner. It checks the original registered Host, live physical
connection, exact full peer/current parent/generation, cancellation and immutable
query intent. Fresh owner and query have the same original first floor. Trusted
wall/Instant samples must not regress below first floors or either observed
highwater, and must stay within original Source/query and parent deadlines.
Observation updates only the existing highwaters; it never registers, evicts,
refunds, restamps or renews a query. Prejoin and Access methods remain unchanged.

The Core qualifier borrows that owner, its exact embedded receipt capability,
the actual Host OwnedMutexGuard and the actual supplied Main Transaction. It
checks shared Store health, same Core Agent/lease/Main/endpoint/mutation and
attached Host, actual guard mutex identity and physical connection liveness.
Complete current Host endpoint keys/role/nonrevocation and the full genuine
peer registration/access/nonrevocation are checked before current grant SQL.
The grant must be Active for that full peer and exact parent generation.
Snapshot requires every requested key in current R before any later value
capture; W is irrelevant. Inspect retains only a private read ceiling, with no
Original existence, requesting-peer provenance or disclosure permission.

The actual slot must retain every original reservation field: ID/local/peer,
canonical public provenance, family/bytes and creation/expiry. Text is borrowed
and bounded before comparison. Canonical provenance includes the actual full
peer, Host/connection epochs, current exact grant and parentSome. Snapshot uses
Default49152 and InspectOriginal uses Inspection90112. No denial family or
provenance rewrite is allowed. The row is metadata, never authority.

Creation stays the original admission observation and must fit both first
floors and original request/grant window. Exact expiry is the original clipping
of request/parent/grant; monotonic expiry derives from the original query and
Source floors with that same clip, capped by original parent lifetime. No
now-plus-remaining, replacement reservation or current-time restamp is used.
After all pin/grant/reservation SQL a final actual Authority observation checks
same query/owner/floors/deadlines/parent lifetime and nonregressing same-call
clocks, including current slot/grant expiry. The qualifier retains those private
facts, original invocation and the actual Transaction borrow. Recheck requires
that exact capability, Transaction, owner/invocation and Host guard, repeating
current checks without registering or revealing grant/read values.

These helpers borrow an actual Main supplied by the later sole publisher; they
never reacquire Store Main or manufacture arbitrary-transaction-origin proof
from pointer equality. All underlying authority, SQL/health, clock, pin and
provenance serde causes remain typed under fixed redacted descriptions. Lost
scope, revoked grant, expired original slot/parent or retired connection fails;
it cannot create a denial, new slot, retry, ACK or no-effects result. The helpers
perform no SQL write, rollback or commit and do not reinterpret writer uncertainty.

The full gate requires its reservation to exist. It cannot be used after exact
DELETE/transfer or for queued send; those phases need their genuine consumed and
queued associations. Counted Snapshot capture, permanent Original lookup and
all disclosed-key checks, Read BUILD eligibility/permit, projection/seal/send,
lender/retirement, Root pump and client adoption remain separate source gates.
No native settings snapshot or OwnerIPC forwarding is added. Source formatting
and preservation prove no compiler, SQL/crypto/runtime, security acceptance or
#116/#117 completion; automated validation remains deferred in #32.
