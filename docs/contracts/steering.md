# Durable native task inputs

Agent::accept_task_input is a trusted host delivery primitive. It accepts TaskInputCommand containing the exact conversation, task, active user command, unique delivery command, authoritative host acceptance time, and typed input. The scheduler must verify current task ownership, cancellation, descendant relationships and immutable child terminal records before constructing these commands. A remote caller cannot supply a successful child result or an outcome_unknown decision directly.

TaskInput is Steering, WaitForChildren, or ChildFinished. Steering instructions require nonempty UTF-8 of at most 32768 bytes without NUL. A wait contains 1 to 32 distinct child task IDs. ChildFinished references the exact wait command, a terminal child status, a bounded 8192-byte output preview, and an explicit unknown-outcome flag. That flag preserves uncertainty rather than converting a failed child into an ordinary successful completion.

Acceptance appends SteeringReceived, TaskWaitRequested or SubagentFinished and the private input queue in one sequence/revision-CAS transaction. Event causation is the delivery command; the payload command_id is the original active command. TaskInputReceipt returns the original event sequence. Exact replay returns that same sequence even after consumption or task completion; a changed target, payload or acceptance time conflicts. A fresh delivery to a completed command or terminal task is rejected.

The private queue lives in the existing conversation checkpoint, outside the immutable native definition. It holds at most 64 deliveries and 512 KiB in aggregate. It validates ordering, journal identity, target, payload and cursor bounds. Consumed identities remain in the immutable public command journal; the checkpoint stores a monotonic consumed event cursor rather than an unbounded list of IDs. The existing public 256-KiB and private 8-MiB limits also apply.

Only the native kernel consumes inputs. It appends steering and known child-result User messages with the delivery causation and advances the consumed cursor atomically. Child text is explicitly structured as untrusted output; it does not replace fixed constraints, task objective, authority, model configuration, memory or tool setup. Original command identity, limits, counters, deadline, continuation and native tool-call mappings remain intact. Inputs cannot split a tool-call/result round. WaitingForEvents yields only after all ordered known results have committed. A child with an unknown outcome pauses at ChildOutcomeUnknown for owner reconciliation and never authorizes another provider attempt automatically.

One short per-conversation write gate serializes input acceptance and native commits across Agent clones, independently from the full-turn execution gate. A cached kernel snapshot may merge only appended, validated input deliveries and their corresponding non-message acceptance events. Raw messages, native phase, continuation and every other checkpoint field must still match; any other concurrent mutation fails. If input arrives during context preparation, the kernel rebuilds before charging or sending a new model request. If acceptance wins the final-response commit race, the assistant response commits while retaining the active turn and counters for the queued inputs. If finalization wins, subsequent fresh delivery is rejected. A paid or uncertain request is never repeated to resolve a checkpoint conflict.

A child input may be accepted after safe consumption computed WaitingForEvents but before that pause commits. The accepted delivery remains in the durable queue. The scheduler must recheck pending input when settling that exact safe wait, or retain an active-worker wake hint, and requeue it without requiring another external event. Subscribe-before-query notifications and startup repair complement this durable check. Provider uncertainty and ChildOutcomeUnknown must never use that automatic path.

Steering acceptance does not grant retry permission. ProviderInFlight, interrupted execution, unknown effects, reconciliation and exhausted budgets retain their original owner-action requirements. Cancellation continues to signal native provider and broker futures and preserves queued input for inspection; it does not manufacture a completed result or erase an uncertain turn. Legacy text-only execution cannot consume task inputs and rejects a queued input before inference.

The Agent primitive is implemented independently of Scheduler and HostInbox. Scheduler wait-set ownership, child terminal delivery repair, authenticated command admission and approval wake handoff are documented at their composition boundary once integrated. Automated acceptance coverage is deferred to #32. Successful live model continuation remains unverified without authorized credentials.
