# macOS Settings assistant composition

The existing app-owned `HostModel` constructs one `SettingsAssistantController` with its original `NativeSettingsStore`. Both use the original owner client and applied connection. The native Settings scene places `SettingsAssistantView` in a collapsible macOS inspector alongside conventional controls. Expansion alone creates no session or inference. The consumer contract is [Ask Settings](apple-settings-assistant-ui.md); the underlying sealed admissions remain in the [native assistant contract](apple-native-settings-assistant-session.md).

The inspector binding calls synchronous expansion hooks. The Settings window observer supplies its weak actual window, application activity, physical visibility and covering-sheet state. Hide, miniaturization, application resignation, genuine window replacement and close retire the original child. A still-present window covered by its own attached sheet remains a parent surface: covering clears private cells and pauses publication instead of closing the child waiting for that native ceremony. Actual foreground, occlusion and sheet predicates are checked again by the controller before private presentation. General service confirmations and the native path picker also invalidate private presentation before being shown.

`NativeSettingsStore.beforeRetire` is a local presentation callback installed with a weak controller capture. Its three public parent-retirement paths call it synchronously before close, connection replacement or permanent invalidation changes owner state. This covers conventional Close session buttons without depending on delayed SwiftUI observation. It does not authorize any effect, change native receipts or let the controller stop the Host. Actual owner/read/cleanup observations additionally reconcile the sealed original child.

`SettingsAssistantNavigation` owns the native tab selection and at most one pending section presentation. Its input is the closed `SettingsSection` enum, reached only through the sealed native OpenSection bridge. General, Models, Memory, Tool Selection, Notifications and Devices map to their actual existing tabs. Owner Security has no destination and returns dismissed. No URL, model text, action label or public UUID can select an executable route.

Selection intent does not finish the action. A pending route returns opened only when its exact selected destination has actually reported appearance and the original attached window is visible, active, unminiaturized and uncovered. An already appeared matching destination can acknowledge immediately under those same predicates. Selecting another tab, covering or retiring the surface, or retiring the original controller settles its pending continuation as dismissed. The controller checks its original context and sealed Store owner again at the actual callback invocation, before registering a route. There is no automatic navigation retry, second pending queue or fabricated success for an unsupported section.

Connection replacement retires the original controller context before its future connection key changes. Closing the inspector affects its child and private display, leaving conventional controls and the headless Host independent. App shutdown invalidates fresh intake, joins the original controller callbacks and joins existing Store/lifecycle/native-presenter drains before shutting down the same shared owner client. An unconfirmed child close remains unconfirmed even when parent cleanup completes.

The four new Swift leaves are registered only in `EverythingMac`. Existing iOS membership, Host/provider ownership, native action whitelist, shared admission limits and protected confirmation paths remain unchanged. No private transcript persistence, new runtime, provider fallback, automated tests or source comments are introduced.

Source, project registration and supported SDK build/static analysis are separate from actual UI acceptance. Real inspector layout/accessibility, navigation callbacks, sheet occlusion, permission/credential/pairing interactions, provider responses, connection switching and shutdown races have not been observed on macOS by this increment. No successful inference, security acceptance or issue #115 completion is implied; deferred automated verification remains [#32](https://github.com/izyuumi/everything/issues/32).
