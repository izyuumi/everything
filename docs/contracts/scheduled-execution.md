# Scheduled execution policies

Issue #52 extends the existing ScheduleEngine and Store with serial attempts, cumulative budgets, explicit uncertainty acknowledgement and terminal notification delivery. It uses the one native Scheduler and global Tool Broker. Schema 9 follows actual schema 8 and preserves every existing first-attempt identity and serialized policy. The source and disposable local walkthrough are implemented on the issue branch; integration review remains pending. This document does not assert a main merge, CI success or successful inference.

## Attempts and retry

The immutable occurrence owns at most its captured 1–8 attempts. Attempt 1 retains the original reserved TaskId. Each later attempt reserves fresh isolated conversation, creation/input commands and native task before Agent admission, with the original occurrence deadline. Definition generation, endpoint, instructions and authority never follow mutable host defaults. The original captured allowlist is reused and all actual SCHEDULER_TOOL_NAMES remain excluded. A new never-paid attempt may capture fresh local preparation; active resumes reuse their exact native Definition. An approved classifier result is not copied or automatically approved for a different task.

A durable admission marker distinguishes an unadmitted reservation from a previously admitted missing native task. Schema-8 running occurrences seed that marker. Missing admitted tasks become Unknown; replacement work is forbidden. Exact native enqueue reuses identities and policy. Attempt results are immutable, including settlement time, charged usage, typed disposition, bounded diagnostic, outcome digest and optional next-retry instant. Terminal settlement updates the final run outcome and notification readiness in the same transaction. Run history and its original immutable snapshot remain authoritative.

Automatic retries are restricted to the actual trusted Scheduler retirement proof for ProviderUnavailable. The engine reserves the retirement request identity first. The actor proves an unused factory boundary, atomically retires the exact native task and records its audit; its exact request replay repairs a crash before ledger settlement. A generic Failed status, diagnostic text, native request, interrupted tool, provider uncertainty, child uncertainty or broker reconciliation never authorizes retry. Before recording any completed, failed or cancelled native result, the engine independently checks the validated saved native phase, typed waiting state and any immutable Running/Unknown tool journal for that exact task. Any uncertainty yields Unknown regardless of terminal status. Cleanup acknowledgement or zero unresolved cleanup count does not change this classification. A cancellation is not converted into a factory failure. The existing native paid-retry owner API is not used.

Each proven factory failure consumes an execution-attempt ordinal and zero paid/native model, output or tool allowance. Queue-capacity replay consumes no additional ordinal. Checked exponential backoff uses the captured initial/capped values and is persisted with settlement. No next attempt is reserved until its predecessor is settled, eligible, before the original deadline and within all ceilings. The final permitted failure settles the occurrence; no occurrence UUID or generation is invented for retry.

## Budgets and time

Native requests reserve their full configured output maximum before ProviderInFlight. New scheduled policies set max_reserved_output_tokens to the remaining captured output ceiling and keep the captured model-request ceiling; a request that cannot fit stops without shrinking its output maximum. Reservations survive failures, uncertainty and restart. Completed-attempt accounting is summed before a successor is reserved. Output reservations are distinct from reported output. Model requests, tools and reserved output cannot exceed the original occurrence capture across attempts.

Historical schema-8 policies with no exact output ceiling retain their original conservative request bound and are never rewritten. Missing historical output accounting conservatively consumes that attempt's unprovable allowance. cumulative_usage includes conservative allowance for unsettled or unaccounted attempts and sets known=false; it does not claim those allowances are observed paid usage. Settled validated native counters replace that accounting uncertainty only with actual evidence. known=true describes recorded accounting, never certainty about external effects or permission to retry or release overlap. Factory proof is the only automatic zero-effect retry boundary.

The absolute deadline is original actual claim time plus captured timeout. Queue, provider construction, approval, offline and backoff waiting all spend that time. New attempts never reset it. Recording timestamps may clamp for ordering, but admission and retry eligibility use actual realtime. Native fixed monotonic caps and persisted maximum observed wall samples remain in force. Detection is relative to recorded samples; unseen clock movement during downtime is not established. Retained optional result publication may wait beyond execution completion without starting work.

## Unknown acknowledgement

terminal_outcome_digest returns a canonical SHA-256 digest over the ASCII bytes everything.scheduling.outcome.v1 followed by one NUL byte, the occurrence's 16 UUID bytes in network order and its bounded UTF-8 typed RunOutcome JSON. The JSON has no whitespace; the kind field comes first, followed by that variant's fields in the Rust contract declaration order, using serde_json string and integer encoding. The returned digest is 64 lowercase hexadecimal characters. Changing that encoding requires a new digest domain version. acknowledge_unknown_as_owner accepts the exact occurrence, stable command, digest, note and acceptance time. It derives the process's real effective UID for the operator audit. Only an authenticated trusted owner route may expose this API; model tools and paired execution controls must not expose it.

Exact replay compares the complete acknowledgement before live-state checks. Changed reuse conflicts. A new acknowledgement requires that exact terminal Unknown and digest. It appends an immutable bounded record; it never rewrites the outcome, clears native uncertainty, grants a retry, resurrects a task or proves an external effect stopped. Overlap queries exclude only explicitly acknowledged Unknown outcomes. Global broker quarantine and native owner-action requirements remain independent. Owner management composition belongs to #53.

## Delivery

Captured conversation delivery reserves immutable destination, command and event IDs in the claim transaction before effects. Legacy unfinished rows reserve before further admission. Terminal outcomes and ready notification bodies commit together; legacy terminal rows can be backfilled without changing their outcomes. The full bounded notification is checked against the immutable run capture before publication. Task references describe only the latest reserved attempt when its matching native task exists; a missing or never-admitted latest task yields paired None references, never an older attempt.

The engine polls at most once per second, uses bounded pages and a rotating cursor, and invokes the actual Agent publish_scheduled_result primitive. Busy destinations retain their intent. Missing destinations expose a delivery error with no alternate destination. A failed legacy backfill does not prevent existing ready deliveries from draining and freeing slots. EngineStatus.delivery_preparation_error retains its bounded diagnostic until actual backfill progress; delivery_error separately reports publication and receipt errors. Cancellation still stops admission. Publication creates no model message, pending turn or task. After append, acknowledgement checks the complete durable Agent command journal and original event sequence before releasing the pending reservation. A crash between append and acknowledgement replays the same full request. Delivered payload storage is released; immutable IDs, digest and sequence receipts remain.
