## Closed Update data

The private command decoder accepts only an actual-object schema_version1 wrapper with payload kind=settings,version1,host_id and message kind=command. That message has exactly parent,request_id,time,body. Parent has parent_id and complete generation{grant_id,grant_revision,host_epoch,connection_epoch}. Body kind=update has positive expected_settings_revision, optional enabled and optional dimensions. At least one preference must be present. Explicit null for an optional field means absent; backend_default is the distinct explicit dimension reset.

Dimensions reuses the existing RemoteDimensionSelection only: backend_default or selected{dimensions}. Static selected range is1..65536. Actual successful cached profile choices, current grant/readable+writable keys, revision and authoritative service CAS remain later Core checks, not decoder claims. There are no generic keys, provider/model selection, native confirmation, credentials, devices, chat data or arbitrary JSON values in this intent.

Every accepted nested object is map-only and closed. Canonical nonzero lowercase UUIDs, positive signed-SQLite-range revisions, checked UnixMillis conversions, duplicate/unknown fields and trailing input are validated through actual serde types/visitors. Original inner interval is positive, at most30000 milliseconds. The decoder applies the complete32768-byte bound before full decoding and returns data-only Update/Unavailable/Invalid. Known unsupported chat body kinds produce Unavailable; no speculative ChatOpen/Send source variants exist. Only the actual owned callback may connect a decoded Update to verified ownership; pure data alone is not transport acceptance.
