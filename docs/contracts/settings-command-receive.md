# DirectUpdate source foundation

This is held, unactivated Unix source for #116. It defines closed DirectUpdate data and opaque verified ownership; it does not accept a command, write a command receipt, create a paired caller or execute a setting change. The existing public and relay private lanes retain their fixed rejection. Read [Bind receipt](settings-bind-receive.md), [paired Authority](paired-settings-authority.md) and [paired operation metadata](paired-settings-operations.md) for the implemented adjacent boundaries.

## Closed Update data

The private command decoder accepts only an actual-object schema_version1 wrapper with payload kind=settings,version1,host_id and message kind=command. That message has exactly parent,request_id,time,body. Parent has parent_id and complete generation{grant_id,grant_revision,host_epoch,connection_epoch}. Body kind=update has positive expected_settings_revision, optional enabled and optional dimensions. At least one preference must be present. Explicit null for an optional field means absent; backend_default is the distinct explicit dimension reset.

Dimensions reuses the existing RemoteDimensionSelection only: backend_default or selected{dimensions}. Static selected range is1..65536. Actual successful cached profile choices, current grant/readable+writable keys, revision and authoritative service CAS remain later Core checks, not decoder claims. There are no generic keys, provider/model selection, native confirmation, credentials, devices, chat data or arbitrary JSON values in this intent.

Every accepted nested object is map-only and closed. Canonical nonzero lowercase UUIDs, positive signed-SQLite-range revisions, checked UnixMillis conversions, duplicate/unknown fields and trailing input are validated through actual serde types/visitors. Original inner interval is positive, at most30000 milliseconds. The decoder applies the complete32768-byte bound before full decoding and returns data-only Update/Unavailable/Invalid. Known unsupported chat body kinds produce Unavailable; no speculative ChatOpen/Send source variants exist. This pure decoder is not connected to the active ReplayGuard and is not transport acceptance.

## Opaque verified association

A private VerifiedSettingsEnvelope factors the actual existing Bind association: original Agent/StateLease/Main/endpoint/mutation context, exact lean connection, complete verified public registration, envelope receipt metadata, original wall/monotonic pair and actual held-guard witness. It contains no Core, parent, caller, queue or HostInner. Bind retains its separate immutable intent/history and original public accessors. The same actual crypto-callback record checks and field captures construct its common envelope; no byte/UUID/boolean/SQL-row factory is exposed.

AuthenticatedSettingsCommandSource privately owns that association, immutable SettingsCommandIntent and one per-input Arc identity. CommandIntent contains host_id,parent,request_id,issued_at,expires_at and SettingsUpdateIntent. UpdateIntent contains only expected_settings_revision/enabled/dimensions. These data structures and copied metadata are not authority. Source and OwnedVerifiedSettingsCommand are neither Clone nor serde values; their Debug is fixed redacted. The unique Arc distinguishes the actual invocation, independently of request UUID, but is not sufficient authority by itself.

The parent-private from_verified_update constructor consumes the sealed common envelope, decoded intent and actual counted PrivateWitness. Source/context/data drop before its final witness. Its intended callsite is the original registered authenticated receive callback after actual AEAD/routing/size validation. This stage deliberately has no callsite or artificial instance: the genuine command branch must wait for the real same-Core receipt gate. A pure decoder cannot construct Source.

Source exposes only actual context matching, connection/public peer keys, immutable intent, invocation identity, fixed receipt metadata/public pin and checked precommit observation. `pinned_identity` is the verified public registration JSON only, never a private packet/settings body. The observation checks original held guard, actual Main/endpoint/Host role, live Host/connection, exact epochs and immutable original interval. Outer duration stays positive and<=30000, outer expiry<=inner, actual wall does not precede the original floor and both original monotonic deadlines remain fixed. The checker takes no caller-supplied current time, liveness or proof; decoded RequestTime is only an admission bound. There is no known-Bind expiry override.

## Remaining real producers

Core must first import the reviewed actual command definitions and implement its SAME SettingsService receipt authority. That concrete capability is held on the actual Root run stack/registered worker, never inside Source/context/endpoint/lean identities/ledger/parent map. Within the actual Main Immediate it must verify actual context/attachment, complete current pin/Active grant and exact still-live Authority parent, then qualify only the two-memory-preference Update. The same qualification is rechecked before commit without changing original admission time or target. No await or nested Store acquisition occurs under Main.

Only a subsequent genuine producer may atomically commit the metadata-only marker, accepted Original and required reply reservation inside the real AEAD ReplayGuard before returning true/open success. Only the original actual blocking-job join may transfer the committed owner. This source defines no guessed committed request/result, callback bridge, paired caller, publication permit, Original insert or accepted branch. Actual service/file admission and filtered result remain separate current checks.

Send child/provider proof, ChatOpen, queries, known-Bind exception, reducing Close, private projection/build/seal/SQL transfer/send and full Host activation remain separate real gates. A reducing known Close must not acquire new command/query/output capacity or mandatory reply quota; this stage supplies no fake close producer. No new queue, harness adapter, cryptography, dependency or compatibility layer is introduced.

Validation here is direct Rust1.88 formatting/parsing, diff/static factoring/source preservation and documentation links only. No Cargo/compiler/typecheck, database/SQL engine, crypto/runtime/provider or Apple verification was performed. Held declarations require genuine consumers and strict exact-head CI before publication; no lint suppression or fake use is added. No source comments or new tests/fixtures/mocks were created.
