# Attributed remote task reports

`ConversationEvent::RemoteTaskFinished` carries a bounded `RemoteTaskReport` in the existing public event stream. It is attributed external output, with original local task/command, delegation/attempt, manifest SHA, executor identity/fingerprint, exact inbound message/envelope/packet digests, source kind and outcome. It is neither a user instruction nor an assistant/model message. Guarded Worker verification, atomic Agent/Scheduler settlement and Host orchestration are implemented in source; their distinct [bridge](worker-bridge.md), [result admission](remote-result-admission.md) and [Host validation](../development/worker.md) contracts retain the evidence limits.

The neutral protocol module imports no Worker or Scheduler types. `RemoteTaskUsage` preserves informational worker counters and optional reserved-output accounting; these values never refund or widen the once-charged native reservation. Actual Result sources carry their canonical result digest and reported finish time. Rejected sources carry their own reason with no fabricated result digest/finish time, zero usage and no artifacts. Local `accepted_at` records the host commit time; it is separate from the worker's clock.

Reports validate non-nil delegation/attempt IDs, exact 64-character lowercase digests and the existing native eight-group fingerprint form, at most8192 summary bytes without NUL, at most64 artifacts and at most64KiB serialized bytes. Positive artifact count requires a quarantine digest. When present it equals the exact Result source digest, matching the actual quarantine receipt’s result fingerprint; it does not authenticate or prove file contents by itself. Unknown and Rejected carry no artifacts/quarantine digest. Unknown retains its outcome and reservation; its acceptance cannot prove remote effects stopped. Rejected is distinct from execution failure. Summary text remains untrusted display content and grants no capabilities. Artifact names, contents and local filesystem paths are absent from this public report.

`RemoteTaskReport` is a public data structure, not an authentication capability. Deserialization validates shape and bounds only. A real result consumer must authenticate the retained inbound encrypted envelope against the original purpose pin, compare the exact immutable source packet/manifest and same-Store binding, quarantine actual approved artifacts, and retain endpoint/host/native authority through atomic persistence. Neither this DTO nor caller-supplied JSON, a local quarantine flag, cancellation acknowledgement, deadline or disconnect authorizes settlement.

The actual `append_with_external_task` primitive updates the dedicated conversation and its exact Scheduler row in one transaction, leaves original task input and conservative charges immutable, rejects any local tool row and preserves exact receipt replay. Its storage API supplies no source authentication; the real bridge/Actor/Agent capabilities retain that authority through commit. General native state transitions and model commit paths remain unchanged. The combined `d273c52` normal-package Rust 1.88 gates passed; the actual Host credential-rejection/result-acceptance walkthrough also passed, while protocol validation alone proves no runtime guarantees. Exact provenance is in [worker validation](../development/worker.md#combined-host-validation-checkpoint). Automated verification remains deferred to #32.
