# Inactive iOS presentation cover

The iOS app applies the same `InactivePrivacyCover` to its four app-owned presentation roots: main Root content, the pairing NavigationStack, the nested QR scanner sheet and the steering NavigationStack. The add-conversation sheet was removed when New conversation became one tap. The module-internal modifier lives in the existing `VorraIOSApp.swift`; no project membership or presentation owner is added.

Each root reads its enclosing Scene's `scenePhase`, marks its content `privacySensitive()` and places the existing opaque background Rectangle with the Vorra lock label above that content whenever the phase is not active. The main root's previous visual treatment is unchanged. Separate sheets explicitly apply the modifier because an overlay on their presenting content does not cover their own root. Future app-owned presentation roots must also apply it.

The modifier only renders a view. The existing scene and UIKit callbacks, platform-eligibility latch, local-settings foreground generations, pairing and scanner callbacks, steering actions and owned OS work remain separate and unchanged. It does not clear private values, cancel or authorize an action, create a window, observe application notifications or start a Task. Local preference and notification ownership remain defined by [local device controls](apple-local-device-controls.md) and [committed-event notification delivery](ios-notification-delivery.md).

Native alerts, confirmation dialogs, camera and notification permission dialogs, and System Settings are system-owned presentations. This cover does not install content in their windows or establish their snapshot behavior. Scene-phase rendering is not a screenshot-prevention, first-frame, immediate callback-order or app-switcher snapshot guarantee. No app-switcher disclosure was observed during this source change.

Source validation covers all actual Swift grammar, the five opt-in roots, unchanged action and lifecycle source, documentation links and formatting. It does not typecheck SwiftUI or prove rendered behavior. Independent source review and fresh supported macOS/iOS SDK build and analysis are required before integration. Actual inactive/resume rendering with each sheet, camera presentation and app-switcher behavior still need separately authorized Apple-device verification. This change does not implement accepted remote Settings or complete issues #28/#117; [deferred automated verification](../../AGENTS.md) remains tracked in #32.
