# MCP client contract

`McpHost::new(max_servers)` admits 1–16 explicitly trusted Unix stdio processes. `connect(config, cancellation)` prepares an executable and working directory, starts the child, performs the native MCP handshake, discovers a bounded catalog, and returns `McpSession`. The host must own the trust decision before this call. Credentials or models cannot choose a server through tool arguments.

`McpStdioConfig::new(server_id, executable, working_directory)` requires a 1–20 character ASCII server ID using letters, digits, `_` or `-`, and absolute UTF-8 paths of at most 4096 bytes. Paths are resolved before launch; the executable must be a file and the working directory a directory. This validates configuration shape rather than sandboxing or authenticating the program. `with_arguments` accepts at most 64 values and 32 KiB in total; values cannot contain NUL. `with_environment` accepts at most 64 explicitly selected entries and 32 KiB of key/value bytes. Keys are conventional ASCII environment identifiers up to 128 bytes and values cannot contain NUL. Ambient variables are never inherited.

`with_limits(McpLimits)` configures total startup/discovery, request and cleanup deadlines. Startup/request deadlines require 1 ms–300 seconds; cleanup requires 100 ms–10 seconds. Defaults are 30/30/5 seconds. Filesystem metadata calls are cooperative blocking operations and are not forcibly interrupted. Cancellation never reports remote effects as rolled back. Production broker cancellation grace must accommodate SDK and process cleanup; an insufficient grace yields the broker's existing unknown/quarantine path.

`session.catalog()` borrows `McpCatalog { server_id, launch_fingerprint, tools }`. Every `McpToolInfo` includes `native_name`, `original_name` and the complete conservative descriptor. Original names are 1–128 UTF-8 bytes, nonempty after trimming, and cannot contain control characters. Alias encoding is `mcp_<server_id>_<20-character-readable-prefix>_<16-hex-SHA256-prefix>`; non-native prefix characters become underscores. The domain-separated digest covers server ID and exact original name with unsigned 64-bit little-endian byte lengths. The full launch fingerprint similarly covers canonical executable/cwd, ordered arguments, and sorted explicit environment entries. Fingerprints are identity metadata rather than credentials or authentication.

`session.register(&mut registry)` validates all imported tools in a cloned registry and returns their native-name → `ToolScopeRule::Host` map, replacing the caller's registry only on complete success. Call this synchronous schema work on a blocking worker in an async host. Registration does not authorize tool execution. `check_connected()` distinguishes disconnected and invalidated catalogs. `process_id()` is local owner metadata. `shutdown().await` stops and joins owned service/process work through shared supervised outcomes; concurrent or dropped callers cannot turn unconfirmed SDK cleanup into success. A cleanup error is explicit. Unconfirmed process cleanup permanently consumes its admission slot; replacing the host requires owner reconciliation. Cloning a session or registering tools extends ownership. Hosts must retain sessions and await shutdown before stopping Tokio.

The process supervisor owns its child wait status. The host must not install a competing global child reaper or externally reap this PID. Group termination checks the unreaped leader identity before sending signals and disarms before reaping; a missing wait-status anchor fails cleanup without sending signals to a potentially reused PID. Process-group cleanup does not contain a trusted server that deliberately creates a new session or delegates external work.

Bounds are fixed: 1 MiB per incoming/outgoing JSON-RPC frame; 8 MiB and 128 newline-delimited messages per ten-second receive window; five seconds per write; 16 discovery pages; 128 tools; 8 MiB aggregate serialized discovery responses; cursors of at most 256 bytes with no repeats/controls; input schemas at most 256 KiB and declared type `object`; server descriptions at most 7000 bytes; tool arguments at most 512 KiB; completed native output at most 512 KiB. Excess traffic disconnects instead of silently truncating. The official SDK's bounded codec parses framed JSON; its unbounded default stdio transport is not used.

Imported tool arguments are objects validated by the registry. The remote call receives the exact original name and arguments, with no host authority or secrets inserted into arguments. Completed output has `is_error` from MCP `isError` and `content` shaped as `{ server_id, original_tool_name, content, structured_content }`. Provider adapters consume the broker's generic failure flag; they do not inspect MCP-specific JSON. Unknown content links or embedded resources are preserved without being opened. Remote protocol error text is not included in host diagnostics.

A completed semantic error is a known terminal result with retained content. Any error after dispatch is `ToolError::EffectsUnknown` with unconfirmed cleanup and no implicit replay. Before dispatch, failed connectivity/catalog/admission checks return `FailedWithoutSideEffects` for that invocation. Broker operation IDs and approvals still determine durable identity; MCP request IDs are connection-local SDK identifiers. Restart creates a new connection and requires host reconstruction, never automatic replay of uncertain work.

`McpError` distinguishes configuration, capacity, busy, process, disconnected, stale catalog, cancellation, deadline, protocol, resource limit, cleanup, worker, unsupported platform and registry errors. These errors use bounded local descriptions. Server-advertised capabilities, descriptions, annotations, tool results and instructions are untrusted; only the host can grant execution authority or approve disclosure.
