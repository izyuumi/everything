# Bounded outbound candidate DATA

The crate-private `Store::next_transport_outbound_candidate(now, excluded, selection)` selects at most one typed metadata candidate. It neither loads ciphertext nor changes an outbox row. Its defining types live in `storage/transport.rs`; no caller or shared storage alias is installed by this slice.

`TransportOutboundCandidate` contains only the canonical nonnil `MessageId`, canonical nonnil recipient `DeviceId`, actual `not_before` and `created_at` signed integer order scalars, and `TransportOutboundRouting::{Ordinary,PrivateSettings}`. It contains no ciphertext, provenance, grant, Source, settings values, authority, permission or ownership proof. The two routing values describe whether the private transport row exists; they cannot authorize a send.

The selector preserves the existing pending outbox, ready time, unexpired transport row and active peer joins, ordered by `not_before, created_at, id`. `TransportOutboundSelection::OrdinaryOnly` also preserves the existing private-row exclusion. `SettingsEnabled` returns routing DATA for either family; it does not enable private delivery. A present Settings connection owner is not an activation decision. Until the real private pipeline is separately reviewed and activated, any future caller must use OrdinaryOnly for both ordinary-only and Settings-attached sessions.

Exclusions contain at most16 typed message IDs. The single SELECT has a fixed17-row maximum and streams rows without an intermediate candidate vector. Every encountered row is validated before exclusion; the first valid unexcluded candidate is returned. At most16 distinct rows can be excluded, so a17th eligible row suffices to find the first remaining candidate in the same durable order. No row is mutated, skipped as malformed, deferred or repeatedly retried to advance selection. No caller-controlled page or byte bound exists.

SQLite identifier values must be Text and exactly36 bytes before UTF-8 or UUID parsing. Canonical lowercase hyphenated syntax and nonnil values are checked against the established UUID formatter using a fixed stack buffer, then converted through the real protocol ID types. Order values and the private existence marker must be actual SQLite integers. Existing nonnegative creation and `not_before >= created_at` invariants are checked through the existing interval validator; zero remains valid. Readiness and transport expiry are the existing WHERE predicates, with no new clock observation or authority inference.

This is an explicit new canonical DATA contract. The older generic storage ID validator accepts other bounded strings; this method does not promise equivalent behavior for malformed or noncanonical legacy IDs. Such a row produces real typed `StorageError::InvalidInput`, including if its parsed ID was excluded. It is never silently skipped or converted into an empty result. Actual SQLite query/type access errors propagate through `StorageError::Sqlite`; connection poison/quarantine and invalid query time use the existing Store behavior. Invalid exclusions and malformed scalar values also remain explicit InvalidInput errors. Error messages contain fixed descriptions rather than row values.

The existing `pending_transport_outbox`, `confirm_transport_outbox`, preparation, deferral, acceptance, maintenance, receipt and enqueue implementations are unchanged. This method uses the same checked Main connection and adds no transaction writer, schema, window, slot, runtime or background task. Its selection mode creates no trust or current authorization. An eventual private consumer must obtain genuine same-Work queued ownership before any real counted window reservation; Root's missing-owner policy is a typed nonclean connection fault, without ordinary fallback or row mutation.

The same-total16 window, ordinary phase adapter, counted private ciphertext loader, original registered worker/join, current socket admission, Accepted/error cleanup, retained parent/history creator, Supervisor retirement and Host drain remain separate dependencies. Existing [transport storage](settings-transport-storage.md) and [reply publication](settings-reply-publication.md) ownership requirements still apply. No private route is activated here. Direct formatting and static source preservation are separate from compiler, SQL/query execution, runtime/transport or security verification; none of those acceptance claims follows. Automated coverage remains deferred to #32, and #116 remains open.
