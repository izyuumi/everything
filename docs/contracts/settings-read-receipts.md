# Remote Read receipt and joined ownership

The internal Read receive path consumes the existing strict
[scoped DATA](settings-scoped-reads.md) only inside the original authenticated
replay callback. It uses the genuine [verified Source](settings-read-sources.md),
actual receipt capability, same registered blocking worker, Main connection and
Host mutation guard. It adds no runtime, query map, schema, mutation caller,
settings value capture, Original lookup, BUILD arm or public Delivery activation.
A committed metadata receipt is neither a settings reply nor Saved.

The [current Core qualifier](settings-read-qualification.md) now supplies a
borrowed reservation specification only for First. Snapshot derives Default49152;
InspectOriginal derives Inspection90112. Creation time is the original qualified
observation and expiry is its fixed clipped query/Source/parent/grant horizon.
Neither time, family, full peer, grant nor current parent is caller-selected.
Known has no specification and cannot allocate another response. Existing
AccessStatus known-query response behavior remains unchanged.

Store::admit_settings_read borrows the actual verified owner, gets its embedded
capability and Source, and opens its own Immediate on the checked same Main. It
never accepts an arbitrary transaction as proof of Main origin. Exact encrypted
message sender/recipient/digest matching occurs before speculative prune, query
registration and SQL quotas. Duplicate changes no row, query, slot, owner or
clock; like the existing Access writer, its read-only transaction still requires
an observed successful COMMIT. A changed encrypted identity is a typed conflict.
The earlier actual encrypted frame and private-RAM bounds remain necessary to
own input; no unverified header bypasses them.

A new outer envelope is pruned under the existing expired-nonpending policy and
100000-marker ceiling, then qualified in the one existing512-global/64-full-peer
query history. First reserves exactly its required family through the actual
shared queued-plus-reserved quota. Its canonical Host provenance retains the
actual full peer, Host/connection epochs, grant and nonnull current parent. The
plain reservation INSERT and processed marker are atomic. Payload, command ID
and detail are NULL; no query body, plaintext/hash, Original, operation or remote
command row is written. A new outer for Known commits only that metadata marker:
no response ID, reservation, outbox quote, committed Read owner or renewal.

Readback checks every immutable reservation column and all ten marker columns,
borrowing bounded text before comparison. Inspection's family text has its own
ten-byte bound; the existing Access family reader remains unchanged. The writer
checks receiver/pin again and invokes the SAME capability/Source/transaction
qualifier's final recheck after all SQL, immediately before one COMMIT. No query
is registered or restamped by recheck. Actual Source, full pins, live parent,
grant R and original fixed wall/monotonic bounds remain the real authority.

Every returned post-BEGIN error takes explicit rollback. Successful rollback
preserves only a direct typed expected capacity or narrow Expired/OutsideScope
policy classification. Query512/64 exhaustion is before new cell insertion;
reply capacity may occur after registration and retains that new query cell.
Errors, rollback, completion and cancellation never refund or evict query history.
A real rollback failure latches the same shared Store while its original Main
mutex is held and retains both primary and cleanup causes. Commit error remains
uncertain even if rollback succeeds: no ACK, Fresh, automatic retry or no-effects
claim follows. Commit/Rollback wrappers are never recursively capacity or policy.
An unwind can trigger transaction destruction and mutex poison; it does not
supply an observed rollback result. The actual outer worker retains its Source
state and reports Worker/nonclean rather than fabricating a panic cause.

The callback authenticates/decrypts once. Private plaintext over32768 is typed
capacity/noACK before decoding. Valid Read also checks the actual serialized
received encrypted envelope against49152 and destroys that temporary ciphertext
buffer. Its real serde cause is retained under fixed redacted error descriptions.
Malformed/unsupported within-bound packets retain the existing fixed refusal
policy. Only a successfully completed strict Read decode selects this new arm;
ordinary six-lane and accepted Bind/Command/Access behavior is unchanged.

The complete verified Read state is installed before Store. The exact returned
result or Arc-wrapped actual error is installed before any classification; result
is declared before the boxed verified owner and final private witness. Raw opened
bytes are destroyed before worker output. The original JoinSet result enters the
existing retained slot before any fallible accounting/ID/association check. The

ledger/witness and Fresh-family/metadata matrix can privately construct
OwnedCommittedSettingsRead. Its reply precedes the boxed verified owner. Known,
Duplicate, confirmed policy and expected capacity settle without that owner.

Unexpected completion, SQL/commit/rollback/observation uncertainty, conflicting
matrix, panic or bookkeeping failure closes intake and retains the complete

refund its query. Normal cleanup joins; catastrophic whole-owner Drop preserves
existing bounded terminal quarantine. Read adds no BUILD eligibility stamp,
shared request variant, permit, queue or sender. Existing four BUILD variants
remain unchanged.
