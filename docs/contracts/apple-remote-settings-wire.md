# Apple AccessStatus and Bind wire data

`Shared/Settings/RemoteSettingsWire.swift` defines pure request encoders and bounded response decoders for the generation-free AccessStatus bootstrap and subsequent Bind. The leaf is registered in both Apple target source lists; a transport consumer remains absent. It does not authenticate a response, grant access, create or adopt a parent, send an envelope or expose Host controls. Existing authenticated private Settings routing still refuses these packets before ordinary plaintext persistence.

## Finite request shapes

Both request encoders fix the complete `schema_version=1`, `payload{kind=settings,version=1,host_id,message}` wrapper. AccessStatus uses `message{kind=query,query_id,body{kind=access_status,time}}`. Bind uses `message{kind=bind,generation,binding_request_id,time,requested_parent_expires_at}`. No actor, principal, credential, owner operation, native proof or arbitrary request body is accepted.

`RemoteSettingsRequestTime` retains the supplied original positive signed-range interval: expiry is after issue and at most30000 milliseconds later. `RemoteSettingsGeneration` contains only nonzero `grant_id`, positive signed-range `grant_revision`, nonzero `host_epoch` and nonzero `connection_epoch`. Bind requires `issued_at < requested_parent_expires_at <= issued_at+300000`, with checked arithmetic and signed-range expiry. Request IDs and times are explicitly supplied and immutable; encoding does not mint an ID, observe now, renew a deadline or retry an intent. AccessStatus has no generation or parent.

Actual request encoding uses the existing `WireValue` serializer and checks the entire output against32768 bytes. UUIDs serialize as canonical lowercase nonzero strings. These are post-serialization byte ceilings, not allocator or secure-erasure bounds. No product serialization was executed for this source slice.

## Strict response decoding

`RemoteSettingsWire.decodeAccessReply` and `decodeBindReply` accept complete plaintext `Data`. They use the actual existing `WireValue.parse(maximum:32768)` before typed body decoding, including Foundation syntax validation, decoded duplicate-key rejection and existing depth/key bounds. Every nested object has its exact allowed and required fields. Missing fields, unknown fields, positional arrays, duplicate or escaped duplicate keys, unsupported tags/versions/directions, trailing JSON, noncanonical or zero UUIDs, and noninteger or out-of-range timestamps fail. No separate parser or generic retained JSON result is introduced. The existing `SettingsWire.decode` is not used as a duplicate-key boundary.

Both response families require `payload{kind=settings,version=1,host_id,message}` and `message{kind=response,in_reply_to,correlation,generation,body}`. The actual envelope request ID in `in_reply_to` remains distinct from the original inner query/Bind ID and the response envelope ID. Parsing their fields does not establish that they match a genuine pending original.

| Decoder | Correlation | Body and generation |
| --- | --- | --- |
| AccessStatus summary | `family=query,query_id` | `kind=access_status,summary`; message generation equals summary generation |
| AccessStatus fixed denial | `family=query,query_id` | `kind=denied,reason=grant_unavailable`; generation is explicitly null; complete original packet<=2048 bytes |
| Bind | `family=bind,binding_request_id` | `kind=bound,binding_request_id,parent,expires_at`; both binding IDs match and message generation equals parent generation |

The summary has exactly `generation`, positive signed-range `expires_at`, `readable_keys`, `writable_keys`, `session_consent` and required nullable `configured_settings_revision`. Readable keys are at most five strictly ordered existing Host keys. Writable keys are at most two ordered embeddings enabled/dimensions keys contained in the readable set. Existing `SettingKey` ordering and `SettingsProviderKind` are reused.

Consent is exactly `none` or `configured_provider{provider,model,recipient}`. None requires an explicit null configured revision; configured consent requires a positive signed-range revision. The model is nonblank, NUL-free and at most256 UTF8 bytes. The recipient is NUL-free and at most4096 UTF8 bytes, and Foundation URL parsing rejects credential userinfo, query or fragment. The exact tuple is retained without normalization, endpoint lookup, network contact or provider fallback. The actual Host grant validator owns canonical official/loopback recipient and model policy; this data decoder does not create consent or implement another endpoint authority.

Bound contains only a nonzero parent ID, the exact matching public generation and positive signed-range original parent expiry. It contains no Original/service outcome, receipt, grant summary or permission flag. Unsupported responses and invalid data throw; they never become Bound, a fixed denial or Saved. The decoders return typed immutable observations with no stored raw plaintext, parsed tree, diagnostic or additional field. Response records have file-private construction; all new aggregate descriptions and debug descriptions are fixed redacted strings. Existing finite `WireError.invalid` and `size` are the only outward errors; Foundation exception text is not retained or forwarded.

## Required authenticated consumers

A real future owner must register the bounded private adoption pipeline before decoding, authenticate the complete current pinned Host/local device and signature/AEAD, and match the current connection, actual retained query and encrypted request ID before adopting an AccessStatus generation. A decoded generation, correlation UUID or matching body is not authority. Revocation, reconnect and Host/connection epoch changes invalidate the corresponding observation. An authenticated denial disables the relevant current scope; it creates no parent.

Only that actual authenticated observation can supply the genuine Bind producer. Bound adoption must match its original Host, encrypted request ID, binding ID, complete generation and retained requested/grant deadlines. It must preserve the actual Host-issued parent/expiry rather than fabricate a parent or renew an original. This leaf implements neither producer nor adoption and names no type Authenticated or Granted.

`DeviceIdentity.seal` currently fixes ordinary envelope lifetime to seven days. It cannot be used for Settings fresh requests without a later scoped existing-identity API enforcing duration<=30000 milliseconds and outer expiry<=the original inner expiry. Accepted private receive still needs the genuine post-AEAD owner, current full-pin/local-ID/disabled rechecks, exact replay transaction and metadata-before-ACK ordering. Ordinary inbox caching is not a private Settings consumer, and a transport ACK is not Saved.

The actual later consumer must enforce full encrypted envelope bounds49152 for summary/Bound and4096 for denial, complete Settings relay frames<=364544, response duration<=60000 and the actual current grant/parent/fixed clocks. It must retain private owners and buffers through actual work joins. No queue, Task, storage, cryptography, UI or lifetime owner is added here. Root owns both Apple project registrations and shared integration. The [AccessStatus source](settings-access-status.md), [summary data](settings-access-replies.md), [Bind data](settings-bind-replies.md) and [Apple refusal boundary](apple-private-settings-ingress.md) retain their separate authority and activation requirements.

## Same-identity scoped request sealing

`DeviceIdentity.sealSettings` now has separate overloads for the actual `RemoteSettingsAccessRequest` and `RemoteSettingsBindRequest`. Each accepts only its typed original request and an actual `DevicePublicKeys` recipient. The existing identity actor, signing key, key agreement, HKDF context, ChaChaPoly authentication, header randomness and signed envelope format are shared with ordinary sealing. Ordinary `seal(_:recipient:now:)` retains its original guards and seven-day lifetime; its unchanged CryptoKit body is factored into one private header-taking helper. All five existing ordinary callers and receive/routing behavior remain unchanged.

Each Settings invocation reads real `ContinuousClock` and `WireID.now()` values inside the actor before request encoding or encryption. It revalidates the actual recipient through the established public-key constructor, requires its device ID to equal the request Host and rejects the local identity as recipient. These are shape and label checks, not proof of a currently pinned, active or trusted Host. No caller-supplied current time, replacement deadline or arbitrary-plaintext Settings API is exposed.

The actual wall observation must be at or after the original inner issue and before its fixed expiry. The existing header constructor receives that actual creation time and exactly the remaining original interval, at most30000 milliseconds. The signed outer expiry therefore equals the immutable inner expiry. One monotonic deadline is derived from the first captured instant and that same remaining interval before any request encoding or sealing; it is never restamped. After actual complete encoding and sealing, a final real wall observation must remain at or after captured creation and before original expiry, and the actual continuous clock must remain before the fixed invocation deadline. Rollback below that captured wall floor or expiry fails without returning an envelope.

This monotonic fence bounds one sealing invocation. It does not recover the original pending request's first monotonic deadline, detect all earlier clock rollback or establish validity across queueing, retries or reconnects. A later genuine original owner must retain that first intent lifetime and gate actual sending/adoption. Re-encrypting the same typed intent cannot renew its inner expiry, grant a new original, adopt a generation or parent, or authorize a retry.

The request encoder checks the complete plaintext against32768 bytes. The actual complete signed envelope is encoded with a49152-byte ceiling, and the actual existing `Send{type=send,schema_version=1,envelope}` frame is encoded with a364544-byte ceiling. These temporary measured buffers remain local; only the actual signed envelope is returned. Plaintext, encoding temporaries and the private fixed-redacted invocation context are synchronous values without a new Task, queue, callback, storage owner or retained registry. Swift Data/ARC/COW lifetimes provide no secure-erasure or peak-memory guarantee. Established CryptoKit/randomness/encoding failures propagate as real local errors; scope, clocks and sizes use existing finite errors. No failure constructs a denial, parent or success result.

No actual Settings caller, outbound admission, transport send, authenticated reply adoption or private receive activation is added. The complete current Store pin, local disabled state, connection/epoch association and original correlation must still be checked by genuine owners before sending and adopting responses. Existing metadata-only refusal remains active. Standalone Swift grammar and exact ordinary-source inverse/static checks are the current evidence; supported SDK compilation, actual product serialization/sealing, encrypted interoperability, clock/cancellation observations and security acceptance remain unverified. #116/#117 and deferred #32 remain open.

## Non-authorizing verified reply and metadata prerequisite

`DeviceIdentity.verifySettingsAccessReply` and `verifySettingsBindReply` are separate same-identity, synchronous actor methods. Each receives the actual encrypted envelope and expected complete Host public keys, reads actual wall time internally, and uses the exact existing sender/recipient, header/skew/expiry, pinned-signature and CryptoKit AEAD verification prefix. The original prefix is shared in one private helper; ordinary `receive` keeps its original caller-supplied clock, routing, exact plaintext and ordinary/refusal Store calls. Neither new method is wired to the receive loop or a caller.

After successful actual cryptography, each method invokes its actual strict typed AccessStatus or Bind response decoder and requires the decoded Host to equal the verified Host. Wrong routing/direction/family, duplicate or unsupported fields, invalid correlation/generation and malformed data fail; no ordinary or successful-response fallback occurs. Response envelope duration must be positive and at most60000 milliseconds. The actual complete encrypted envelope encoding must fit49152 bytes for summary/Bound or4096 for the actual fixed denial. Existing packet32768/denial2048 checks remain in the decoder. No crypto, decoder or encoder was executed during source validation.

Only then does a file-private constructor create `VerifiedReplicaSettingsReply`. The final immutable Sendable class retains the actual encrypted envelope, full verified Host/local identity and a private finite typed observation. Raw plaintext and parsed trees remain synchronous local values; neither is retained or returned. Public read access is limited to actual envelope metadata, finite query/Bind correlation, `in_reply_to` and generation labels. `matchesVerifiedPeer` compares the real retained full Host keys and local ID. Neither class has a private body getter, arbitrary constructor, generic JSON/bytes accessor, Codable conformance or authority-producing method. All six new aggregate description/debug implementations are fixed redacted strings.

`commitMetadata(into:)` retains that actual verified object through the real awaited `ReplicaStore.rejectAuthenticated` call. Despite the existing method name, its unchanged schema records terminal ciphertext metadata with `payload=NULL,done=1`, not a denial reason or accepted Settings result. The same immediate transaction rechecks the complete current Host pin, local identity/recipient and sticky disabled state, compares exact ciphertext replay before capacity, and preserves changed-ID conflict and total-receipt rules. No Store/schema/SQL changes occur.

Only a successful actual transaction return constructs the opaque `CommittedReplicaSettingsReply` retaining the same verified object. Its closed `fresh` disposition means a newly inserted metadata row; `duplicate` means an exact preexisting ciphertext marker. Neither means fresh permission, adoption, ACK, Saved or a replayable effect. Existing commit errors propagate; rollback failure maps to the existing storage error. This prerequisite does not add detailed rollback/quarantine truth or infer a clean transaction from cancellation. No failure fabricates a committed proof or clears an original.

The new cryptographic factories contain no await or background work. The proof's private typed data remains owned across the actual Store actor wait, and a successful returned committed object continues that ownership. Store work receives only the existing encrypted metadata arguments. A discarded result drops data without changing marker disposition. No detached Task, callback, registry, queue, rescue, current-original owner or cleanup signal is added. Swift ARC/COW behavior remains outside secure-erasure or exact memory-release guarantees, and cancellation is not proof that SQLite aborted.

This proof establishes cryptographic/data facts and metadata transaction completion only. It does not establish the original pending request's first wall/monotonic lifetime, an actual RelayConnection scope, current pin after later waits, readable grant, generation/parent adoption or permission to reveal private body data. The later genuine Service owner must exist before any qualified private payload accessor is added, retain original clocks and actual work through joins/retirement, and match its real original/correlation/current connection before adoption. No optional admission, synthetic owner, caller boolean or DTO/row reconstruction is supplied.

`RelayFrame` currently discards the original complete raw frame byte count. This proof cannot claim the incoming364544-byte Settings frame check from re-encoding an envelope; the later actual relay/service receive owner must carry and enforce it. The existing ordinary receive loop still commits metadata-only refusal for Settings. Actual Rust Access/Bind producer/publication/send/cleanup prerequisites, client pending/pump/current-pin owners, supported SDK integration and real encrypted replay/clock/cancellation/private-cache observations remain separate. This source has only standalone Swift grammar, exact ordinary-source inverse and static preservation evidence; #116/#117 and deferred #32 remain open.
