# Host worker admission and recovery

The Host coordinator uses the existing Agent, Scheduler, Broker, Store, owner socket and state lease. Its optional settings field defaults to `None`. When no coordinator service is constructed at startup, status creates no worker-purpose identity or endpoint and reports unknown retained-history counts (`None`) without scanning the worker ledger. A retained service disabled through live settings still reports its actual inspected counts. Existing native tasks remain inspectable through ordinary owner task queries. The ordinary device relay and worker-purpose relay have separate identities and pins. Enabling coordination requires an explicit relay origin and a Host restart; the retained endpoint rejects a changed immutable origin.

Preparation captures only the owner-selected request and input paths. The full manifest, exact executor keys/fingerprint, model endpoint/profile, constraints, context, file bytes, output paths, tool scope, budgets, deadline and separate local/executor identities are disclosed before Delegate. Delegate must supply the ticket, exact manifest digest and executor fingerprint, using the disclosed local creation command as its actual enclosing owner request ID. A serialized manifest or journal snapshot cannot replace the live prepared/staged capability.

`WorkerAdmissionSnapshot` is trusted effective metadata of a genuine local `OwnerCommand::Initialize`, stored in the existing `local_initialize` Host inbox kind. It contains version, ticket, fingerprint and compact `RemoteTaskSubmission`; the original Initialize stores title/configuration/conversation/creation identity. Selected context, full manifest and derived instruction remain outside the 64-KiB effective metadata limit. The full manifest is staged in the worker ledger before the compact Host journal and before Agent side effects. The original server acceptance time precedes actual approval and remains the task creation time.

Endpoint authority precedes the owned Host mutation guard. The original staged capability, full immutable native definition, actual guards, original wall and monotonic deadlines and Agent pass through opaque `RemoteTaskAdmission` into the Scheduler's blocking transaction. Approval is checked after acquiring SQLite's immediate transaction and before commit. The Host journal compares the complete trusted effective snapshot on an existing identity, because the ordinary inbox identity check alone compares the original request. Dedicated local conversation creation and text acceptance never enter ordinary local model dispatch.

An owner caller can disconnect after admission. The coordinator's bounded owned operation retains its permit, payload reservation, Host/Agent and guards until its actual operation ends. Host drain closes fresh intake and joins the coordinator's operations and relay/reconciler before stopping the shared Scheduler. A queued message or local shutdown does not establish remote stop.

The dispatcher recognizes retained RemoteInitialize metadata before taking ordinary Host mutation. Recovery reads the immutable worker manifest outside Host mutation, then checks the exact actual native reservation under the mutation guard. Configuration, instruction, IDs, original acceptance, full policy, approval and binding must match. The original Agent creation and user-message command receipts are independently checked; recovery creates no assistant response or replacement command. It finishes only the original ingress receipt. An initialization without a native reservation becomes an explicit unadmitted boundary: expired consent is never reconstructed, no remote slot is charged and no Offer is generated by that journal. Existing partial conversation/input history and the staged manifest remain inspectable. Disabled or unavailable composition leaves recovery pending; it never rejects a command merely because its native reservation cannot currently be inspected. Other proof failures preserve the ingress record and fail the dispatcher closed rather than asserting that an admitted task was rejected.

Exact Delegate replay uses that retained mapping and original command receipt. Changed ticket, digest, fingerprint or request identity conflicts. Offers are recovered from the actual native binding and must reuse the original authenticated encrypted envelope. Terminal worker sources are pinned by schema11 and become native results only through the bridge's authenticated capability and atomic Agent transaction. A result acknowledgement requires its actual opaque native receipt. No public report or inspection flag supplies authority.

Cancel first validates the exact native binding under Host mutation, then releases that guard before durably queuing the original encrypted cancellation request under endpoint authority. That durable worker intent blocks further Offers before the Host reacquires mutation and records native cancellation. Recovery mirrors retained worker cancellation/revocation into native intent without creating another cancellation message or request identity. Revocation records permanent purpose trust revocation before requesting native cancellation for matching reservations. Neither action fabricates remote completion or refunds the immutable charge. Artifacts remain in private quarantine; this interface supplies no automatic workspace application.
