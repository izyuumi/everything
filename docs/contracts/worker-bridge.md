# Native worker coordinator bridge

The worker bridge connects the existing worker-purpose ledger and cryptography to the native Scheduler reservation and Agent result transaction. It does not construct another local Scheduler, Broker, provider, agent loop or cloud service. The implemented [Host admission](host-worker-admission.md) and [coordinator service](host-worker-service.md) supply optional settings, owner operations, durable local identity mapping and the real Gate. The actual combined Host credential-rejection/recovery walkthrough passed within its separately recorded limits. A public snapshot/report is data, not approval or result authority.

`WorkerEndpoint::acquire_staged(StagedDelegation, UnixMillis)` returns opaque `OwnedStagedDelegation` after acquiring actual endpoint authority and verifying the exact durable unstarted manifest, current purpose pin and original wall/monotonic approval. Read-only manifest/binding/approval accessors expose the captured scope. Its crate-private `into_native_admission(TaskSubmission, original_owner_command, owned_host_guard)` compares exact native tools/mode/budget/limits and separate local/worker identities, captures the actual manifest-derived configuration/instruction and transfers the original deadline and all guards to opaque `RemoteTaskAdmission`. It does not reset approval lifetime. Neither opaque object has public fields, Clone or serialization.

`Scheduler::admit_remote` now requires that actual capability. There is no public DTO-only fresh admission path. The neutral Scheduler type imports no Worker code. The Actor checks same leased Store, exact original pending instruction/configuration and native reservation rules, then moves remote/native/write/endpoint/Host resources and the leased Agent into the actual blocking insert. SQLite immediate-transaction acquisition and precommit both recheck original wall and monotonic approval. Expiry rolls back without charging/inserting a task or stopping unrelated native work. Ordinary task insertion semantics remain unchanged. The Agent stays retained until resource cleanup. Existing immutable once-charged caps, root-only primary capacity and no-local-dispatch rules remain effective.

Host must obtain endpoint authority before its owned mutation guard, preserve the original local identities/preapproval receipt time and durably record its compact trusted initialization mapping before any Agent create/accept effects. The bridge does not create a Host inbox kind, adopt an existing chat or reconstruct lost approval from a stored manifest. Unadmitted partial initialization remains an explicit recoverable owner-visible boundary; an existing native reservation uses its exact durable definition.

`offer_reserved(RemoteTaskBinding, actual WorkerOutboundGate, now)` requires the exact retained manifest/current pin and the real native Gate. Under endpoint authority it queries at most two original outbound Offers for that delegation. Zero permits one first encrypted Offer; one requires exact canonical full manifest, role/endpoints, immutable recorder binding and historical signature and reuses the original message/envelope; more than one fails closed as ambiguous legacy history. It never selects by clock order, last row or SQLite rowid, refreshes an expired Offer, infers new approval or creates another attempt. Gate authority is retained through queueing, and existing relay flush reacquires it through socket send. The older approved-Offer wrapper now delegates to this path and requires prior staging.

Schema11 terminal-source recording occurs in the same immediate transaction as the first authenticated inbound Executor Result/Rejected packet and immutable message insert. It pins a source only when no previous result/rejection existed. Later identical packets cannot replace it or repair an already-terminal pre11 row. The bridge reports unavailable original provenance for those legacy outcomes; retained history is preserved for inspection.

`verify_native_outcome(RemoteTaskSnapshot)` checks actual endpoint role/origin, current purpose pin, exact original manifest/native scope and the referenced immutable packet/envelope. It reauthenticates and decrypts with the established DeviceIdentity implementation at the actual recorded receipt time. Its retained replay guard compares exact existing identities/plaintext and deliberately returns the established Replay outcome after successful historical verification; it never claims a new inbox admission or rewrites replay state. Signature or AEAD failure cannot mint a capability. Canonical source SHA digests use the existing worker digest helper with distinct packet/envelope domains.

Known/Unknown signed WorkerResult fields are compared to the immutable ledger and original manifest. The actual private quarantine helper validates/replays protected files before acceptance; public QuarantinedArtifacts or a stored Boolean alone are insufficient. Known reports include the exact result/quarantine digest. Unknown exports no artifacts and reports no quarantine digest; it keeps native reservation/charge under the separate Agent/Scheduler contract. Rejected maps the actual signed reason to a distinct zero-usage, zero-artifact report without fabricating a WorkerResult or stop attestation. The returned VerifiedRemoteOutcome retains actual endpoint authority/Agent; Host attaches its current owned mutation guard before the actual atomic native result admission.

`acknowledge_native_result(RemoteResultReceipt, now)` consumes only the real opaque native acceptance proof. It reacquires endpoint authority and verifies same leased Store, exact accepted source/binding/report, current trust and actual private quarantine. Rejected returns NotRequired and emits no invented acknowledgement. Result acknowledgement is an idempotent repair of that original acceptance: zero original outbound ACK queues one, one verifies/reuses its exact receipt/result/message, and ambiguous legacy duplicates fail closed. Queued describes durable local retention and does not assert relay delivery or remote stop. No raw public binding/digest/command ACK API remains.

Endpoint/Host exclusion is continuous through native commit. ACK is a separate operation with fresh trust checks; revocation in between can deny ACK without rolling back accepted history. Caller cancellation after native commit can omit ACK, and recovery can repair only that original opaque receipt. ACK grants no fresh task/data capability or Host network lifetime, and may finish as cleanup during drain; Host owns the optional enabled relay and its joined shutdown.

Shared scope is deliberately limited to typed capabilities and the existing native/store/worker boundaries. No new dependency, crypto primitive, source comment, test or migration is introduced by this bridge.
