# Private Settings ciphertext loading

The crate-private Store loader accepts a genuine whole queued reply, actual endpoint, receipt authority, retained Host mutation guard and a private-routing candidate. It opens its checked Main connection and one Deferred transaction. Existing queued authority checks run before the read and again after all SQL, decoding, historical signature verification and complete relay-frame validation. The returned existing Send value is DATA only: it grants no current socket, first-poll, original-job join, send, retirement or drain permission.

The loader reads all eighteen actual outbox/transport/private roots and checks that the original reservation is absent. It compares complete retained canonical provenance, family, recipient, IDs, byte count and fixed expiry. Reservation creation is a lower bound on sealed-header creation; actual outbox and private-row creation must equal the header. Mutable retry metadata must match the selected candidate, remain valid and be ready at a real local wall observation. This observation is scheduling data and does not advance Core floors or renew deadlines. Missing or mismatching rows are errors, never ordinary fallback or silent retirement.

Before application ciphertext allocation, a borrowed BLOB must be nonempty, match the committed byte count and remain within the original family quote: inspection 90,112, default 49,152 or denial 4,096 bytes, plus the existing storage ceiling. Its encrypted JSON SHA-256 must match the RAM-only committed digest. Existing bounded envelope decoding must recover the entire exact header and signature. Existing authenticated-sender verification uses the exact original header creation time for historical verification only; fresh permission comes from the surrounding real queued gates. Existing Send encoding validates the actual complete frame and its scratch is destroyed before the final gate. Snapshot and Inspection use their genuine Read-derived queued arms; Status has no accepted queued arm in this loader.

Every returned post-BEGIN error explicitly rolls back through the existing publication rollback helper while the original Main guard remains held. Actual rollback failure quarantines the same Store clone group and retains both causes. Read-only COMMIT failure remains uncertain even if rollback succeeds. Caught panic retains its actual payload and rollback result. Errors and Debug displays are fixed and retain typed causes without logging ciphertext, provenance or private data. No error implies NoEffects, refund, cleanup or retry permission.

The loader does not allocate a new queue, manufacture authority, change ordinary transport, or remove queued custody. The counted job and [final socket consumer](settings-private-socket-admission.md) below retain the entire original input, actual handle/task ID and whole result through true join. Their internal source does not install a session caller, private Accepted/no-resend, retirement or composite drain. SQLite and bounded decode/frame scratch can allocate internally; per-call bounds are not an aggregate heap or RSS guarantee. Current final-unit compiler validation is pending and private activation remains disabled; source review is not runtime acceptance.


## Genuine counted preparation consumer

The Unix shared relay window now has a private preparation consumer of this exact loader. Its retained Source owns the original candidate supplied to the paired Work/window lend; it never reconstructs a candidate or queued owner from row metadata. The Source borrows its actual queued payload/context and derives the receipt authority from the embedded Fresh committed source, Historical original, Access verified request or Snapshot verified read. Bind uses the exact authority retained by the original BUILD input. The same Host mutation guard is supplied to the unchanged Store loader. No SQL, header/authentication rule, rollback handling or Store quarantine policy changes in this consumer.

The window registers the full input before direct blocking spawn, retains the original handle and task ID, and stores its entire actual return before any fallible association checks. Actual loader errors, uncertain commit/rollback and caught panic payloads remain owned by Observed outside the Source/input Arc; their fixed Debug/error summaries do not copy private content. The worker releases its actual Host guard before returning a frame or failure. Cancellation, connection closure and original absolute deadline expiry stop admission or mark a running attempt, but still require that original handle to join. The Source, settlement and original Work/private/Supervisor charges remain retained in every phase.

The prepared frame remains counted DATA in the same total16 map. This change does not wire the relay pump to private preparation or enable a private selector. The [final socket unit](settings-private-socket-admission.md) now supplies final current SQL, original final-job join, separately returned uninterrupted Host guard, bounded last checks and guard destruction immediately before the first physical poll. Internal started handback now returns the full Source and evidence to Work before genuine adoption frees its window cell. ACK handling, SQL no-resend disposition and creator-LAST retirement remain separate source dependencies. Orderly close and catastrophic retention destroy all registered lock-acquisition futures before archiving; running guards stay on the actual worker stack. Existing unstarted return and ordinary delivery semantics remain separate. No new automated tests or local compiler, SQL, cryptographic or socket execution establishes these source claims.

## Final current transaction and scoped guard return

A separate crate-private Store wrapper now rechecks an actual queued reply on its checked Main connection in one Deferred transaction. It invokes the existing generic six-family queued current gate under the same actual Host guard, then executes one borrowed COMMIT immediately after the successful gate. It performs no additional SQL between them. Explicit rollback reuses the actual publication helper with Ignore drop behavior; rollback failure quarantines Main while its mutex is still held. Primary errors, rollback errors, commit uncertainty and caught panic payloads remain distinct and owned.

The retained Source derives authority separately for Fresh, Historical, Bind, Access, Snapshot and Inspection from the actual original owners. Bind uses its genuine retained BUILD authority; each other arm uses its embedded receipt authority. Immutable loan/candidate/queued association is checked as DATA, followed by the real Core current checks. The final worker offers its same uninterrupted guard only after Store Main/transaction borrows end. Its original task/handle must truly join, and the complete returned result must be registered before the outer driver reads the scoped one-shot. Arrival, reference count and is_finished provide no substitute.

The new socket consumer does not change this loader's ciphertext query, complete encrypted JSON SHA/header/signature/length checks, frame encoding rules or historical authenticated-sender verification. It preencodes the exact returned frame before the final wait; the fresh no-SQL six-family gate and bounded checks occur later at physical socket admission. No Source reconstruction, resealing, SQL row authority, private selector activation, ACK cleanup or retirement is introduced. Guard receivers, parcels and lock-acquisition futures never enter terminal custody. Supported CI and actual SQL/crypto/socket/runtime verification remain outstanding for this final unit.
