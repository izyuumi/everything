Issue #68 composes the actual memory, MCP and selector services inside the existing headless host. The current-main replacement includes the strict embedding-only helper required by #72 and the two startup ownership guards. Its exact-head CI and runtime verification remain pending; historical observations below retain their original source scope.

Host settings add defaulted `memory`, `mcp` and `selection` fields to the existing owner-only revisioned settings. They contain configuration and purpose-bound credential references. Service settings take effect at host restart. `OwnerQuery::Composition` reports active configuration, real service status and separate restart-required flags. Model/workspace defaults continue to be captured independently for each new task.

MCP sessions start only under their exact stored launch authorization and clear environment policy. Their real tools/scopes join the single host registry before discovery, permission policy, global broker and scheduler construction. A separate lifetime token keeps sessions available while admitted broker operations drain. `CredentialOperation::StoreMcp/RemoveMcp` uses the same host vault and native-store admission handle, with no ambient model-key fallback.

One leased MemoryService owns the canonical Wiki and Consolidator. `Scheduler::start_with_preparation` uses real bounded retrieved excerpts without an answer-model request and captures the resulting context before provider construction. A fresh command prepares independently; active native resumption preserves its saved definition. The retrieval query normalizes whitespace and bounds 64 terms/4096 UTF-8 bytes while leaving the accepted objective unchanged. An objective with no usable retrieval terms gets no excerpts.

Owner queries include Composition, Publication, MemoryJob and RetrieveMemory. Memory operations include MemoryEnqueue, MemoryCancel, MemoryRetry and ApplyMemoryPlan. Enqueue accepts the existing typed ingest/query/lint requests and stable job identity. Explicit host plans use the actual source/hash conflict checks. Feature-enabled RebuildEmbeddings takes bounded chunk/time limits; no extra embedding model or runtime download is introduced. Embeddings stay disabled by default, and initialization/fallback/cancellation semantics remain those of the actual memory service.

Optional selection has three owner operations: PrepareSelection, ApproveSelection and DiscardSelection. Preparation takes the complete original local domain command JSON for a fresh root task/message before command admission. The host derives actual captured execution, authority and registry fingerprint. It returns either real local selection or the exact endpoint/model/payload/authority disclosure. Only explicit approval can make that captured off-device request. Approval rechecks the original command and current captured policy. Sending the identical domain command afterward lets the fresh task consume that one-shot result; the native checkpoint then persists the selected definitions. Later active resumes never reclassify. Missing, unapproved or expired tickets retain ordinary local selection and search_tools. Tool budgets reserve the local discovery definition. Tiny/no-tool budgets remain usable through ordinary local execution.

All service operations use host-owned admission. Drain closes new admissions and promptly cancels selector/maintenance work. The host joins previously admitted handlers/preparation and repeats the real memory idle barrier. Scheduler workers and broker operations drain before MCP cleanup. Local owner inspection/recovery and the state lease remain owned until actual service and publication cleanup. No menu bar application owns this lifetime. Cancelled memory, selection and local requests retain a distinct `cancelled` failure code; a cancelled mutation still requires inspection of its durable receipt before retry.

The separate startup registry/Authorizer worker captures and binds the complete `(Store, Agent)` resource pair. Its successful result retains the Agent as its last field, so Store-bearing registry, Authorizer and discovery resources are destroyed before that owner even if the startup caller drops its pending JoinHandle. The adopted owner remains held through Broker startup. This narrow lifetime correction has source review and formatting validation only; fresh combined compilation, CI and a qualified cancellation/resource-lifetime observation remain pending.
