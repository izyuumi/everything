# Scheduling controls

`Scheduler::schedule_context(caller, workspace, operation, tool_name).await` is a trusted host API for native schedule-control tools. It requires a scheduler-owned Running caller with a live active worker, its exact captured canonical workspace, no cancelled ancestor, and the exact running Broker operation for that task and tool. It returns `ScheduleCallerContext` with read-only access to the task's immutable native configuration, restricted execution authority, active command and operation identities, tool name and cancellation. It is not serializable and contains no model-provided permission override.

The context's cancellation is derived from the actual active worker. Task cancellation, host shutdown, worker completion and worker failure invalidate it. Returning a context does not grant new capabilities, approve a tool, authorize another provider endpoint, or guarantee that a later mutation may still execute. Consumers must recheck the token and exact running Broker record immediately before repository admission, retain the actual leased Agent through blocking work, and preserve truthful uncertainty if cancellation or response loss follows admission.

The controls service and native tool adapters will be documented here only after implementation. Owner IPC, CLI registration, profile exclusions and host lifetime integration remain coordinator-owned work for #53. The existing repository's CRUD revision CAS and manual-claim exact replay have different semantics; no generic scheduling command journal is implied by the context API. Unknown acknowledgement remains a separate owner-only operation, never an agent permission or retry capability.

Rust 1.88 static validation is recorded with the implementation handoff. No successful live inference, native tool-call generation or race/crash acceptance criterion is established by source compilation. Automated coverage is deferred to [#32](https://github.com/izyuumi/everything/issues/32).
