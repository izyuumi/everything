# Guarded native remote result admission

The Agent/Scheduler transaction path composes the neutral report and external-task storage contracts with the actual [Worker verification/ACK bridge](worker-bridge.md) and [Host authority/owner operations](host-worker-admission.md). No public data record or JSON decoding grants result authority. The actual combined Host credential-rejection/result-acceptance walkthrough passed with the qualifications recorded below.

`VerifiedRemoteOutcome` has private fields, no public constructor, Clone or serialization. Its crate-private mint is reserved for the real worker verification bridge: retain the actual coordinator endpoint authority guard after validating its original pinned encrypted source and private quarantine. The capability retains its leased Agent and original native `RemoteTaskBinding`. A separate crate-private method attaches the actual owned Host authority guard once. Both guards remain owned through fresh admission. Read-only `binding()` and `report()` expose metadata; incoming `report.accepted_at` is not the local commit timestamp.

`Scheduler::admit_remote_result(task, outcome)` acquires the existing owned remote-admission mutex before enqueueing Actor control. The Actor never awaits that mutex. Fresh admission requires the exact actual owned native reservation and original binding/task/command, the same leased Store connection, live activated Scheduler, current captured workspace authority, an available Broker and the real retained Host guard. No local provider or native setup is constructed. Immutable original model/tool/output/token allowances remain fully charged; reported usage never refunds or widens them.

The private `RemoteResultCommit` is minted only by that Actor. It carries its validated typed task, full expected TaskRow and actual owned capability/admission resources. Its checkpoint builder accepts only the Agent-generated inspection/report metadata. It cannot execute arbitrary SQL, accept an arbitrary callback or turn a caller Boolean into authority.

`Agent::commit_remote_result` takes actual native conversation admission before the short write gate. Its blocking operation retains those guards, the endpoint/Host/Scheduler guards and leased Agent through completion. It requires the exact original pending user command/text and immutable configuration, native entirely absent, continuation absent, input inbox empty and last_turn absent. It loads the current checkpoint after the write gate, preserving trusted metadata progress. It changes only the original pending field to None and appends one typed `RemoteTaskFinished` event. There is no assistant message, new user instruction, fake model response, native completion record or TurnSummary.

Local accepted time and actual next event sequence are generated under those guards. The original task snapshot, new typed result checkpoint, conversation sequence/revision and any-task-or-conversation tool-row exclusion are enforced by `append_with_external_task` in one immediate transaction. Only a successful atomic commit can release a known outcome's primary slot. The general TaskRecord/TaskState transition rules and native metadata merge proof are unchanged.

`RemoteResultInspection` is Clone/Serialize/Deserialize data containing the report, stable receipt command/event IDs, event sequence, accepted task status and cancellation intent at acceptance. It is stored once in the typed remote checkpoint and exposed through `remote_status.result`. IDs reuse the existing Agent control-event SHA identity helper with a distinct remote-task input and original source identities/digests. The opaque `RemoteResultReceipt` has no public constructor, Clone or serialization; it retains the actual leased Agent, original binding and conversation. Inspection data cannot be deserialized into that proof.

Receipt restoration checks the actual validated private remote task checkpoint, then the exact report/event/command/sequence/schema/time/cause and actual event row in that Store. The command must also retain its atomic state digest. It does not treat a matching public event or inspection alone as a receipt. Exact authenticated source replay reuses the original local accepted time, returns the historical receipt and performs no pending/task/tool mutation. Newer legitimate conversation or tool history does not rewrite or invalidate that already-committed acceptance. Changed source, report content, mapping or policy conflicts.

Succeeded settles Completed; Failed settles nonretryable Failed; Cancelled settles Cancelled. Rejected remains a distinct source/outcome and settles nonretryable Failed, except the exact cancelled-before-acceptance reason settles Cancelled. A known success after a cancellation request preserves the actual successful outcome and recorded cancellation intent. A request or cancellation ACK does not become confirmed remote cancellation.

Unknown stores its one immutable attributed report and closes the original pending command, but remains WaitingForChildren in explicit OutcomeUnknown phase with its primary slot and complete charge retained. It has no artifacts, dispatch, retry, replacement attempt or refund. A later cancellation keeps that Unknown phase and original receipt. Known outcomes use Settled; cancellation of Settled is a no-op. Strict decoding verifies phase/status/failure/receipt/binding/usage/charge relationships and prevents terminal replay from reinserting a slot.

Startup scans at most4096 retained remote identities, validates every stored receipt against its real Agent journal and restores only unresolved slots. It does not create a provider, recover a native loop or reaccept the original command. `remote_by_binding` is a bounded pure query over validated retained definitions; the crate-private receipt query restores only existing proof. Neither query emits a Scheduler mutation notification. Retained approval/delegation/native identity uniqueness continues after settlement. Parent/child delegation is still unsupported, so no SubagentFinished event is generated.
