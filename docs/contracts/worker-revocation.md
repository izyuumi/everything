# Exact worker revocation retry lookup

`worker::revocation::retained_revocation(&WorkerEndpoint, DeviceId, CommandId)` is a synchronous, crate-private worker helper. The transport caller must already hold the actual endpoint authority mutex and run the helper outside Tokio workers while retaining the endpoint's leased Agent. The helper performs no mutation, socket operation, key lookup outside the existing worker-purpose ledger, reapproval or re-encryption.

The lookup scans existing outbound canonical packet request IDs, including Cancel records so another kind cannot reuse a revocation request identity. It selects at most two matches and rejects ambiguity, a changed peer or a different body. It does not include peer-controlled inbound request IDs or result receipt IDs in that namespace. No match returns false so the caller can perform its existing fresh authorized revocation path.

An exact match requires the existing combined 4KiB revocation packet/envelope bound before copying either payload, canonical WorkerPacket bytes, exact Revoke request ID and original revocation time, current immutable endpoint role/public keys/origin, exact sender/recipient/message identity, expiry and the original recorded timestamp. The historical peer keys must still match that recipient and the original sticky revocation record. Header/ciphertext signature verification uses the established EncryptedEnvelope verifier with the original recorded time, allowing an expired historical record to be recognized without granting a fresh send. Canonical serialized envelope bytes must match their immutable stored form.

The existing DeviceIdentity::open API requires the local identity to be the envelope recipient, so this helper does not use it to open an outbound peer envelope. It verifies the authenticated outbound envelope and the canonical sibling plaintext packet recorded by the actual local queue transaction; it does not claim recipient decryption or a cryptographic binding independently of that immutable recorder. Existing `record_message` constructs the packet/envelope association and applies revocation atomically. A successful lookup returns historical local acceptance only; it neither transmits another envelope nor changes trust, native task state, remote stop status, capacity or budget.

Transport integration must invoke this lookup inside its acquired authority before active-peer lookup, since a successful original revoke intentionally made that peer inactive. Root/worker bridge owner owns the module registration and that actual call site. The focused leaf adds no migration, dependency, automated test or source comment.
