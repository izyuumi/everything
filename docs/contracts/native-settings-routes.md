# Authenticated native Settings routes

The private native owner pipe carries the existing closed `NativeSettingsOperation` enum. Open mints a session proof only from the actual verified owner ingress. Describe, Get, Update, ConfirmPatch, Changes and Reconcile use that same proof and the same SettingsService as the restricted service callers. Their arguments never create a caller from public UUIDs or a Boolean. The generic file-backed owner request path does not accept native Settings frames.

Describe returns the shared bounded registry with actual cached embedding choices. Get returns a validated revisioned Host snapshot; device preferences remain in their independent native store, and unsupported Host/device bridges fail explicitly. Update validates a whole typed batch through the service. ConfirmPatch uses the original native invocation and the service's exact protected-diff admission; inspecting or replaying an admitted invocation does not approve another mutation.

Changes returns bounded redacted hints with a monotonic cursor, known key names and original operation state. It contains no setting values, credentials, invitations, artifact paths or session proofs. Native response validation checks its sequence, key/scope and page bounds. Consumers must read authoritative snapshots after a missed hint or reconnect; the page is not another settings authority.

Reconcile reads the original file intent and actual pre/post fingerprint through the existing service. It never rewrites the file or reapplies a backend. Its cleanup caller remains bound to the original native session. The Host-owned application worker separately advances an original durable known-applied receipt. Inspect and other cleanup routes retain their original semantics; no request expiration is renewed.

All returned operation inspections use the shared pure metadata validator. Registry decoding is data-only and does not grant tool or caller authority. Transport limits and the original pipe supervisor remain unchanged. This route source does not establish Apple client composition, secure credential enrollment, foreground notification behavior or integrated runtime acceptance. Deferred automated verification remains [#32](https://github.com/izyuumi/everything/issues/32).

The Rust-only `NativeActionAdmissionResult::Existing` carries a boxed inspection to bound the enum's stack size; callers consume that owned inspection normally. This representation change does not alter the native wire result or grant another admission. Internal prepared application results likewise box their owned data without changing resource retention or drop order.

## Private pairing approval

ApprovePairing carries the private proof and one strict NativePairingApprovalInput: operation_id, native_request_id, creation_operation_id, redacted existing PairingRequest, label, expected_fingerprint and explicit access. Conversation access uses the existing scope/ids tags with strict unknown-field rejection and the actual DeviceAccess policy. The request signature/proof remains a private typed transfer, not a model target, generic JSONValue, file-backed owner operation or durable payload.

The service creates a distinct native-only PairingApproval identity and uses the same retained Host mutation/claim/effect/Agent boundary. It calls the actual endpoint protocol and derives the receipt from original durable marker/full-registration evidence. PairingApproved returns its validated original operation, nonsecret approval metadata, NotEstablished or Committed Host-pin metadata and optional private acceptance. The latter is the actual cached response, never a UI-created completion or persisted signature. Its wire shape is data only and cannot authorize another effect.

PairingApproval status is an original-session cleanup read allowed during drain. Fresh ApprovePairing is denied during drain; an exact replay while the Host accepts calls can inspect/settle its original existing admission without renewing authority. Closed/expired sessions may inspect metadata through their retained cleanup proof, but cannot receive acceptance or make a new grant. Existing Inspect remains receipt-only. Creation and final Host approval are separate outcomes, and neither proves replica finish. After restart, historical owner inspection remains possible while private acceptance is unavailable.

See the full [device settings contract](device-settings.md#native-final-approval-backend) for identity, continuous guard, expiry, cancellation, immutable Unknown and volatile response-repair rules. Existing native variants and seven model tools are unchanged. No Swift consumer API is claimed by this Rust addition; actual Apple integration/build/runtime and new backend checks remain separate gates.
