# Host selection preflight

`host::selection::SelectionPreflight` is a leaf service for owner-approved tool classification. It does not admit commands, change scheduler state, execute tools or expose an IPC route. The headless Host connects it to authenticated owner operations and durable command preparation through [service composition](host-composition.md). Remote device commands and model-generated input must never invoke its approval method.

`SelectionSettings` is a tagged, non-secret, serializable document. Its default is `local`. A `system_one` entry contains the exact endpoint, model and optional non-nil UUID native-store reference. `configuration()` delegates endpoint/model validation to the existing native System One configuration. `typesafe()` constructs the existing TypeSafe preset. Configuration does not authorize disclosure, read environment credentials, contact the native credential backend or send a request.

Pass the host's actually leased `Agent`; constructing an `Agent` from an unleased Store does not create process ownership. Build `SelectionCatalog::from_registry` and the offline `ToolSelector` from the same final registry and authorization scopes on a blocking worker. The helper hashes the JSON array of complete descriptors in registry name order, excluding `search_tools`, exactly as the native selector hashes its catalog. It checks 1000 descriptors and 16 MiB while accumulating the canonical SHA256. The constructor accepts this trusted matching pair; it does not inspect private selector internals or rebuild the catalog. Catalog replacement requires a new preflight service. The configuration-generation hooks below replace endpoint/model configuration within the same service while invalidating its previous tickets.

`SelectionBinding` contains typed conversation, task and command identifiers and lowercase hexadecimal SHA256 digests for the original proposed command, captured execution policy and catalog. The host computes the first two digests from its actual immutable command/policy representation. The preflight service checks that the catalog digest matches its snapshot and that conversation/task identifiers match the separately supplied `ExecutionAuthority`. Root must reconstruct the current binding and authority from trusted state before approval and again before taking the result. A caller-supplied digest is identity metadata, never proof of current authorization.

`prepare(binding, authority, query, limit, cancellation)` invokes the existing synchronous selector on an owned blocking worker. It returns a random ephemeral ticket, the same binding, monotonic remaining lifetime, and either a local-result summary or the exact remote destination, model, JSON payload, native fingerprint and authority. The authority display includes workspace, mode and optional inherited allowlist. Preparing a disclosure performs no credential lookup or network request. The original nonserializable `SystemOneDisclosure` stays in memory; the displayed fingerprint cannot recreate consent.

An explicit owner action calls `approve(ticket, current_binding, current_authority, cancellation)`. The service checks the current binding and full authority, consumes the original disclosure once using its remaining lifetime, and calls the actual native `select_approved` adapter. The native adapter independently checks selector identity, catalog/visibility, expiry and authority before sending. A wrong, changed, expired, missing or previously consumed disclosure does not start another request. A second approval while selection is running or ready returns `NotReady`. The adapter's actual credential, transport and classifier failures produce its genuine bounded local fallback and sanitized diagnostics. Cancellation and permission failures remain errors. The wrapper never refreshes a ticket, retries classification, searches another credential source or changes the approved payload.

`take(ticket, current_binding, current_authority)` consumes one ready `ToolSelection`. It returns complete native definitions and the existing `search_tools` fallback. The host must persist the exact result for that command during durable admission and then reuse the captured definitions on resume. Taking before readiness consumes/cancels the ticket and returns `NotReady`. An unavailable ticket requires the host's normal offline selection path; it does not permit classification. `discard(ticket)` implements decline/cancellation, removes the ticket and cancels an admitted selection. A second discard is unavailable. Ticket UUIDs do not independently authenticate the caller.

Each ticket lasts a positive duration of at most five minutes, measured by `Instant`. Tickets and results disappear on restart. There are at most 16 visible tickets and 16 owned active requests. The service reserves at most 8 MiB of conservative serialized component charges, including twice the catalog size, both encoded/disclosed request budgets, result budget and authority/query metadata. Actual native payload and result budgets are each 512 KiB. This is bounded admission accounting, not an exact heap-usage claim. Large catalogs can exhaust the preflight budget before the ticket-count bound; ordinary local discovery remains available. Expired idle tickets are pruned on admission/status. Active tickets retain their resource reservation even after discard, mismatch, expiry or shutdown until their owned request finishes.

Every admitted prepare/approval runs in an owned Tokio task retaining the same `Agent`, including its state-lease ownership. Dropping the caller future does not drop that admitted operation. Explicit cancellation, expiry and shutdown cancel the request and await the native selector future before releasing the active reservation. `shutdown()` closes admission, discards tickets, cancels owned work and awaits actual service-request quiescence without holding a mutex over an await. The host must await it before releasing runtime ownership. Cancellation of `shutdown()` leaves admission closed and work cancelled; a later call can continue draining. No automatic test or successful remote classification is implied by this lifecycle contract.

## Reversible configuration generations

`suspend_remote()` returns a private-constructor `SelectionGeneration` comparison token bound to that actual preflight instance and its checked epoch. A token from another instance cannot configure this one even if their numeric epochs match; readonly status exposes only the numeric epoch. Under the same short state lock suspension removes all visible tickets and cancels their selecting tokens. Actual active requests retain their original charges and ownership until RequestGuard settles. Counter exhaustion permanently closes admission and cancels work; it cannot wrap or reactivate an old generation. This hook neither waits for quiescence nor claims cancellation stopped an already-sent request.

`configure_remote(generation, settings, enabled)` validates the existing complete SelectionSettings, constructs a new actual SystemOneSelector identity without network or credential lookup, and installs it only for that exact suspended generation. It also invalidates local tickets prepared during suspension. Exact repeated configuration returns current metadata without another replacement; changed reuse or a stale token returns BindingChanged. Permanent shutdown cannot be reopened. Remote selection is usable only when enabled, configured for SystemOne, not suspended and not permanently closed. With remote selection off, preparation uses the same guarded native local selector path, including discovery and current authority checks; local definitions and search_tools remain available.

Each preparing/approved request captures its original selector and generation. Off or endpoint/model replacement removes old disclosures, selecting tickets and ready results. A stale worker cannot install a late result or adopt the replacement endpoint. The small native `reconfigured` helper keeps the same four-permit admission across old and new selectors, as well as the same local catalog/Authorizer and native credential-store handle. The existing sixteen-request and eight-MiB preflight bounds remain in force while old work settles. The retained Agent is the final PreflightInner field, after all Store-bearing selector resources. The preparation blocking worker also first-binds one owned bundle containing both selectors and Agent last, so its real work/destruction does not rely on outer async-task ownership.

`configuration_status()` returns SelectionConfigurationStatus: generation metadata, suspension, effective remote admission and the exact configured SelectionSettings. It observes configuration and gate state, not credential presence, model availability or a completed remote request. The token, status and serializable configuration do not authorize a caller or disclosure. Configuration methods are trusted Host control hooks; the settings facade must validate its real principal, original operation, exact protected change and settings revision first. Generations never replace those checks.

Composition exposes narrow suspend/configure wrappers. Suspension invalidates the preflight first and then clears its command handoffs under a separate short lock, with no nested locks or await. Its status reports the configured selector and admission metadata; memory and MCP restart comparisons retain their existing startup snapshots. The intended settings writer suspends after durable Applying intent and before its file effect, then configures only from the established committed settings result. That facade/override/startup wiring is separate work and is not implemented by these hooks.

Every new remote preparation still requires a fresh explicit exact endpoint/model/payload/authority approval. Native credentials remain keyed by canonical endpoint plus reference UUID under ai.everything.system-one. Changing an endpoint never copies an old secret, looks up a different purpose or migrates credentials; a retained reference UUID can resolve only its exact endpoint-bound key if actually provisioned. No credential check or request occurs in configure/status. Old approvals cannot send to the replacement endpoint, and enable does not itself contact it. Persisted desired/effective settings and redacted principal-scoped projections remain the shared facade's responsibility.

These reversible-hook and Agent-last corrections have source/format/preservation review only at this slice. Fresh production compilation, actual queued generation replacement/cancellation and same-four-slot observations remain pending. Earlier disposable and CI observations below describe their historical source, not these additions.

The existing `NativeCredentialStore::read` can return after timeout/cancellation while its bounded native backend worker still holds the shared credential semaphore. That worker does not use the host Store, tool execution or state lease. Preflight quiescence proves that this service's selector requests have settled; it does not assert termination of the underlying platform keyring worker. Native-store success and Apple platform behavior require their actual environment verification.

Disposable Linux observations verified the native offline definitions and discovery fallback; command/authority/catalog changes, decline, expiry, replay and byte-budget rejection without a classifier request; actual unavailable native-credential lookup with sanitized local fallback; and an explicitly approved literal-loopback HTTP refusal with real offline fallback. Five tickets reached the conservative byte limit. A real pending native HTTP request retained exclusive Agent state ownership after its caller was aborted, then explicit cancellation settled it and allowed the state directory to reopen. Shutdown during another actual pending HTTP request returned typed cancellation and zero service requests, tickets and reservations.

The runtime trace observed exactly three outbound connections, all to literal loopback destinations after their explicit approvals, and no embedding model/runtime file opens. Environment credential access was checked by inspecting the actual leaf/default-selector call path; syscall tracing does not observe userspace environment reads. Rust 1.88 formatting, workspace all-target compilation with default and all features, strict all-target/all-feature Clippy, and the all-feature workspace release build passed with the leaf registered. These isolated checks used the temporary package identity `0.1.0-host-selection` to prevent stale shared-target library reuse; that manifest/lock change and disposable module/bin wiring are excluded from the implementation. Successful remote classifier responses, native credential-store success and Apple behavior remain unverified. This leaf verification does not establish completed host IPC or scheduler integration.
