# Same-user owner IPC

`ipc` adds typed owner commands, queries, operations, and bounded conversation waits to the authenticated [Unix IPC transport](local-ipc.md). Authentication means the same operating-system user. These requests must not be accepted through paired-device domain command ingress.

`OwnerCommand::Text` retains the CLI's conversation ID, command ID, exact text, and explicit `RequestedRunOptions`. `OwnerCommand::Initialize` retains the original conversation ID, command ID, title, and exact conversation configuration. Durable admission retains their raw JSON before typed decoding can discard fields. The host inbox explicitly distinguishes this legacy narrow identity from full domain-envelope identity.

`OwnerQuery` covers bounded conversation and task lists, individual conversation/task metadata, permission approvals, non-secret settings, public device identity, paired devices, and a command receipt. List limits are 1–100. Query results expose public domain/task information and receipts rather than private provider continuations, raw scheduler checkpoints, or credential values. Conversation history uses the existing bounded synchronization contract.

`OwnerOperation` covers settings replacement with expected revision, ephemeral session/native credential store/remove, pairing invitation creation, explicit fingerprint-and-access pairing approval, device revocation, task wake, and an explicit expected-attempt provider retry. Credential values occur only in the credential operation. Pairing invitation material occurs only in its explicitly requested ephemeral response. Both have redacted debug output. Settings replacement and credential storage are separate operations so a failed platform credential write cannot silently rewrite settings or select another credential source.

Provider retry supplies a target task and exact expected attempt. The transport's unique request ID must reach the native scheduler's one-use transition. A reconnect must reuse that same request ID; it must never persist a reusable retry boolean or automatically retry a changed attempt after a crash. Task wake does not itself authorize an uncertain paid provider attempt.

`ConversationWait` names one conversation, the last observed sequence, and a timeout from 1 to 30,000 milliseconds. A handler registers the scheduler change subscription before querying durable state, then returns a higher durable event sequence, a scheduler change hint, or a timed-out unchanged cursor. A change hint can concern task state without a new conversation event; clients requery the task and conversation rather than assuming the cursor advanced. Process-local change revisions are hints; clients requery after restart. Waiting is neither an execution queue nor permission to cancel a task when the client disconnects.

The transport captures `original_command` only for durable submit/owner command variants. It never attaches an entire credential-bearing request to a `LocalCall` journal field. All responses must match their request IDs and kinds and fit the existing one-MiB frame bound. The source contains these DTOs and validation; the full host request handler and CLI proxy are still being integrated. Deferred automated coverage is tracked in [#32](https://github.com/izyuumi/everything/issues/32).
