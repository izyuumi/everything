# Ordinary relay send window

The existing `DeviceEndpoint` relay loop owns one `RelaySendWindow` with at most 16 message cells. Preparation, a prepared packet, an awaited socket send and a sent message awaiting relay acceptance all occupy that same map. This implementation selects `TransportOutboundSelection::OrdinaryOnly` with or without a settings transport owner. Binding a settings owner to a connection does not enable private settings delivery.

## Selection and exact loading

The metadata-only [outbound selector](transport-outbound-selection.md) supplies one candidate excluding the window's current IDs. The window registers the actual input and its private slot before spawning the blocking preparation worker or loading ciphertext. `Store::load_ordinary_transport_candidate` matches the selected message ID, recipient, creation time and retry time, and rechecks pending status, readiness, transport expiry, active peer and private-row exclusion. It returns no row when that exact snapshot no longer matches; it never probes private ciphertext or substitutes another row.

The loader checks the borrowed SQLite value is a nonempty BLOB of at most the existing 2 MiB transport envelope bound before calling the existing `outbox_row` decoder. Existing row conversion, attempt range and checked Store-connection behavior remain in use. The result's constructor stays inside Store and the bounded row moves into the actual worker.

This path adopts the selector's canonical nonnil UUID contract. Older generic storage APIs accept broader bounded identifier strings. Malformed selected identifiers now fail explicitly. The old batch reader's aggregate read-budget pagination and page-halving fallback do not apply to this exact single-row load. These are explicit compatibility differences; malformed or oversized rows are never silently skipped or treated as an empty outbox.

## Preparation and send ownership

The window retains the original `spawn_blocking` handle and its task ID before awaiting it. Awaiting borrows that same registered handle; no cancellation selection, abort, reference count or `is_finished` observation substitutes for a join. The complete actual result is registered before slot, endpoint or task-error association checks. The worker's temporary raw row and serialization values are destroyed before it returns. Its only packet result is the decoded bounded envelope.

Preparation keeps the existing local endpoint, pinned peer and header checks; retry delay remains `1000 << min(attempts, 8)` milliseconds. The original `NotFound`-only deferral fallback remains exact. An actual deferral `StateConflict` is still an error. The fresh confirmation still serializes the decoded envelope again, reads a fresh clock and peer registration and calls the existing exact-byte confirmation API. It does not replace that confirmation with a raw-byte comparison that would accept additional encodings.

No row, a revoked peer, false confirmation or cancellation before send produces a worker-local `NotSent`. Only the true original join makes that result usable. It means no socket send for this attempt; a deferral may already have occurred. Cancellation after preparation and before socket admission destroys the actual joined packet without sending it.

The actual `RelayClientMessage::Send` remains in `SocketOwned` while the existing `RelayConnection::send` borrows it across its await. The actual returned result is registered before further checks. The packet is destroyed before extracting the same private slot and starting the 15-second acceptance timer. Input exclusivity is checked only after the original join, the actual send return and packet destruction. Failed exclusivity retains the entire returned input. It never proves task completion or reconstructs a slot.

## Acceptance, expiry and normal teardown

An Accepted frame can remove only a matching `AwaitAccepted` cell from this window. That actual removal creates the private `OrdinaryAccepted` receipt consumed by the existing Store acceptance call. Removal still precedes the awaited database operation, preserving the ordinary durable retry behavior. Relay acceptance represents relay custody, not client delivery or execution success.

Maintenance expiration of an ID absent from this window is a no-op. An ID present in an unfinished phase is a bookkeeping fault, with its actual owner retained. Only fully returned `AwaitAccepted` cells expire normally. The original 15-second timeout starts after the awaited send and packet destruction. Heartbeat, ordinary incoming delivery, acknowledgments, retry classifications and durable outbox deletion remain on the existing relay pump.

Every normal relay-session outcome enters `finish`. The actual primary outcome is registered before any cleanup await. Remaining original preparation handles are joined and their complete outputs registered before destruction. A clean finish destroys packet/result owners, clears ordinary slot metadata and returns the original outcome. An observed network failure after the actual send returns remains eligible for the existing retry behavior; it does not quarantine the endpoint.

## Catastrophic retention and session lifetime

A bookkeeping failure, unjoined owner or dropped unfinished populated window retains the complete bounded map, original handles, outputs, inputs, completion outcome and typed failure cause in terminal ownership. Retention occurs before the real endpoint quarantine latch is set. Terminal ownership contains no session mutex guard or Host guard. There is no reset, private accounting refund, task abort, guessed completion or automatic recovery path. The monotonic endpoint fence prevents a successor window in that endpoint clone group and participates only as a negative condition in Host transport draining.

Both outer relay entry points acquire the original endpoint session mutex once. The locked loop checks outbound health before connection admission, reconnection and every normal Stopped path. The settings wrapper holds that same actual guard through `close_and_wait` and its final health check and Stopped publication. Its existing failed-drain pending state also retains the guard. No new session lock or runtime is introduced.

These are source ownership and protocol-preservation claims. Direct formatting and static source checks do not verify compiler acceptance, SQLite execution, cancellation timing, socket behavior or an Apple roundtrip. No automated tests were added. Supported CI and disposable runtime observations remain required. The counted private preparation and [final socket source](settings-private-socket-admission.md) below define internal ownership only; actual pump invocation, private ACK/no-resend, Bind creator retirement and composite drain remain dependencies.


## Private unstarted custody in the same window

The Unix window also has a counted private custody entry. All ordinary phases and private Provisional/LoanedUnstarted entries share the same map and total limit16; no private window, queue, job or runtime was added. The actual successful-connect physical socket identity is captured at construction. A settings connection compares that original identity separately from admission liveness. Both normal relay modes still select OrdinaryOnly: these internal custody producers do not enable private delivery.

A paired operation borrows actual Work and window mutably. It checks the genuine queued owner, original ledger/context/connection, private candidate identity, physical socket and capacity before extraction, then reserves the real cell. The actual complete queued owner moves into that cell's closed Source Arc, and the same Work entry holds the matching affine loan witness. Full or a pre-extraction error leaves the original owner in Work. No ciphertext, future frame, preparation job, loader, current permission or Source from a label is constructed.

The paired unstarted inverse is ownership preservation, including after close/fault. It compares only actual retained payload/header, disarmed permit, moved settlement, original context/connection and real loan/window/physical/slot identities. It does not invoke live capture, current Core, ledger admission, history health, checked queued getters or a supervised handoff read. After that structural proof, Arc::get_mut checks exclusivity; it is not a completion proof. The same complete owner and consumed loan witness enter Work Owned NoResend before the cell is removed. Return errors preserve the full Source Arc/cell/witness and actual ticket. No original private, BUILD, creator or Supervisor charge is released.

Accepted can still remove only Ordinary AwaitAccepted and create the ordinary Store receipt. A private unstarted cell has never sent a message, so Accepted for it is Protocol with no removal or private SQL operation. Maintenance of an absent ID stays a no-op; a present private cell faults and remains owned. No private ACK timeout or ACK/expiry retirement is implemented.

The initial finish still has no Work borrow. It genuinely joins ordinary preparation as before, but any remaining private custody causes the complete bounded map, original outcome and typed cause to be retained before the real Work/endpoint failure latches. It cannot take the ordinary entries.clear path. Clean ordinary finish is possible only after an explicit genuine paired return already removed all private cells. Terminal ownership includes the actual physical identity, Source and slot; no Host guard, receiver, mutex waiter or task was added to Source. The subsequent counted jobs, authenticated loading and final socket unit below supply internal producers; ACK consumption, NoResend-row handling and creator-LAST cleanup remain successors. Formatting/source review does not establish compiler or runtime acceptance.


## Counted private ciphertext preparation

A Unix private cell can now move from LoanedUnstarted through Waiting, Preparing and Observed to Prepared or Stopped. These phases occupy the same existing map cell and limit16. The Source retains the complete candidate selected by the original paired lend, the genuine queued owner and its original loan association. Work retains the same affine loan witness and private/Supervisor charges. No new window, queue, runtime, JoinSet or Source constructor is introduced. Both ordinary relay selectors remain OrdinaryOnly; the relay pump does not invoke these private operations yet.

`try_start_settings_preparation` consumes the actual pending ticket only after checking the same window, physical socket, slot, Source and original association. A failure owns that ticket and its typed cause while the full unstarted Source stays in its cell. The admitted input stores the ticket, original Source, cancellation handles and fixed deadline. Its actual Host-lock future lives separately in Waiting; neither Source nor shared input contains a guard, waiter, result or panic payload. The admitted deadline clips the original request's retained monotonic deadline by the checked difference between original expiry and committed-header expiry. No current wall clock renews it. Fresh, Historical, Bind, Access and Snapshot each use their actual retained authority and deadline.

Observation selects the registered guard wait against the actual connection and external cancellation handles and the fixed deadline. After acquiring the guard it rechecks cancellation, deadline and socket liveness, then directly spawns the blocking loader. The cell registers the original handle and task ID before any await. Cancellation or expiry records a stop cause without aborting or replacing that handle. Dropping an observation future leaves the actual waiting or running state registered. A future pump integration must drive these waits alongside the original receive events so a Host-lock wait cannot prevent existing Work progress.

The worker calls the unchanged private Store loader and destroys the actual Host guard on its worker stack before returning. The entire result enters Observed before fallible association checks. Genuine joined success alone can become Prepared; a returned frame is DATA, with its complete Source and input still retained. Original structured loader errors, panic/JoinError and secondary stop or association failure remain in the cell outside shared Source/input. Fixed redacted observation errors summarize these retained results and do not imply NoEffects, release or retry permission.

Orderly finish first destroys every Waiting acquisition future, including any internally assigned mutex permit, then genuinely joins every remaining original ordinary and private preparation handle. An earlier fault does not skip another running handle. The map iterator used to select a handle ends before awaiting it. Common catastrophic retention, including Drop, also destroys Waiting futures before archiving the complete bounded map, outcomes, inputs and causes, then sets the existing Work/endpoint latches. Already Prepared bytes are destroyed before their input moves to Stopped. Running guards remain only on their actual worker stack. No Host guard or acquisition future is archived in terminal ownership.

The immutable paired return still accepts only LoanedUnstarted and is unchanged. The [final socket unit](settings-private-socket-admission.md) below now supplies the internal Prepared sender, final-current job/returned-guard admission and private socket operation. The started-return successor below now preserves whole custody back in Work; no session caller, relay acknowledgment consumer, SQL no-resend disposition, creator retirement or private drain completion is installed. Accepted and expiry cannot remove these private phases. Any remaining private cell still forces truthful nonclean retention. Formatting and static ownership checks do not establish compilation, SQL execution, cancellation timing or transported behavior.

## Final private socket unit

The Unix counted Settings cell now has a final socket phase after its genuine preparation result. The same cell retains the complete Source/input, original Work loan and all private/Supervisor charges. It stores its bounded preencoded frame, actual final blocking handle/task ID, complete observed return and actual write outcome. No second window, queue, runtime or capacity is created. Ordinary preparation, awaited Send, Accepted removal and its fifteen-second timer are unchanged.

The scoped final driver retains the guard receiver outside the cell and shared Source. A final worker uses the same original Host mutex, checked Main Deferred transaction and actual six-family current gate. Its original handle is joined and the whole return is installed before the driver inspects guard delivery. The uninterrupted guard exists only on the worker stack, scoped channel/driver or affine socket loan. Driver cancellation and close destroy the receiver and any waiting lock future before retaining or fencing custody. The normal window cleanup joins original running final handles even after faults. Catastrophic retention keeps the bounded whole handle/result/Source and never archives a guard or lock waiter.

The [real remote writer](settings-private-socket-admission.md) consumes a private loan of that exact cell and polls one original absolute five-second timer before current admission, readiness and flush without renewal. A fresh no-SQL lifetime check runs under the delivered guard; bounded stop and budget checks follow, then guard destruction directly precedes the first physical socket readiness poll. Guard ownership never crosses a socket poll. The same preencoded Message moves once into start_send and the same physical socket is flushed. Actual current errors, remote results, cancellation, panic payloads and uncertainty remain retained outside the shared Source. A dropped write future closes that exact socket and records the actual dropped outcome. An unregistered write return retains its original result and adds a separate actual abandonment cause.

The final driver is a real producer/consumer unit but the original session has no caller yet. Both existing selectors remain OrdinaryOnly. The later accepted dispatcher must retain and drive actual Work events alongside one persistently pinned final driver; empty Work cannot be polled as a fake consumer. A flushed write is buffer-free retained metadata, not RelayAccepted, client receipt, operation success, cleanup, parent closure or drain. The started handback below exists internally; private Accepted, SQL no-resend disposition and creator-LAST retirement remain absent. Full Root/independent source review and direct formatting cover this unit; integrated supported CI and focused runtime verification remain pending. The separate [Host supplier](settings-host-relay-capability.md) is installed without a dispatcher or second runtime.

## Started custody return to Work

A Unix connection owner can now return a genuinely started private phase through a paired mutable operation on its original Work registry and shared relay window. The collector stops actual lock waiters, borrows original handles through await and installs their complete actual outputs before checking them. Cancelling that collector leaves the original registered phase/handle/Source and Work witness owned. Socket return requires the final driver's mutable borrow to have ended, its scoped guard receiver/parcel destroyed and every running original job truly joined. A returned or dropped socket helper retains its actual full outcome, including ambiguity; neither flush nor expiry is RelayAccepted or NoEffects.

Return compares only immutable original connection, physical socket, window/slot, ticket, Source, header, settlement, ledger and actual context identities. It works after close/fault without calling checked current getters, check_open, current permission or a supplied skip flag. The whole joined phase and SAME original Work loan are installed in StagingNoResend in the existing32 registry before decomposition. Known joined output/input owners are consumed, and try_unwrap then serves only as an additional exclusivity gate. Every returned Err Arc and the complete remaining stage stay owned; the original16 cell remains counted on failure. The nonawaiting move tail invokes no source/provider/permission callback and preserves native errors/panic payloads outside the shared Source.

A completed OwnedNoResend retains the original by-value SettingsSendSource, original ticket, complete evidence and same witness before a private adoption borrow of that actual registered record can remove the exact window cell. The borrow is not a constructible ID/Boolean receipt. Drop archives the whole phase/stage/Source/evidence/witness before latching; it cannot fall through to source/parent/charge release. Only window capacity is freed after genuine adoption. The original private/Supervisor counts and byte charges, claimed witness, parent and history creator stay unchanged. Existing LoanedUnstarted return and ordinary prepare/send/Accepted/expiry/timing bodies remain distinct and unchanged.

This unit adds no SQL, Work job, session/Accepted dispatcher, private selector, retirement or drain. SQL ciphertext may still be pending after Work adopts NoResend; both current selectors remain OrdinaryOnly. Exact scoped row deletion/absence disposition, real same-socket private Accepted and its Work event consumer must be implemented before activation. Row absence, ACK, cancellation or time cannot retire that full Source. Creator-LAST and witness-LAST cleanup remain separate. Full Root/independent source review and direct formatting/diff checks cover this unit. They do not establish compiler/Send, timing, SQL, transported or security acceptance; current integrated CI and runtime verification remain required.
