# MCP environment credentials

`CredentialVault` implements the existing `McpEnvironmentResolver` used by the configured MCP host. `CredentialOperation::StoreMcp { binding, secret }` and `RemoveMcp { binding }` are trusted owner operations; the binding's storage field selects process-local session storage or the actual native credential store. Binding validation precedes lookup or mutation. Owner IPC may serialize SecretTransfer to the authenticated private local channel; its Debug remains redacted. Raw secrets never belong in durable DomainCommand, host inbox, settings, events, logs or remote configuration. SecretTransfer retains its existing bounded printable UTF-8 validation.

An MCP binding freezes its server ID, complete manifest fingerprint, variable name, opaque reference and storage kind. Session keys use a distinct MCP prefix plus the existing versioned scope hash. Native access uses the existing MCP credential-key derivation. A different executable/argument/environment-reference manifest, server, variable, reference or purpose cannot retrieve the old binding's value. Missing MCP credentials remain missing: the resolver never falls back to model keys, ambient environment variables or plaintext files. The model resolver keeps its established explicit-binding and official-endpoint environment behavior.

Vault clones share one session map and one NativeCredentialStore. At most 128 session credentials across purposes are retained, including at most 16 model credentials. Capacity returns Busy before inserting a new binding; replacement and deletion remain available. Model and MCP entries cannot collide even if their opaque reference IDs match. Removing a session entry cannot erase copies already lent to an active trusted consumer; native mutation likewise does not recall process environment values already supplied to a server.

The resolver checks cancellation before lookup and again after acquiring the short session lock. Native reads inherit the existing three-second deadline and cancellable waiting semantics. MCP startup also applies its own bounded credential/startup deadline. The native OS call owns its shared semaphore permit until the blocking worker actually finishes, including after timeout or caller cancellation. Neither result means the OS call stopped. Native store/delete await actual mutation completion; dropping a caller does not undo an in-flight mutation.

`CredentialVault::native_store()` returns a clone of the same native handle for trusted optional selection and other purpose-bound consumers. It does not create an independent admission gate or enable any new credential fallback. The underlying native keyring may prompt or make internal copies; the application does not claim universal heap zeroization or native-service quiescence from cancellation.

Explicit startup-only environment transfer is provided by [MCP session bootstrap](mcp-session-bootstrap.md). It validates a non-secret mapping against the actual authorized MCP manifest before reading only its selected environment variables and atomically staging the existing session bindings before MCP startup. It does not make a running server reconnect or persist session values across restart.

This leaf supplies credential resolution and operations. Owner IPC/settings and the actual host composition wire it into the configured MCP lifecycle and enforce owner authorization. It does not authorize process launch, change FullHost tool permissions, restart a server automatically or weaken the MCP manifest approval check. Deferred automated coverage remains in [#32](https://github.com/izyuumi/everything/issues/32).
