# Ordinary relay ownership health

Each actual `DeviceEndpoint` clone group shares one monotonic `EndpointInner.outbound_failed` atomic. Its initial value is false. The private `quarantine_outbound` operation stores true with Release ordering; `outbound_is_quarantined` observes with Acquire ordering. There is no reset or recovery constructor. `check_outbound_health` returns the fixed `DeviceError::OutboundQuarantined` when set. These observations perform no SQL or locking.

The actual Host transport-drain conjunction also requires that this endpoint is not quarantined. All existing native worker, private receive, Settings service, Broker and composition drain conditions remain necessary. A false quarantine flag proves no join, buffer destruction, current authorization or completed drain. Creating another endpoint is not proof that the original endpoint drained.

The real [ordinary send window](ordinary-relay-send-window.md) retains actual input, original preparation handle, joined output and socket message in the same bounded map. Both relay entry points acquire the existing session mutex once. Health checks run under that original guard before admission, reconnect and every Stopped path; the Settings wrapper retains the same guard through its actual owner drain. Catastrophic populated window/future or handle loss retains complete bounded unresolved ownership before fencing reuse. Terminal retention contains neither that session guard nor a Host guard. An abort, task label or reference count proves no join.

Ordinary awaited network errors remain eligible for existing durable retry after genuine preparation and buffer cleanup. They do not set permanent quarantine. Actual worker join, returned send result and message destruction distinguish normal completion from abandoned ownership. Both Settings owner modes explicitly select OrdinaryOnly; no private Settings activation follows. The separate [physical socket identity](relay-socket-identity.md) fences a genuine Settings connection when its actual authenticated socket closes or cancels. These are source implementations with formatting and independent review; compilation and runtime verification remain separate.
