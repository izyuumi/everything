# Native Settings assistant response leaf

`NativeSettingsAssistantWire.swift` supplies the unchanged `fd011755` typed response leaf against the Rust declarations originally frozen at `229f74a294c467788b54c3ce8ecf9f0060818a60` and validators at `69e17308a4ca392eae48669fd57dc0ec860b27ac`. The corrected backend is normally merged in `8d05f780e344af6e3dc2448c8fa7ea12fa11d308`; its exact Rust source has its own required CI evidence. `NativeSettingsWire` now supplies the eight closed assistant request encodings, response integration and byte/matching boundary described below. Root registers the response leaf only in the existing macOS Settings group and source phase. Session, lifecycle, Store and UI still require their separate integration. No assistant request is issued by this Wire increment, and no successful runtime or [#115](https://github.com/izyuumi/everything/issues/115) completion follows.

The closed `Reply` variants are Opened, OpenState, Accepted, Status, Operation, ActionDetails and Unavailable. Each rejects unknown fields and uses the actual native field names. The outer reply discriminator is `kind`; the nested OpenState and OperationLookup discriminators are `state`. All decoded UUID identities are nonzero, including optional identities when present, provisional attempt IDs and nested operation/reference identities. Existing shared metadata types retain their actual domain validators rather than becoming opaque JSON.

Opened requires an OpenAI or Anthropic provider, the original configured model and recipient, the exact lowercase provider-binding SHA-256, the ordered seven existing tools, a nonzero chat identity and a positive signed-range expiry. Model and recipient limits are 256 and 4096 UTF-8 bytes. These are actual disclosure data; neither a digest nor a DTO grants authority or selects another provider.

Status preserves all nine phases, the optional original turn, committed assistant text, unsigned text revision, optional provisional text, optional context observation, original operation IDs and actual accounting flags/counters. Committed and provisional text each have a separate 16 KiB UTF-8, NUL-free ceiling. Provisional has an actual nonzero attempt ID and the closed Streaming or Interrupted state. Context has a positive signed-range settings revision, positive signed-range observation time and stale flag. Provisional or context data requires a nonnil turn identity. The existing eight unique operation IDs, four model attempts and 8192 reserved-output-token limits remain; charged tokens retain the full unsigned counter. A standalone decoder cannot prove monotonic text revisions, event provenance, snapshot freshness, provider completion or joined cleanup. The future owner must compare original chat/turn/attempt observations, distinguish provisional from committed content and never turn text or counters into effect receipts. This decoding support does not establish a working streaming producer or UI.

OpenState is NotAccepted, Ready with Opened, Closing with a chat identity, Closed with an optional chat identity, Unavailable or Unknown with an optional chat identity. `RequestExpectation.open` captures the original outer Open frame ID. A repeated Open's OpenState and explicit OpenStatus/CloseOpen replies must name that exact original ID. CloseOpen rejects NotAccepted, matching the actual manager's suppression contract. The initial Open may still return Opened or Unavailable. These decoded states do not themselves prove suppression, absence of effects, resource drain or successful recovery; the actual manager owns those semantics. No decoder invents a new Open identity or automatically retries.

Operation replies name the exact original chat, turn and operation. Their lookup is NotRecorded or Inspected with the real `SettingsOperationInspection`. NotRecorded is only meaningful after the Host verifies the original scoped provenance; it is pending/unknown row presence, not rejection or proof of no effects. An inspected receipt must bind that operation ID, the original SettingsAgent child and Host scope. The scoped request expectation additionally matches its original native parent in both origin and binding, and its exact original Host. Historical phases remain inspectable. The Host remains responsible for authenticating the actual native proof, actual principal and original fence membership; public IDs cannot construct those capabilities.

ActionDetails requires the same scoped identities, exact currently-awaiting original reference and a target whose request ID, scope and expected revision match the receipt binding. Only Patch with AwaitingConfirmation, Device Pair/Revoke with AwaitingAction, or Native OpenSection with AwaitingAction is eligible. Owner replacement, final pairing approval, credential entry and notification authorization are rejected. No action target or reference is synthesized from chat text, UUIDs or missing metadata. The future Session must derive request expectations from its retained actual proof/Host connection and authenticated child history, and capture the actual stored reference. A UI-supplied ID or reference is not an admission. Executing a genuine target still requires the existing separately owned native gesture, authority and expiry checks.

`Reply.validate(for:)` accepts only that closed request/reply matrix. It matches exact chat/turn for Send, chat for Poll/Close, original Open ID for Open replay/OpenStatus/CloseOpen, and all original scoped identities/reference for the two scoped reads. Unavailable remains a top-level reply only for Open or Send. A Close Status can still be Closing or Unknown. Validation never creates authority or infers rollback, a refund, resource quiescence or Replica completion.

Disclosure, chat, provisional, Open-state and lookup containers are Decodable and Sendable, with fixed redacted descriptions where private content is reachable. They are not Encodable transcript records, generic Settings metadata or Equatable/hashable caches. Reused operation/target/reference values keep their existing nonsecret typed metadata contracts; no new private payload is encoded. The leaf has no native proof, credential transfer, input text, transport, callback, model tool or persistence. Assistant text remains untrusted private content. Future pipe code must keep fixed errors and never log decoder errors or raw response bytes.

## Closed native Wire boundary

`NativeSettingsWire.Operation` adds `agentOpen`, `agentOpenStatus(openRequestID:)`, `agentCloseOpen(openRequestID:)`, `agentSend(chatID:turnID:providerBindingSHA256:text:)`, `agentPoll(chatID:)`, `agentClose(chatID:)`, `agentInspectOperation(chatID:turnID:operationID:)` and `agentActionDetails(chatID:turnID:operationID:reference:)`. Their encoded snake-case tags and fields match the actual merged Rust operations. They use the existing private `native_settings` input wrapper and proof; no generic public OwnerOperation or second transport is added. Send validates nonzero chat/turn IDs, the canonical lowercase digest and at most 8192 UTF-8 bytes of nonblank, NUL-free text. The complete encoded sensitive input still must fit 32768 bytes, including proof, wrapper and escaping; a raw-size-valid input can therefore fail encoding without truncation.

The compatible entry point is `decode(_:for:proof:requestID:hostID:)`, with the last two arguments defaulting to nil for existing ordinary calls. Every assistant decode requires a nonzero original outer frame ID and retained proof, validates the typed request and constructs its own frozen RequestExpectation. Open matching uses that actual outer frame. OpenStatus/CloseOpen use their original Open ID while retaining the actual new outer frame for envelope accounting. Scoped reads additionally require the actual Host ID; their native parent comes from the supplied proof, never a decoded/UI ID. Missing context fails closed. The future Session must supply these arguments from its original proof/connection and retained child ownership; this decoder cannot prove that an internal caller supplied genuine Session state.

`Response.assistant` accepts only the closed kind/reply wrapper and invokes the exact frozen reply matcher. Assistant responses cannot satisfy an ordinary request, and ordinary responses cannot satisfy assistant requests. The existing ordinary response paths, input encoding and 2 MiB/pairing-approval bounds are preserved. Operation and private Request descriptions/debug descriptions are fixed redacted strings, including when existing credential submission is reachable.

The actual CLI prints compact NativeSettingsResult JSON plus one LF, after HostClient has validated and stripped the socket LocalResponse. Assistant decoding requires that exact one-LF outer framing: after dropping one LF the first/last bytes must be object braces. It does not trim arbitrary surrounding whitespace or accept a second trailing LF. This is an outer framing check and closed typed JSON decoding, not a new parser or a claim of byte-for-byte canonical validation of every internal JSON spelling. Ordinary decoding retains its prior behavior.

For the actual schema-1 LocalResponse, the known 36-byte original request UUID and fixed native-settings-result wrapper add exactly 126 bytes to that compact received result: prefix124 plus suffix2. The received result already includes all payload/text escaping. The decoder uses checked addition to reconstruct the full encoded size; it does not observe original socket bytes, re-encode private reply DTOs or apply a nested-reply allowance. Before typed decoding it enforces the 2 MiB raw transport guard and the largest assistant full bound,200704; after closed decoding/matching it enforces the exact full bound: Status200704, Operation/ActionDetails65536, all other assistant replies32768. Corresponding compact-result ceilings are200578,65410,32642. No reply is returned before that final bound passes.

The complete wrapper accounting agrees with the actual Rust assistant_result bound. The existing process layer may still collect up to its 2 MiB global stdout guard before this variant-specific check; no smaller during-I/O limit or process-RSS guarantee is claimed. The current native parent/child lifecycle, recipient consent, original replay, paid admission, read coalescing, operation adoption and cleanup remain the Session owner's separate work. There is no fallback provider, automatic Open/Send or model-text action creation in this Wire seam.
