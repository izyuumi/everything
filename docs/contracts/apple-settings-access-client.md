# Live Apple AccessStatus client

The iOS Connected Host access section offers one explicit read-only AccessStatus check using the existing [closed wire](apple-remote-settings-wire.md), pinned identity, ReplicaService and relay connection. It displays actual access metadata only: granted readable/writable keys, configured provider/model/recipient consent metadata, configured revision and observation freshness. An Access check sends no model request, native Owner operation, Snapshot, update or restricted chat, and never automatically starts the separate [explicit Bind action](apple-settings-bind-client.md). The Rust private reply sender is still incomplete at this source freeze; no transported Host response or issue completion is claimed.

## Gesture and original

Before its Button Task, AppModel verifies actual UIKit activity plus the existing scene/platform latches, visible Settings root, tab, covers, connection and full displayed Host/local identity. A MainActor ReplicaSettingsAccessGesture captures ContinuousClock before wall time, one query UUID, the exact Service and the displayed opaque connection token. Its take method is one-use. The immutable Sendable input has no caller-settable constructor. These fields are timing/correlation data, not authority. The actual token is minted only by the real private connection scope; an old copied view cannot authorize a same-Service reconnect.

Service intake checks cancellation, exact Service/token/current scope and fixed first clocks. A repeated currently retained input returns its original handle; the immediately previous spent input cannot mint another original. New checks require a new explicit gesture and current scope. No timestamp/deadline is captured at actor intake, preparation, retry or reconnect. The request lifetime is at most30000 milliseconds from the synchronous original capture. Query UUID, encrypted request message ID, reply envelope ID and connection token remain different identities.

AppModel retains one interaction and one owned control Task. Hide, cover, tab/path change, scene inactivity, willResignActive, disconnect, disable and observed scope/Host replacement synchronously retire its generation, stale copied display and cancel that Task. Its original handle is cancelled when it actually returns; a late actor result cannot adopt a later foreground generation. Scene/disconnect/disable capture the actual control Task before waits and join it after the real Service stop. No OS dialog, local preference write, second notification delegate or Host stop is introduced.

## One total send window

The existing per-connection pump and receiver remain the only two relay children. One typed outbound map counts ordinary sends and the single Access/Bind/Snapshot original together, with a total capacity of16. Intake reserves the private cell before crypto preparation, keyed separately from ordinary message IDs. A full window refuses the new check; it does not queue it. Existing ordinary outbox selection excludes only actual ordinary inflight IDs and keeps its existing preparation/attempt/send order, retry delay and15-second acknowledgement timeout. An ordinary cell also records actual send return and successful Accepted SQL separately; it releases only after both. Accepted cannot free capacity while that original frame is still held by the awaited send. Its timeout still starts after attempted SQL.

The actual returned encrypted message ID is bound once after real preparation, before socket send. It must differ from the query UUID and collide with neither registered outbound message IDs nor pending incoming acknowledgements. Before send, Service repeats the actual full Store Host/local/disabled checks and original scope/clocks, then synchronously checks the same prepared envelope/cell. Private send starts once on that actual socket, with no durable outbox row, re-encryption, automatic retransmission or second pump.

Private send-started, send-returned, Accepted and reply-returned are orthogonal facts in that original cell. An Access reply can finish before send returns or before Accepted arrives. Reply consumption does not erase the encrypted ID needed to match late Accepted. Private Accepted settles only that exact RAM owner and never calls ordinary relayAccepted SQL; ordinary Accepted still commits SQLite before removing its entry. Accepted is relay custody, never Saved, denial, NoEffects or Host permission.

Normal private release requires actual send return, matching Accepted and real reply-helper return. A one-way send failure fences intake and prevents both ordinary and private completion paths from releasing uncertain cells, including a late already-entered Accepted handler; actual socket-group return remains their cleanup boundary. Unsent cancellation releases only after preparation has returned. Sent cancellation, expiry, error or missing disposition retains the original cell and closes the old connection through its existing task group. The original map is released only after withThrowingTaskGroup actually returns/unwinds, or stop joins its owned runner; socket.close, retirement flags and cancellation alone are not join proof. The ordinary reconnect may resume, but never resends or reconstructs a private original. A later user-requested read is a new observation, not a mutation retry or evidence that the prior Host operation had no effects.

The latest immutable input is retained only within the current socket lifecycle to reject immediate replay; its Service reference is released at the actual socket-group/stop boundary. This is not a query history, resumable session, proof cache or generic replay service. The existing single pending cell excludes simultaneous Access/Bind/Snapshot work. The [Bind](apple-settings-bind-client.md) and [Snapshot clients](apple-settings-snapshot-client.md) use this same private window and AppModel control Task; Bind’s [nonresettable association](apple-settings-bind-owner.md) remains distinct from heavy send/receive ownership.

## Authenticated delivery and ACK

The actual receive owner selects Access, Bind or Snapshot from its retained pending original and invokes the corresponding classifier and one-use Fresh qualification/adopter. This Access path retains its own query/ciphertext correlations. A pending original is eligible only if its exact ciphertext is registered and send has begun. The classifier authenticates the full pinned Host/local identity and the actual received frame, runs strict duplicate-key/closed decoding, checks original encrypted-message/query correlations, commits metadata-only replay state and repeats real Store/current-scope/fixed-clock checks around waits. Only its genuine Fresh object/qualification can expose the private Access body; duplicates and unrelated replies cannot re-adopt.

Ordinary/refused results already have their actual Store disposition. The installed receiver acknowledges and drains once, without calling legacy identity.receive again. A private valid proof must commit its metadata before adoption/ACK. Authentication, size, Store, capacity, conflict, commit or quarantine failures do not manufacture denial or freshness. Queue-full leaves delivery on the relay without ACK. The same outer finishSettingsReceive runs only after the actual nested helper/ACK/drain returns or unwinds, preserving its original frame/proofs through that boundary.

The existing [pre-cache refusal](apple-private-settings-ingress.md) still handles unsupported Settings forms without ordinary plaintext persistence. This Access path adopts only genuine AccessStatus observations; the separately selected [Bind path](apple-settings-bind-client.md) can adopt its genuine private parent, and the [Snapshot path](apple-settings-snapshot-client.md) can display its exact requested endpoint-free values. No raw plaintext, parsed JSON, generation, parent, credential, invitation, private proof or ordinary conversation enters the new display/observable state. Metadata replay rows retain the existing null-payload terminal markers; old durable data is not erased.

## Display and limits

The cache remains one bounded RAM observation with its original clipped wall/monotonic fences and weak scope. A redacted request-handle identity ties its display to the same actual UI interaction, so an older cached result cannot become fresh merely because the user starts another check. Stale or absent cache is not denied access. Real grantUnavailable, local unavailability, timeout, cancellation and interruption remain distinct. Copies stale immediately on lifecycle invalidation or refresh failure; only a matching newly adopted observation can display current. The UI shows no writable controls or permission inferred from those labels.

All previous local This iPhone preferences, saved appearance, notification ownership, privacy covers, paired identity, ordinary history and independent Host lifetime remain in place. No new schema, library, crypto, parser, project membership, automatic Task per refresh or private offline queue is added. ARC/COW, cancellation and actor isolation are not secure erasure, transaction abort, exact memory-release or OS suspension guarantees.

Direct official Swift grammar and static source/preservation checks are source validation only. Public Access/Bind SDK results and the later Snapshot source review are separately attributed in [implementation status](../status/implementation.md); those earlier SDK results do not cover the new Snapshot integration. Current-head supported Apple SDK build/analyze plus Rust CI remain required. Real Host/device delivery, crypto/codec/SQLite execution, replay pressure, late Accepted, revocation, suspension and native UI acceptance have not been observed. #116/#117 remain open; automated verification remains deferred in [#32](https://github.com/izyuumi/everything/issues/32).
