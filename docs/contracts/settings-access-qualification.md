# AccessStatus current own-grant qualification

The held `service/paired/access.rs` source adds a pre-parent AccessStatus receipt check and private current-read qualification to the existing `SettingsReceiptAuthority` and the same ServiceCore/Authority. It does not accept Delivery, commit a receipt, allocate a reply reservation, construct response DATA or serialize a private response. The [verified AccessStatus source](settings-access-status.md) and [closed response DATA](settings-access-replies.md) remain separate prerequisites. Compilation and runtime behavior of this slice have not been verified.

## Genuine source and supplied Main

`check_access_receipt_on` takes the actual `OwnedVerifiedSettingsAccess` and a supplied Main transaction. It verifies the exact receipt-capability instance retained by that owner, original Agent/StateLease/Main, endpoint and Host mutation identities, the actually attached Host Arc and live connection. It calls the source's real receive-time `check_precommit` before and after its checks. That check requires the original active receive guard; it is never reused as a post-join publication check.

The method reads the actual Host endpoint configuration and the requesting peer's complete pinned registration in the supplied transaction, including revocation. Each encoded identity is bounded to16384 bytes before typed decoding. It validates the actual Host keys/role and peer keys/access, compares the complete canonical peer registration with the verified source and then uses the existing transaction-local Settings grant reader. This independent pin check is required even when there is no Settings grant head. Device/Host revocation, missing or corrupt identity rows, changed pins, poisoned state, SQL and validation errors remain structured errors; they are not policy denials.

The future receipt writer must own the real Main Immediate transaction and original Host mutation guard, perform marker/reservation writes atomically, repeat this check at the actual commit boundary and retain the registered worker through its true join. A supplied `Store`/`Transaction` argument does not itself prove transaction provenance, commit, receipt ownership or successful join. This leaf creates none of those missing producers and performs no SQL writes or nested Store acquisition.

## Bounded query correlation

The same Authority holds at most512 fixed-field correlation cells total for its current actual connection, with at most64 for one complete peer-key identity. A cell contains only the genuine query's immutable Host/query/time intent, complete public peer keys, an in-process comparison identity, its first wall/monotonic floor and fixed deadline, and nondecreasing observation floors. It retains no Source, request, Agent, Store, endpoint, ServiceCore, callback, response buffer or back-reference. Correlation IDs and comparison identities cannot mint authority.

An exact replay must retain the same Host/query/time intent and complete peer keys. It may observe a newer current grant but never renews the first request deadline or wall/monotonic floor. Every observation checks both those original bounds and the actual replay source's own fixed bounds. Changed identity conflicts; expired cells remain counted. There is no same-connection eviction. A cell reserved by a genuine receipt check may remain counted if a later check or transaction fails; that conservative metadata reservation is not an acknowledgment or durable receipt.

The single map can be replaced only for a genuine distinct current Source on the same attached Host after the previous exact connection is permanently retired. Retirement alone is insufficient reasoning. The actual constructor chain is `HostSettingsTransportOwner::connected_relay` → `SettingsReceiveWork::connect` → actual framed admission → verified crypto replay hook → the private Access source factory. `connect` requires the previous work report to be complete and failure-free before installing the next context/history or admitting another callback. Its report includes registered jobs, private owners and the shared BUILD slot. The verified envelope cannot be constructed from IDs, DTOs or rows. This full-drain provenance is what permits replacement without retaining unbounded old maps; any future Access producer must preserve it. The current Access factory has no accepted receive callsite.

## Private current-read facts

`qualify_access_status_on` additionally borrows the actual same-Core `OwnedMutexGuard`. It performs its own current checks without the inactive receive guard. It requires a previously registered exact query and holds private decision facts plus the original owner/capability/guard borrows and actual invocation/comparison identities. Those facts have no getter, serialization or public response conversion.

Only a genuine currently pinned requesting device with no Settings head, a revoked Settings grant, or an expired Settings grant can select the private fixed `GrantUnavailable` decision. A future-issued grant or failed identity/storage observation remains an error. An Active decision holds only the validated, bounded current head for the later counted projector; no fabricated grant, BindingIntent, parent or generation is created.

`recheck_access_status_on` repeats the same current read with the exact borrowed capability, original invocation and Host guard. It requires the same correlation identity, equal decision facts and nondecreasing observations. A changed grant requires a new qualification of the same bounded original query; it does not update or silently retarget an existing qualification. All time checks use the original captured clock/deadline, never now plus remaining time.
