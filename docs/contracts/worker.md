# Scoped worker contract

The optional worker provides bounded manifests, files, results, consumed approval, purpose-scoped encrypted transport and composition of the existing native kernel. The native Scheduler reservation/result lane, dedicated executor CLI and optional owner-only Host coordinator are implemented in source. See [Host admission](host-worker-admission.md), [coordinator service](host-worker-service.md) and [executor commands](worker-executor.md) for their integration and validation boundaries. The actual combined Host credential-rejection/recovery walkthrough passed within the limits in [worker validation](../development/worker.md#combined-host-validation-checkpoint).

A manifest binds its delegation/attempt UUIDs, coordinator and executor purpose identities, exact relay origin, worker-local native task/conversation/command identities, original creation time/deadline, exact worker-owned model configuration and credential reference, explicit workspace tool allowlist, mode, copied task/context/files, permitted artifact names and native execution budgets. The manifest SHA-256 fingerprint includes all these fields and actual file bytes. Prepared disclosure and consumed approval objects are nonserializable; approval expires within five minutes and never outlives the job deadline. Submission validation also retains a monotonic cap and rejects observed wall-clock rollback.

Initial supported tools are `read_file`, `search_files`, `write_file` and offline `search_tools`, subject to the explicit allowlist. ReadOnly cannot select writes; FullHost, shell, MCP, general network tools, nested delegation, active-parent delegation without real native accounting and hard operating system resource requests fail explicitly. The worker's approved native model API is a separate network destination. File tools do not create an arbitrary-code sandbox.

Only explicitly selected ordinary data is transferable. At most 64 files and 256 KiB aggregate decoded content fit in each direction. Paths must be normalized relative UTF-8 names, contain at most sixteen components and use no traversal, backslashes, controls or reserved scheduler names. File payloads use canonical Base64 and established SHA-256. The complete manifest fits in 480 KiB, leaving envelope headroom within a 512-KiB application packet. Selected task text is checked against the native command limit before approval. Output artifacts must match the approved names; summaries are at most 8192 bytes. No local host database, complete history/wiki, private checkpoint or raw credential belongs in this protocol.

Worker credentials are references to that executor's native credential store, scoped to executor identity, complete model configuration and reference UUID under `ai.everything.worker.models`. There is no host-key, ambient environment, instance-metadata or cloud-SDK fallback. A worker's OS operator can inspect the plaintext it executes; encrypted relay transport does not make that operator blind.

`load_or_create_worker_identity(&Agent)` uses the existing secure identity implementation under the separate private `worker-identity/` directory. It requires a leased Agent. Call this synchronous function outside Tokio workers while retaining that Agent. `WorkerEndpoint::open(agent, identity, role, origin)` is also local and synchronous. It binds immutable public identity, role and origin to the worker-purpose endpoint. Same-Store ordinary device identities/pins are rejected; trusted composition must also keep purpose keys separate across Stores.

`WorkerOutboundGate::acquire(&WorkerManifest, &DevicePublicKeys, UnixMillis)` is an async trusted-composition interface returning `Box<dyn WorkerOutboundPermit>`. A real implementation validates the complete manifest/current attempt, exact peer pin, original deadline, current owner authority and actual native concurrency/budget reservation. The owned permit must retain the corresponding mutation guard through its lifetime and must not call back into that endpoint while holding it. A caller-supplied boolean or ledger row does not implement that contract.

`stage_approved(ApprovedDelegation, now)` consumes approval into an opaque staged capability and durable exact manifest. `acquire_staged` transfers its original expiry and endpoint authority into actual native admission. After that reservation, `offer_reserved(RemoteTaskBinding, &dyn WorkerOutboundGate, now)` obtains the real permit before durable enqueue and either creates the first Offer or verifies and reuses its single original encrypted envelope. The older `offer(ApprovedDelegation, gate, now)` wrapper requires prior staging and routes through that same reserved path. Actual relay transmission reacquires a permit immediately before sending every queued Offer. The endpoint's owned authority mutex serializes cancel/revoke/received control changes with these operations. Durable operations move authority and admission guards into the actual blocking SQLite closure; dropping their caller cannot release the guards while that commit continues. With no real gate, Offer enqueue/transmission is unavailable. Replies do not acquire broad host-command authority.

`WorkerPacket` uses the distinct `everything.worker.v1` purpose and version 1 inside the existing encrypted envelope. Its authenticated sender/recipient and explicit sender role bind Offer, Accepted, Rejected, Cancel, CancellationAccepted, Result, ResultAcknowledged and Revoke messages. Ordinary Host/Replica device packets and their conversation/sync/permission rights are separate. Role and purpose validation precedes packet acceptance. Cancellation acceptance records intent; it does not prove remote effects stopped.

Worker results remain untrusted. They bind the original delegation, attempt and manifest fingerprint, retain actual native usage counters and cannot refund reservations or authorize permissions. A result must be quarantined and durably accepted by the authoritative host before application acknowledgment. Generated files require a separate local review/application decision. Native uncertainty remains unknown, with no automatic model retry or history rewrite.

`receive_envelope` authenticates using the existing encrypted envelope, checks endpoint/role/purpose/job scope and commits its complete receipt and semantic state transaction before returning a relay-acknowledgeable receipt. Exact replay is idempotent, conflicting identities fail, and revocation is sticky. Known revoked public keys can authenticate an exact already-durable replay solely for acknowledgment; fresh messages cannot change state. Cancellation before a delayed Offer binds an immutable tombstone and prevents its execution. CancellationAccepted binds the original request and records intent only.

`subscribe()` returns a watch receiver for committed changes. It wakes consumers to read bounded current snapshots and does not claim a complete transition history. Mutation notifications execute in the actual blocking commit continuation, so dropping its async caller cannot suppress a successful committed-result notification. Blocking resources drop their repository before the retained leased Agent.

`verify_native_outcome(RemoteTaskSnapshot)` authenticates the original terminal packet and immutable manifest/pin, verifies actual private artifact quarantine and mints the opaque result capability. The Agent/Scheduler accepts it atomically before `acknowledge_native_result(RemoteResultReceipt, now)` can queue an application acknowledgment. That method requires the real opaque native receipt, same Store, exact accepted source and fresh purpose pin/private quarantine checks; an arbitrary public binding, digest, receipt ID or quarantine flag cannot authorize it. Rejected sources return NotRequired and emit no invented result ACK. Exact ACK replay reuses its single original envelope. Transport acceptance never substitutes for this application receipt. See [the bridge](worker-bridge.md).

`WorkerRuntime::start(endpoint, profile)` requires Executor role and binds the immutable worker-owned model profile. It registers filesystem operations plus offline discovery, then composes one native Scheduler and one global broker. Before native effects it reserves an immutable exact worker-native admission after rejecting preexisting unowned task/conversation/command identities. Startup requires that ownership ledger for every existing task. While the scheduler is still inactive, recovery compares the exact original public submission and workspace and asks the native Scheduler to compare its existing immutable definition before activation. Worker-manifest ID membership alone is not ownership proof.

Actual native waiting state, matching native phase and immutable Running/Unknown tool journals take precedence over terminal task labels and cleanup attestation when classifying results. Unknown results export no artifacts, trigger no retry and refund no budget. Runtime failure remains inspectable separately from its lifecycle phase. Scheduler channel loss fails explicitly rather than polling a closed watch indefinitely. Durable packet notifications and scheduler changes wake orchestration, with a bounded 500ms reconciliation fallback.

Migration 10 adds `worker_endpoint`, `worker_peers`, `worker_profile`, `worker_delegations`, `worker_messages` and `worker_native_admissions`. Migration 11 retains the immutable first terminal packet's source; migration 12 indexes native remote binding lookup without changing authority or accepting ambiguous rows. All use the normal ordered Store migration chain; endpoint open never creates tables. Worker plaintext is private local state; raw identity/provider secrets are excluded. The ledger retains at most 16 pins, 256 delegations, 8192 messages and a 64 MiB serialized payload budget, counting UTF-8 bytes. Within these limits, 16 message slots and 64 KiB remain reserved for permanent peer revocation; a revocation's original envelope and canonical packet together must fit in 4 KiB. One fresh revocation permanently retires that peer, bounding consumption of this reserve. Ordinary admission fails closed before consuming it. No automatic deletion or reset loses replay identities.

`Scheduler::admit_remote`, `remote_dispatch_permit`, `remote_by_binding` and `admit_remote_result` operate on the actual immutable remote definition and opaque authority capabilities. Admission charges conservative caps once and never dispatches the remote reservation into a local model worker. Known accepted terminal results settle the original dedicated task; Unknown preserves its slot and full charge. The current Host surface delegates fresh root tasks only. There is no cumulative active-parent/nested delegation budget API, model-origin cloud tool or automatic paid retry. A worker ledger row or caller assertion cannot substitute for native concurrency, authority, command/revision and budget checks.

Automated coverage is deferred to #32. Full validation is tracked in [worker development](../development/worker.md). No successful live provider, native credential-store persistence, arbitrary-code isolation, remote attestation or production-readiness claim follows from this stage.
