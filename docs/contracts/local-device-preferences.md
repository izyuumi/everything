# Local preference-store identity

`DevicePreferenceStore.local(directory:)` opens the authoritative device preference database without requiring an external device identity. It reads or creates the preference-only installation UUID in the same `preferences.device` singleton that owns the shared revision, completion/attention values and appearance. The macOS app already composes one app-owned actor in private Application Support, initializes it away from the UI executor and shares it across Settings scenes. Host executable or state-path changes do not replace that identity. Initialization failures are reported without deleting or reseeding state. See [This Mac controls](this-mac-settings.md).

Both factories use one SQLite connection and a `BEGIN IMMEDIATE` bootstrap transaction. Bootstrap rereads `user_version` after acquiring that transaction, so concurrent creators observe the committed identity rather than competing UUIDs. Version 0 must contain no application schema objects. Only that genuinely empty database receives schema 2, one Foundation UUID, revision 1, default-off completion/attention values and appearance `system`. Partial or malformed schemas fail explicitly; no partial-bootstrap repair remains.

A version 1 store must have the expected complete structure, one canonical lowercase nonzero identity, positive integer revision, valid Boolean values and a bounded canonical original request ledger. Migration in the same transaction adds appearance `system`, tags original requests `notifications` and advances the schema version to 2. It preserves the identity, preference revision and values, original request IDs and BLOB bytes, outcomes and result revisions. Migration does not increment the preference revision. Version 2 requires the complete schema and valid actual values; missing rows, unexpected objects/columns, malformed receipts, unreadable appearance and unsupported versions fail without defaults or reconstruction. See [appearance and migration](device-appearance.md) for exact structural and receipt validation.

The existing `init(directory:deviceID:)` remains the strict externally bound path: it requires a nonzero supplied identity and rejects a stored different identity. iOS composition must continue using its actual replica identity through that path. The local factory does not weaken that check. Both paths share private database setup, transaction behavior, compare-and-set and exact request replay. Notifications and appearance share one revision and one combined 8,192-request ledger; neither section silently rebases a stale draft. Rollback failure poisons the connection. Request/main-page limits, private file modes, backup exclusion and iOS protection remain in effect.

The installation UUID identifies only this authoritative local preference store. It is not a physical Mac identifier, Host ID, paired-device identity, native UI session proof, peer grant or authorization for a remote action. Deleting authoritative app data can create a new preference installation. This factory supplies no Host device-revision adapter; OS authorization remains observed separately from saved completion/attention preferences. Supported native/device/runtime acceptance remains tracked under [#110](https://github.com/izyuumi/everything/issues/110), [#114](https://github.com/izyuumi/everything/issues/114) and [#117](https://github.com/izyuumi/everything/issues/117).

The complete two shared Swift leaves passed strict Swift 6 concurrency typechecking with warnings as errors against actual Foundation and the retained upstream SQLite header. No SQLite database was opened for this source-stage validation. Earlier Apple SDK compilation of schema 1 does not verify the new schema-2 implementation. Current supported macOS/iOS build/analyze and disposable first-open, version-1 migration, reopen, concurrent initialization, corruption and replay observations remain required. Automated coverage remains deferred in [#32](https://github.com/izyuumi/everything/issues/32). See [native action foundations](../architecture/native-settings-actions.md) and [typed settings scopes](settings.md).
