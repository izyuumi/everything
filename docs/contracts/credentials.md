# Native credentials

`credentials` is independent of selectors, models and transport. `CredentialKey::new(service, account)` accepts bounded nonsecret identifiers. `CredentialSecret::new(Vec<u8>)` takes ownership of 1–32768 bytes in zeroizing storage. Printable owner-entered secrets (API keys, MCP values, Apple entry) remain limited to 8192 bytes by the host transfer boundary; the larger bound fits the host-written Sign in with ChatGPT token record. It has no Debug, Clone or serialization implementation. `expose` lends bytes only to trusted native consumers. Do not put secrets in identifier fields.

`NativeCredentialStore` selects an explicit real native credential implementation, never a global default builder: macOS Keychain (`MacCredential`) or Linux Secret Service (`SsCredential`). Unsupported platforms return an explicit error. There is no environment-variable, plaintext file, Linux kernel-only, or mock fallback. Linux needs a working session D-Bus and Secret Service daemon; vendored libdbus permits compilation without system development headers, not runtime service emulation.

`read(key, cancellation)` runs the native call on a blocking worker and stops waiting after three seconds or cancellation. One owned semaphore permit admits a single native operation across store clones. It remains with the worker until the OS call actually finishes; timed-out work cannot accumulate through the same store. A late secret result is dropped and its owned buffer zeroized. Locked stores may prompt through the platform; OS prompt/call termination is not promised.

Owner-only `store(key, secret)` and `delete(key)` await actual native completion and return a sanitized error on failure. They do not have an artificial mutation timeout. Dropping their future cannot undo a native mutation already in flight; the host must retain and observe mutation tasks. Missing entries are `None` for reads and successful idempotent deletion. Native error text, backend metadata, rejected bytes and response bodies are never formatted into application errors.

These methods are trusted library APIs, not model tools or durable command handlers. Host/Apple owner setup must pass ephemeral secret bytes directly into this boundary. Never place secret setup in command-line arguments, TOML, logs, events, conversation checkpoints, permission payloads, remote command journals, or relay messages. Owner access enforcement belongs to the authenticated host surface; possession of a selector configuration file is insufficient.

System One's key derivation lives in its own module. `SystemOneSettings::credential_key` hashes a versioned domain, exact canonical endpoint including query, and opaque UUID reference into the native account. Keys for one endpoint cannot be looked up by a different configured endpoint. Provider integrations may define their own domain-specific keys without importing the selector.

## Model credential sources

A `ModelCredentialReference` has an optional `source`: `api_key` (default, omitted when serialized, unchanged key derivation) or `chatgpt`. A `chatgpt` binding is valid only for `openai` with the `official` endpoint. Its account key adds a `chatgpt` domain suffix to the existing digest, so it never collides with an API-key entry for the same reference. The host stores one JSON record there in the binding's `storage` (session memory or native store). The record holds the issuer, issued client ID, subject, email, ID token, access and refresh tokens, token type, granted scopes, expiry and save time. Owner `credential` Store rejects `chatgpt` bindings, so only the sign-in flow writes them. Remove deletes the record and its in-memory cache. A host write replaces the in-memory record first and marks it unsaved until the store write succeeds; a failed write is reported as unsaved and retried before the next bearer use, so rotated tokens stay usable until the host stops. The CLI creates new ChatGPT bindings with `native` storage unless `--storage session` is given. Sign-out clears the tokens but keeps the client, subject and email so the next sign-in reuses the registration. The nonsecret `ext_agent_host_id` lives in `chatgpt-host-id` in the state directory, not in the credential store. See [OpenAI SIWC](../architecture/openai.md#optional-sign-in-with-chatgpt).

The application-owned buffer is zeroized, and bearer header values are marked sensitive. Native keyring and HTTP libraries can make internal memory copies; this API does not claim universal heap zeroization. Native store access controls are part of the OS user security boundary, not protection against a compromised process running as that user.

On macOS `MacCredential` uses the legacy file keychain. An item's access list trusts the designated code requirement of the binary that created it. An ad-hoc or linker-signed `cargo build` has a requirement bound to its own code hash, so a rebuilt binary cannot read or update the item without a user prompt (headless: `errSecAuthFailed`, mapped to `Unavailable`). Binaries signed by [`scripts/sign-dev.sh`](../../scripts/sign-dev.sh) with the fixed identifier `ai.everything.cli` and one Apple Development or Developer ID certificate keep reading and updating their items across rebuilds. Items do not move between certificates. The observations are recorded in [ADR-0014](../decisions/ADR-0014-optional-sign-in-with-chatgpt.md#credential-durability). Linux Secret Service has no per-binary access list.
